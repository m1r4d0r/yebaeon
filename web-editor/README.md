# 예배온 Studio — 웹 편집기 첫 버전

예배 자료를 준비하는 공간. 전체 프로젝트는 **예배온(YebaeOn)**, 교회 Mac의 동기화 도구는 **예배온 Sync**다. [브랜드 기준](../docs/BRANDING.md).

[예배온 Studio](https://yebaeon.grace-jean-p.workers.dev/)를 집 Windows PC의 최신 Edge/Chrome에서 열면 됩니다. 로컬 `index.html`도 사용할 수 있습니다. 서버 라이브러리는 공용 비밀번호와 작업자 이름으로 입장합니다. 별도 계정 가입은 없습니다. 입장 화면에서 **로컬 파일로 작업하기**를 선택하면 업로드 없이 편집할 수도 있습니다. 처음에는 `sample-demo.js`의 안내용 예제 3장이 열립니다. 실제 예배 자료가 없는 소스 공유용 예제이며, PP6에서 직접 여는 호환성은 실기 확인 전입니다. 원본 파일에는 쓰지 않습니다. 사이트는 GitHub Actions로 자동 배포합니다. [배포 구성](../cloudflare/README.md).

집 PC에 보관한 실제 수정본은 **내 파일 열기**에서 `test-pair/update/documents/토요일.pro6`를 선택하면 37장이 열립니다. 이 원본 쌍과 이전 `sample-data.js`는 로컬에 보존하며 GitHub에는 포함하지 않습니다.

아리따부리·나눔고딕·나눔명조는 CDN 웹폰트로 불러옵니다. 인터넷 연결이 필요하며, 연결이 안 되면 설치된 글꼴 또는 대체 글꼴로 계속 편집할 수 있습니다. 슬라이드의 글꼴 적용 상태는 오른쪽 패널에 표시합니다. 미디어 연결과 로컬 편집만으로는 파일을 서버에 보내지 않습니다. **문서 올리기 / 서버에 저장**을 선택한 `.pro6`와 작업자 이름은 공유 라이브러리에 전송합니다. [배포 출처와 글꼴 매핑](FONT-SOURCES.md).

문서 편집과 ZIP 생성은 브라우저 안에서 처리합니다. `.pro6` 서버 저장은 구현했고 성경·사용 미디어의 클라우드 저장은 다음 단계입니다. [서버 설정과 API](../cloudflare/README.md), [전체 저장 범위](../docs/SERVER-PLAN.md).

## 함께 작업하기

1. 공용 비밀번호와 이름으로 입장합니다. 이름을 기억하며 로그인 유지는 30일까지 선택할 수 있습니다. 공용 PC에서는 로그인 유지를 해제하고 작업 후 로그아웃합니다.
2. 첫 화면에서 **플레이리스트**를 고르고 순서 안의 **편집**을 누릅니다. 가사 등을 바꾼 뒤 **서버에 저장**, **← 플레이리스트로**로 돌아옵니다. 같은 파일의 다른 플레이리스트와 공유하는 문서는 함께 쓰이는 이름을 표시합니다.
3. 순서에서 **추가 / 교체 / 빼기 / ↑ / ↓**를 사용한 뒤 **순서 저장**합니다. 순서에서 빼도 원본 문서는 남습니다. 저장하지 않은 순서 변경은 다른 문서를 열기 전에 저장해야 합니다.
4. 최초 자료는 Mac 앱의 원본 등록 또는 웹 **재생목록 가져오기**로 `.pro6pl`을 올립니다. **전체 문서 → 문서 올리기 / 폴더 올리기**로 `.pro6`를 올리면 같은 상대경로에 연결됩니다. 최상위 문서 폴더 안의 하위 구조를 보존합니다. 누락/경로 불일치를 임의로 파일명만 보고 연결하지 않습니다.
5. 문서의 **저장 이력**에서 이름·시간과 이전 원본을 확인합니다. 다른 작업자가 먼저 저장했다면 충돌을 표시하고 현재 화면의 편집 내용은 유지합니다. 이름 변경은 이후 저장에만 반영됩니다.


이름은 본인이 적는 작업 표시입니다. 서버 비밀번호를 아는 사람은 같은 문서를 읽고 편집합니다. 미디어를 새로 교체한 문서는 아직 서버에 저장할 수 없으며 ZIP으로 보관해야 합니다. 기존 미디어 연결만 한 문서는 원래 Mac 경로를 보존하므로 서버 저장이 가능합니다.

로컬 `file://`로 열면 서버 기능을 사용하지 않습니다. 웹 편집기는 자동 저장하지 않으며, 브라우저를 닫기 전에 서버 또는 ZIP으로 저장하세요.

## 사용 순서

1. **내 파일 열기**로 `.pro6`를 선택하거나 기본 샘플로 시작합니다.
2. **파일 연결 / 폴더 연결**로 기존 이미지·영상을 연결합니다. Mac의 절대경로 대신 NFC 정규화 파일명으로 찾고, 같은 이름이 여러 개면 선택하지 않습니다.
3. 슬라이드를 선택해 텍스트를 수정합니다. **새 슬라이드**는 선택한 장의 배경과 텍스트 상자를 유지하고 내용을 비웁니다. **복사**는 내용을 유지합니다. 자동 실행 단서, 단축키, 노트는 새 장에 복제하지 않습니다.
4. **앞으로 / 뒤로**, **그룹 선택**으로 정렬합니다. 그룹 경계를 넘는 이동은 소속 그룹도 바꿉니다. 삭제와 최근 40회 편집은 **되돌리기**를 지원합니다.
5. 미디어 위치를 선택해 **미디어 교체 / 배경 추가**를 누릅니다. PNG/JPG, 브라우저가 읽을 수 있는 MP4/MOV를 지원합니다. 기존 요소는 같은 종류끼리 교체합니다. 배경이 없는 장에는 새 배경을 추가할 수 있습니다.
6. **PNG 저장**은 선택한 장의 근사 렌더를 저장합니다. **ZIP 저장**은 `documents/`와 새 `assets/`를 함께 저장합니다.

ZIP을 다시 편집하려면 압축을 풀어 `documents/문서.pro6`를 열고 `assets/` 폴더를 연결하세요. 기존 미디어도 필요에 따라 다시 연결합니다. 브라우저를 닫기 전 서버 또는 ZIP으로 저장해야 합니다. 자동 저장은 없습니다.

## 현재 한계

- **PP6 실기 호환성 미검증.** 웹 PNG와 PP6의 실제 화면이 같다는 보장은 없습니다. 폰트 대체, 줄바꿈, 세로 정렬, 자간, 그림자, 외곽선, 이미지 배치, 이전 장에서 유지되는 미디어는 차이가 날 수 있습니다. PSD는 브라우저에서 미리보기하지 못합니다.
- `NanumMyeongjoOTF-YetHangul`은 우선 일반 나눔명조 웹폰트로 미리보기합니다. 옛한글판과의 차이는 남아 있습니다. 내보낸 `.pro6`의 원래 폰트 이름은 보존됩니다.
- **텍스트를 수정한 상자만 첫 글자 서식으로 통일**합니다. 부분 서식 편집은 다음 단계입니다. 수정하지 않은 상자의 RTF와 알 수 없는 XML 요소는 보존합니다.
- 새 미디어의 source는 `file:///PP6-Package/assets/...` 임시 참조입니다. Mac 적용 엔진이 설치·경로 변환을 해야 PP6에서 바로 열 수 있습니다. **현재 ZIP은 읽기 전용 비교/검토용이며, 운영 Documents에 바로 덮어쓰는 배포물은 아닙니다.**
- 연결한 기존 미디어는 ZIP에 다시 넣지 않습니다. 교회에 해당 미디어가 있어야 합니다. 새 파일은 충돌을 줄이는 별도 이름으로 묶습니다.
- 기존 Playlist의 문서 연결·순서 편집은 지원합니다. 새 플레이리스트 생성/전체 삭제·이름 변경과 전문 Arrangement·전환·자동 실행 단서 편집은 아직 지원하지 않습니다. 원본에 있는 관련 메타데이터가 새 슬라이드와 맞는지는 Mac에서 확인해야 합니다.
- 문서 25MB/1,000장, 새 미디어 개별 200MB/합계 500MB를 상한으로 둡니다. 영상은 파일을 디코딩할 수 있을 때만 교체할 수 있습니다. 용량이 크면 메모리 사용량도 커집니다.
- 검증 환경은 집 Windows의 Edge입니다. High Sierra의 오래된 Safari에서 웹 편집기를 실행하는 것은 이번 목표/검증 범위가 아닙니다. 교회 Mac은 기존 네이티브 도구와 PP6 검증을 맡습니다.

## 개발 검증

Node.js와 Playwright가 있는 개발 환경에서:

```text
node web-editor/test-browser.cjs
python tests/test-reference.py
```

기본 브라우저 채널은 `msedge`입니다. `PP6_BROWSER_CHANNEL`로 변경할 수 있습니다. 결과는 `web-editor/test-output/`에 남습니다. 자동 테스트가 만든 `edited-package.zip`은 테스트용이며 사용자의 실제 문서 변경물이 아닙니다.

GitHub에는 안내용 `sample-demo.js`만 포함합니다. 실제 교회 파일이 필요한 브라우저 회귀 검사는 로컬 `test-pair/update/documents/토요일.pro6`가 있을 때만 실행하고, 없는 복사본에서는 건너뜁니다. Python 검사는 로컬 자료에 의존하는 검사만 건너뜁니다. `test-output/`은 Git에서 제외합니다.

텍스트 처리 참고: [Microsoft RTF Unicode·code page 설명](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxrtfex/205e1abf-b794-4fd0-b1e4-5210882233ab), [MDN 인코딩 목록](https://developer.mozilla.org/en-US/docs/Web/API/Encoding_API/Encodings).
