# 교회 문서·재생목록 마이그레이션 안내

2026-10-03. **아직 운영 자료에 적용하지 않았다.** 승인된 유지 7·보관 7·삭제 5와 문서 정리본을 적용하는 순서다. 실제 문서명·식별자·정리 패키지는 비공개 로컬 `서버반영준비/재생목록_서버적용계획.json`과 `정리목록.json`을 사용한다.

최신 정리본에는 가사찬양 115개 문서의 MOV 참조 887개 제거가 포함된다. 가사·슬라이드·정지 이미지·MP4·다른 카테고리는 그대로이며 변경 전 문서는 별도 복구 ZIP으로 보존했다. 영상 파일 자체를 삭제하거나 다른 예배의 영상을 제거한 것은 아니다.

## 저장 거절과 승인된 정리를 구분한다

일반 업로드에서 노드가 없다는 사실만으로 ‘삭제해 달라’고 해석하지 않는다. 구버전/다른 Mac/잘못 고른 파일도 똑같이 보이기 때문이다. 의도한 정리는 보관·삭제 API로 먼저 상태를 기록하고, 활성 목록을 Mac에 맞춘 다음 업로드한다. 숨겨진 보관 노드를 다시 올리는 업로드는 거절되는 것이 맞다.

0.6.3/build16은 서버 전용 목록을 보존하고 ‘웹에서 보관·삭제한 목록 반영…’을 제공한다. **이 버전으로도 아래 순서는 가능하다.** 준비 중인 0.6.4는 보관 노드가 남은 상태의 서버 맞추기를 문서 업로드 전에 멈추고 해결 안내를 보여주는 보완이다. 새 설치본 성공 확인 전에는 후보를 검증 완료판으로 안내하지 않는다.

‘Mac 기준 서버 맞추기’는 같은 경로의 문서/목록 내용을 Mac 기준으로 갱신하고 기준을 연결하는 기능이다. 서버 전용 문서와 목록은 보존한다. **이 버튼 한 번으로 서버 전체를 정리본과 똑같이 삭제·대체하는 기능은 아니다.**

단계 4의 삭제는 **재생목록 노드 제거**다. 연결 문서·이미지의 일괄 삭제가 아니다. 성탄절 등 알려진 보관 원본 누락은 기록하고, 누락 사본을 확보했다고 표시하지 않는다. 현 보관 기능은 이미지 바이트를 별도로 확보하지 않는 `references-only`다. 이미지 이관 전에는 Mac 원본 이미지를 보존해야 한다.

보관목록.pro6pl은 참고용 로컬 사본이다. 현재 Sync가 감시하는 활성 파일로 선택하면 보관 목록을 다시 올리려 하므로 선택하지 않는다. 파일 이름/경로를 임의로 바꾸어 다른 라이브러리를 만드는 방식도 사용하지 않는다.

## 중단했을 때

- **단계 3/8 서버 맞추기 중단:** 성공한 문서와 백업은 남는다. 전체 원자적 작업이 아니다. `server-resets/<작업ID>/job.json`의 완료분을 확인하고 다시 준비한다. 이미 같은 원본은 재사용한다. 옛 준비 기록의 강제 실행이나 DB 초기화로 우회하지 않는다.
- **보관/삭제 요청 응답 유실:** 서버 structure/보관함을 읽어 실제 결과를 확인한 후 다음 항목으로 간다. 실패했다고 가정하고 옛 전체 재생목록을 PUT하지 않는다. 삭제 재요청의 404만으로 최초 삭제 실패라고 판단하지 않는다.
- **보관은 성공했지만 Mac 제거 실패:** 서버 보관은 유지한다. Mac의 백업·중단 복구로 해당 작업을 되돌린 뒤 비교한다. 로컬 목록을 복구하면 서버 보관 상태와 의도적으로 달라지므로 다시 정리를 적용하기 전 업로드하지 않는다.
- **정리본 설치 후 확인 실패:** PP6/Sync를 종료하고 단계 1의 Mac 파일·프로필을 함께 복구한다. 서버 보관/삭제 상태는 자동 취소하지 않는다. 옛 프로필이나 파일로 즉시 전체 업로드하지 않고 서버 상태를 먼저 확인한다.
- **서버 문서 복원 필요:** 문서별 보존된 버전/백업으로 CAS 복원한다. 이력 끔 정책으로 이전 원본이 정리됐을 수 있으므로 단계 1의 독립 백업을 이용한다. 새 편집이 있으면 먼저 대조한다.
