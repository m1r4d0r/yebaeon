# 문서 정리 정책

카테고리별 본문 검색·이력 보관 설정, 옛날자료 숨김 규칙, 분류 원칙, 재생목록 정리 결정을 정한다.

## 카테고리별 설정

본문 검색과 이력 보관은 문서별 독립 설정이며, 인식하는 카테고리가 값을 정한다. 개수는 정리본 2,902개 기준이다.

| 카테고리 | 문서 수 | 본문 검색 | 이력 보관 |
|---|---:|---|---|
| 가사찬양 | 1,604 | 켬 | 끔 |
| 악보찬양 | 829 | 켬 | 끔 |
| 예배순서 | 200 | 켬 | 켬 |
| 특별순서 | 25 | 켬 | 켬 |
| 옛날자료 | 219 | 끔 | 끔 |
| 미결 | 25 | 기존 설정 유지 | 기존 설정 유지 |

- 카테고리는 PP6 문서 루트의 `category` 속성이다. 저장·업로드 때 읽어 검색·이력 설정에 연결한다.
- 위 다섯 이름이 아닌 카테고리와 미분류 문서는 기존 독립 설정을 보존한다.
- 카테고리가 정한 문서의 설정은 수동으로 바꾸지 않는다. 바꾸려면 원본 문서의 카테고리를 바꾼다(서버는 409로 거절한다).
- 예배순서는 매주 갱신하는 문서와 공통 화면을 함께 담은 범주다. 본문 검색을 끄지 않는다.
- 이력 끔은 새 버전을 저장할 때 이력 끔 이후의 이전 버전을 지우는 설정이다. 설정을 바꾸기 전에 쌓인 버전과 기존 백업을 일괄 삭제하지 않는다. 목록 보관본은 별도 R2 경로에 있어 이 설정과 무관하다.
- 본문 검색 끔은 본문 색인을 만들지 않고 이름·경로 검색만 하는 설정이다.
- 버전 CAS는 이력 보관을 꺼도 유지한다.

## 옛날자료 숨김

- 옛날자료만 사용일(`lastDateUsed`)이 2년을 넘으면 일반 Studio 검색에서 숨긴다. 기준일은 한국 날짜의 2년 전 같은 날이며, 그 날짜 당일은 보인다.
- 찬양은 사용 기간으로 숨기지 않는다.
- 사용일이 없거나 읽지 못했거나 현재 버전의 값이 아닌 문서, 미결 문서는 자동으로 숨기지 않는다.
- 숨긴 자료도 명시적으로 포함해 검색할 수 있고(`includeArchived`), 재생목록과 직접 참조에서는 그대로 열린다.

## 분류 원칙

- 파일명이나 경로로 문서를 임의 분류하지 않는다. 카테고리는 원본 문서의 `category` 속성만 따른다.
- 사용자 원본 파일명과 경로를 정리하거나 바꾸지 않는다.
- 미분류 문서의 설정은 그대로 두고, 기존 백업도 일괄 삭제하지 않는다.
- 사용일 정렬과 본문 글자 포함 검색은 유지한다. 비용을 이유로 본문 검색을 제목·접두어·단어 검색으로 줄이거나 짧은 한글 검색어를 누락시키지 않는다.

## 문서·목록 관리

- 문서 추가와 복제는 새 이름·카테고리로 만든다. 같은 이름은 덮어쓰지 않는다.
- 복제는 문서·슬라이드 UUID와 내부 참조를 새로 매기고 사용일을 초기화한다. 저장하지 않은 편집·서식·미디어 경로는 보존한다.
- 재생목록 목록 추가·보관·복원은 Studio에서 한다. 보관본은 보관 시점의 문서 원본을 함께 간직한다([server-storage.md](server-storage.md)).

## 재생목록 정리

- 활성 유지 7개, 보관 7개, 삭제 5개로 정했다. 승인된 선택이므로 다시 묻지 않는다. 결혼예배는 보관, 중보기도자 컨퍼런스는 삭제다.
- 정리본의 `기본 .pro6pl`에는 유지 7개, `보관목록.pro6pl`에는 보관 7개가 있다.
- 보관 7개의 서버 처리는 교회 이관의 맨 마지막에 한다.
- 보관·삭제는 식별자 기준으로 처리하며 문서 원본은 지우지 않는다. 보관 당시 문서 원본이 없는 항목(성탄절 등)은 누락으로 기록하고, 미디어 전체가 확보됐다고 표시하지 않는다.
- 가사찬양 문서의 기존 배경은 유지한다. 단 MOV 참조는 제거한다([media.md](media.md)).
