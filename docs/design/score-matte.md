# 악보 배경 걷기 엔진

같은 PPT에서 나온 같은 배경의 악보 장 여러 장을 비교해 배경판을 만들고, 장마다 악보만 남긴 투명 그림을 만든다. AI가 아닌 정해진 규칙의 그림 처리이며 모두 브라우저 안에서 돈다(서버·D1 요청 없음). Studio PPT 가져오기에는 아직 넣지 않았다. 지금은 실험실 페이지에서 실제 문서로 다듬는 단계다.

## 코드

- `web-editor/score-matte/matte-ops.mjs`: 최대·최소 필터(van Herk), 블랙햇, 장별 밝기 중앙값, 연결 요소, 거리(3-4 체임퍼), 닫기, 빈 칸 메우기(피라미드), 오츠 문턱. DOM 없음.
- `matte-core.mjs`: `buildPlate(frames)`(배경판), `singlePlate(frame)`(한 장), `matteFrame(frame, plate, options, marks)`(한 장 투명 악보), `DEFAULTS`(조절값과 뜻), `MARK`(붓 값).
- `matte-session.mjs`·`matte-worker.mjs`·`matte-client.mjs`: Web Worker 감싸기. 작업자를 띄울 수 없으면 같은 처리를 화면에서 돌린다.
- `synthetic.mjs`: 검사용 합성 장(보케 배경, 고정 오선·제목, 장마다 다른 입체 음표·가사, 하단 네비게이터·로고, 한 장에만 얼룩)과 정답 비교.
- 실험실: `web-editor/score-lab.html`·`score-lab.mjs` → 사이트 `/score-lab.html`(Studio에서 링크하지 않음). `node scripts/build-score-lab.mjs <출력.html> [--artifact]`는 PPT 변환기·작업자까지 한 파일에 넣는다.
- 검사: `tests/score-matte.test.mjs`(엔진, 합성 960×540), `tests/browser/score-lab.cjs`(실험실·붓·PPTX 링크 빼기).

## 방식

1. 배경판(장 N개, 4장 이상 권장, 32장까지)
   - 장마다 블랙햇(창 반지름 15px, 1920 기준)으로 얇고 어두운 획을 찾는다.
   - 획(둘레 2px 포함)을 뺀 장들의 밝기 중앙값 장의 색을 배경판으로 쓴다.
   - 거의 모든 장(75%)의 같은 자리에 있는 획은 고정 획이다. 고정 획 가장자리는 잡음으로 들쭉날쭉하므로 바뀌는 획에서 뺀다.
   - 고정 획이 장마다 바뀌는 획(음표·가사)에 붙어 있으면 악보(오선·음자리표)로 보고, 배경판에서는 둘레로 메운다. 그래서 모든 장에 남는다.
   - 떨어진 고정 획은 아래 띠(22%) 안이면 배경(하단 네비게이터·로고)으로 배경판에 그대로 두어 지워지게 한다. 띠 밖이면 검정에 가까운 칸이 있을 때만 악보(제목), 아니면 배경(사진 속 가지).
   - 아래 띠 안에서만 바뀌는 덩어리(현재 장 단추 강조)는 악보에 붙었는지 볼 때 세지 않는다.
   - 메우고도 남은 외톨이 어두운 획을 한 번 더 메운다.
   - 배경 고정 획 둘레를 네비게이터 자리로 둔다.
2. 장마다
   - 어둠 = 채널별 (배경−그림)/배경 중 큰 값. 옅은 덩어리 중 핵심(어둠 0.32 이상)이 없는 것은 지운다. 네비게이터 자리 안에 다 들어가는 덩어리도 지운다.
   - 입체 음표: 핵심을 닫은 자리 안에서 배경과 다른 칸(밝은 하이라이트 포함)은 몸통으로 본다. 둘레가 두꺼운 작은 구멍(하이라이트)은 메우고, 글자 o처럼 둘레가 얇은 구멍은 두지 않는다. 몸통 안쪽은 원래 색 그대로 불투명, 몸통 가장자리는 안쪽 색을 악보 색으로 보고 배경과 섞인 비율을 구한다(회색 음표 테두리가 옅어지지 않음).
   - 나머지는 어둠을 투명도로 쓰고 색은 (그림 − (1−a)·배경)/a로 되살린다.
3. 붓(칸마다 표시, 장마다 또는 모든 장 같은 자리)
   - 정교하게: 칠한 곳 안에서만 '검고 색이 적은 정도'로 오츠 문턱을 다시 정해(최소 0.5) 검은 악보만 남긴다. 고른 검정 둘레의 무채색 명암과 테두리 1칸은 되살린다.
   - 지우기: 칠한 칸은 배경. 악보(고정 오선 등)에 붙지 않았고 칠한 곳의 4배보다 작은 덩어리는 통째로 지운다(대충 칠해도 됨). 오선에 붙은 덩어리는 칠한 칸만 지운다.
   - 살리기: 칠한 곳은 옅은 문턱(절반)을 쓰고 덩어리 지우기에서 뺀다.

## 합성 검사 결과(1920×1080, 8장)

- 배경판 약 3.4초, 장마다 0.5~0.9초(Node, 작업자 안 브라우저도 비슷).
- 찌꺼기 79칸, 잃은 악보 0.05%, 음표 머리 불투명 99%, 네비게이터·로고 남은 비율 0.
- 얼룩 장에 정교하게 붓: 얼룩 99% 지움, 붓 아래 악보 98% 남김.
- 실제 교회 문서로는 아직 재지 않았다. 실험실의 '보고 복사' 글(설정값·숫자만)과 화면 캡처로 다듬는다.

## PPTX 장 이동 링크

- 하단 네비게이터가 PPT 안의 링크 단추(도형 또는 글자에 `ppaction://hlinksldjump`·`hlinkshowjump`)라면 그림 처리 없이 뺄 수 있다. `ppt-engine-entry.mjs`의 `render(..., {mode:'full', dropJumpLinks:true})`가 장의 그 개체를 빼고, 레이아웃·마스터의 링크 개체는 그리는 동안만 떼어 둔다. 기본값은 끔이라 Studio 동작은 그대로다.
- 이미 그림 한 장에 합쳐진 네비게이터(PP6 PPT 가져오기 결과 등)는 위의 그림 처리로 지운다.

## 레이어가 나뉜 PPT

- 장마다 악보가 이미 투명 PNG로 들어 있고 배경 사진이 따로 깔린 파일은 배경 걷기가 필요 없다. Studio '악보와 배경 분리'가 그대로 나눈다. 실험실은 'PPTX: 악보 그림만'에서 이런 파일이면 화면 위에 알려 준다.

## 한계

- 장마다 배경 사진이 다르면 배경판이 나오지 않는다.
- 어두운 배경 위 흰 글자는 방향이 반대라 다루지 않는다.
- 악보와 떨어진 고정 획을 위치로 나누므로, 아래 띠 안에 있는 고정 악보(모든 장에 같은 마지막 줄 등)는 지워질 수 있다. 그때는 띠를 줄이거나 살리기 붓.
- 1920×1080 24장은 작업자 안에서 약 200MB를 쓴다.

## Studio에 넣을 때(남은 일)

- 악보 용도 PPT 가져오기에서 악보 그림이 불투명하고 같은 크기 그림이 4장 이상이면 `배경 걷기(장 비교)` 선택지를 보인다. 흰 바탕 투명화는 그대로 둔다.
- 미리보기에서 붓을 쓸지, 실험실에서 정한 값만 쓸지는 실험실 결과를 보고 정한다.
- 공개 저장소라 교회 그림은 커밋하지 않는다. 실제 문서 비교 자료는 저장소 밖에 둔다.
