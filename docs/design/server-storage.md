# 서버 저장 설계

자료 종류별 저장 위치(D1·R2), 버전과 CAS, 집(Studio)과 교회(Mac)의 역할을 정한다. 현행 API 목록과 배포·설정은 [cloudflare/README.md](../../cloudflare/README.md)가 맡는다.

## 원칙

- 서버가 정본이고 Mac은 사본이다. 서버는 Cloudflare Worker `yebaeon`, D1 `pp6-library-db`(바인딩 `DB`), R2 `pp6-library-files`(바인딩 `FILES`)로 구성한다.
- 원본 바이트는 R2에, 메타데이터·현재 버전 포인터·버전 행은 D1에 둔다. D1 표와 색인은 `yebaeon_` 접두사를 쓴다.
- R2는 공개하지 않는다. 문서·이미지·재생목록은 세션(또는 장치 열쇠)을 확인하는 Worker API로만 읽고 쓴다. 브라우저와 Mac에 R2 접근키를 두지 않는다.
- 파일 무결성과 중복 판정에는 원본 바이트의 SHA-256을 쓴다. 의미 지문(semantic fingerprint)은 서버 버전의 변경 판정 기준이 아니다.
- 저장은 R2 업로드 후 D1 batch 한 번으로 포인터 변경·버전 행·변경 일지를 확정한다. 일지 행에는 `write_id` 조건을 달아 CAS가 실패한 저장이 남지 않게 한다. CAS 실패 때는 방금 올린 R2 객체를 지우고 409를 돌려준다. 확정 여부를 알 수 없는 실패에서는 원본을 지우지 않으며, 참조 없는 R2 객체의 정리는 유지관리 항목이다.
- 서버에는 문서 삭제 API가 없다. Mac의 문서 삭제를 서버에 자동 반영하지 않는다.

## 자료별 저장

| 자료 | R2 | D1 | 버전·CAS |
|---|---|---|---|
| 문서 원본(`.pro6`, 최대 25 MiB) | `documents/<문서id>/<writeId>.pro6` | `yebaeon_documents`(경로·현재 버전·sha256·크기·저장자·카테고리·검색/이력 설정·최근 사용일), `yebaeon_versions`, 본문 검색 `yebaeon_document_search` | 문서별 정수 버전. 저장은 `If-Match: "N"`이 현재 버전과 같을 때만 확정한다. 다르면 409, 헤더가 없으면 428 |
| 장부(이름·경로만 등록된 문서) | 없음 | `yebaeon_library_catalog`(id·경로·원래 경로·크기·슬라이드 수) | 버전 없음. 문서 줄과 경로로 이어진다 |
| 재생목록 파일(`.pro6pl`, 최대 5 MiB) | `playlists/<id>/<writeId>.pro6pl` | `yebaeon_playlists`, `yebaeon_playlist_versions` | 저장마다 파일 버전이 1 늘어난다. 파일 전체 PUT은 `X-YebaeOn-Sync: 2` 머리글이 없으면 426으로 거절한다 |
| 재생목록 노드(예배) | 없음(파일 버전에 포함) | `yebaeon_playlist_node_versions`(노드 XML·sha256·노드 버전), `yebaeon_playlist_controls`(활성·보관·삭제 상태) | 노드 교체의 기준은 그 노드의 서버 sha(`baseNodeHash`)뿐이다. 다른 예배의 변경과 부딪히지 않는다 |
| 이미지 | `media/sha256/<앞 2자>/<sha256>` | `yebaeon_media_assets` | sha256이 식별자라 버전이 없다. [media.md](media.md) |
| 목록 보관본 | `playlist-archives/<재생목록id>/<uuid>/`(보관 시점의 노드 XML·문서 원본 복사·`manifest.json`) | `yebaeon_playlist_controls.snapshot_key` | 일반 문서 이력 정리와 독립이다 |
| 교회 Mac 수정본 | `revisions/<id>.xml` | `yebaeon_sync_revisions`(대상·기준 버전·이유·해결 상태) | 현재본이 아닌 별도 보관본이다. 이력 끔 정리에 걸리지 않는다 |

변경 일지(`yebaeon_sync_log`)와 장치(`yebaeon_sync_devices`)는 Sync 2가 쓰는 표다. 일지·영수증·판정 규칙은 [sync.md](sync.md)가 정한다.

## 문서

- 같은 경로·같은 내용의 재업로드는 새 버전을 만들지 않는다. 같은 경로에 다른 내용이면 409로 기존 문서를 열어 편집하게 한다.
- 경로는 NFC로 정규화하고 절대경로·상위 경로 이동을 거절한다. 원본 파일명과 경로는 바꾸지 않는다.
- 이력 보관은 문서별 설정이다. 켬이면 모든 버전을 남긴다. 끔이면 저장할 때 이력 끔 이후의 이전 버전 행과 원본을 지우고, 끔으로 바꾸기 전의 버전은 남긴다. 버전 번호와 CAS는 이력 설정과 무관하게 유지한다. 카테고리별 값은 [library-policy.md](library-policy.md)가 정한다.
- 이전 버전을 복원하면 그 내용을 새 현재 버전으로 저장한다. 버전 번호를 되돌리지 않는다.
- 최근 사용일(`lastDateUsed`)은 원본 XML에서 읽는다. Mac이 보고한 사용일(`reported_used`)보다 옛 값으로 저장 때 되돌리지 않는다. 사용일 보고는 새 버전을 만들지 않는다.
- 검색용 본문과 사용일은 업로드·변경 때 그 문서만 갱신한다. 일반 목록·검색 요청에 전체 색인 갱신을 붙이지 않는다.

## 장부

- 장부 줄은 경로·크기·슬라이드 수만 가진다. 원본이 없어도 Studio에서 검색하고 재생목록 순서에 넣을 수 있다. 편집하려면 원본이 서버에 있어야 한다.
- 문서 줄과 장부 줄의 정체성, Mac이 보내는 이름 변동분, 원본 요청 흐름은 [sync.md](sync.md) 5.2가 정한다.
- 원본 없는 장부 이름은 저장과 Mac 적용을 막지 않는다. Mac은 자기 파일을 그대로 쓴다.

## 재생목록

- 작업 단위는 예배(노드)다. 한 `.pro6pl`에 여러 예배가 들어 있고, 선택한 노드만 바꾸며 다른 노드의 바이트는 건드리지 않는다.
- 웹의 순서 저장과 Mac의 노드 교체는 모두 그 예배 노드의 sha(`baseNodeHash`)를 기준으로 한다. 같은 파일의 다른 예배가 먼저 저장돼 파일 버전이 올라도 막지 않는다. 기준 sha를 보내지 않는 옛 요청만 파일 버전(`If-Match`)으로 비교한다.
- 같은 예배를 다른 사람이 먼저 저장해 409가 나면 Studio는 막지 않는다. 서버 최신 순서를 받아 그 sha로 내 순서를 다시 올려 덮어쓰고, 내 기준·서버 최신·내 순서를 비교해 빠진 항목(상대가 넣은 것), 다시 들어간 항목(상대가 뺀 것), 되돌린 자리, 순서 바뀜을 저장 결과 창으로 알린다. 서버 API의 CAS는 그대로다.
- 문서는 덮어쓰지 않는다. 409(`version_conflict`)면 Studio가 `최신 버전 불러오기(내 편집 버림)`·`내 편집을 사본으로 저장`·`나중에(초안 유지)`를 묻는다. 사본은 같은 폴더에 `이름 (사본 작업자 MMDD-HHmm).pro6`로 새 문서가 되고(PP6 UUID 새로 발급), 순서에는 원래 문서가 남는다.
- Studio `서버 저장`은 이 탭의 미저장 문서 전부와 미저장 순서 전부(열린 순서, 이 탭에서 고치다 떠난 순서, 주보로 넘긴 순서·문서 초안)를 한 번에 올린다. 문서를 먼저 올리고, 문서가 하나라도 실패하면 순서는 올리지 않는다. 실패한 것은 브라우저 초안에 남는다.
- 웹에서 만든 노드의 유실과 보관 노드의 부활을 막기 위해, 기존 노드를 빠뜨린 파일 전체 PUT은 409로 거절한다. 명시적 보관·삭제 API는 허용한다.
- 목록 보관은 보관 시점의 문서 원본을 별도 R2 경로에 복사한다. 문서 원본이 없거나 해시가 다르면 보관을 완료하지 않는다. 복원은 현재 문서 원본을 확인한 뒤 현재 문서로 연결한다.

## 집과 교회의 역할

- 집(Studio): 문서 검색·편집·저장, 재생목록 순서 편집, 목록 추가·보관·복원, 문서 추가·복제, 이미지 추가, 교회 Mac 수정본 비교. 입장한 사람은 모든 자료를 읽고 편집한다.
- 교회(Mac, Sync 2): 서버 내용을 받아 PP6 문서 폴더에 적용하고, PP6를 닫을 때 Mac에서 고친 것을 올리며 사용일을 보고한다. 초기 구축 때의 원본 일괄 업로드는 Sync 앱과 분리한 단독 업로더 스크립트로 한다.
- PP6 실행에 서버 연결은 필요하지 않다. 인터넷이 없으면 로컬 파일로 운영한다.
- 서버는 Mac 파일을 삭제하지 않는다. 비교와 충돌 규칙은 [sync.md](sync.md)를 따른다.
