# 이미지 서버 저장 설계

서버가 보관하는 이미지의 범위, 식별, 보호, 정리 기준과 영상 제외 결정을 정한다. Mac 쪽 이미지 설치 규칙과 허용 폴더는 [sync.md](sync.md) 5.4가 정본이며 여기서는 되풀이하지 않는다.

## 범위

- 대상은 전체 문서 라이브러리의 문서가 참조하는 이미지다. 현재 재생목록의 문서로 한정하지 않는다. 재생목록 밖 문서의 이미지와 악보 PPT에서 가져온 슬라이드 이미지·배경을 포함한다.
- 영상은 서버에 올리지 않는다. 영상 바이트가 없는 것은 이미지 전송 실패가 아니다. 영상이 있는 예배는 Mac에서 로컬 확인이 필요하다고 표시한다.
- 이미지가 서버에 없어도 문서의 저장과 적용은 막지 않는다. 그 예배는 완료가 아니라 이미지 누락 상태로 표시한다.
- 전체 문서를 웹에서 열 수 있어야 하므로, 재생목록에서 쓰지 않는다는 이유만으로 이미지를 정리하지 않는다.

## sha 기준 저장

- 이미지는 내용 SHA-256으로 식별하는 불변 객체다. R2 키는 `media/sha256/<앞 2자>/<sha256>`, D1 `yebaeon_media_assets`에 sha256·크기·검증된 종류·보호 여부·revision·저장자를 둔다.
- 다른 이름의 같은 바이트는 하나로 저장한다. 같은 이름의 다른 바이트는 별개다. 시각적 유사도나 재압축으로 합치지 않는다. 파일명과 원래 경로는 식별자가 아니라 표시용 메타데이터다.
- 업로드(`PUT /api/media/<sha256>/content`)는 `X-Yebaeon-SHA256` 값과 본문 해시가 같을 때만 저장한다. 내용으로 확인한 이미지 형식(JPEG·PNG·GIF·BMP·WebP·TIFF·PSD·PDF·HEIC)만 받고 크기 상한은 32 MiB다.
- 업로드는 멱등이다. 응답이 유실된 뒤 같은 요청을 다시 보내면 같은 결과를 찾는다. 이미 저장된 객체의 해시가 다르면 덮어쓰지 않고 오류로 멈춘다. 중단된 전송은 완성 원본으로 공개하지 않는다.
- 32 MiB를 넘는 이미지가 실제로 있을 때만 R2 multipart와 스트림 해시로 분할 전송한다. 원본 전체를 Worker 메모리에 모으지 않는다.
- 경로 키에서 sha256·크기를 찾는 경로표(`media_paths`)는 라이브러리 공용이다. 문서 버전마다 참조 표를 따로 두지 않으므로 문서를 어디서 저장하든 경로표는 그대로 유효하다. 한 sha에 여러 경로가 매달릴 수 있다. 경로 키와 허용 폴더의 규칙은 [sync.md](sync.md) 5.4를 따른다.
- 이미지를 처음 모두 올릴 때는 문서가 참조하는 고유 이미지를 먼저 조사하고, 서버에 없는 sha만 올린다. 그 뒤에는 변경된 문서의 새 이미지만 올린다. 이미지 폴더 전체를 무조건 전송하지 않는다.

## 이미지 버전 없음

- 이미지 버전 이력을 만들지 않는다. 이미지를 바꾸는 것은 다른 sha를 참조하는 것이다.
- 다른 문서·목록 보관본·복구본이 쓰는 기존 바이트는 그대로 유지한다.
- 문서 복제는 이미지 바이트를 복제하지 않고 같은 참조를 재사용한다.

## 서버 보호 표시

- 저장되는 모든 이미지는 기본으로 보호 상태다. 보호하려고 Mac 폴더를 옮기라고 요구하지 않는다.
- 보호는 sha 하나에 한 번 적용한다. 이름이 다른 동일 바이트에도 함께 적용된다.
- 보호 변경(`PUT /api/media/<sha256>/protection`)은 현재 `revision`을 함께 보내야 하며, 다른 작업의 결정을 덮어쓰지 않는다.

## 정리

- 정리 후보는 수동으로 검토한다. 유예기간과 복구 방식이 정해지기 전에는 자동 예약 삭제를 만들지 않는다.
- 후보 조건: 현재 문서, 보존 중인 문서 버전·보관본·복구본, 진행 중인 전송·복원의 어디에서도 참조되지 않고 보호도 없는 이미지다. 참조 정보가 불완전하면 정리를 보류한다.
- 참조 개수가 줄었다는 이유로 곧바로 지우지 않는다. 후보로 고른 뒤 다시 참조되거나 보호가 생기면 지우지 않는다.
- 후보 계산은 현재본·보관본·이력 문서를 파싱해 쓰임을 확인하는 유한한 작업이다. 문서 이관이 진행 중일 때는 후보를 만들지 않는다.
- 서버 이미지 정리(R2 바이트 삭제)는 Mac 원본 삭제와 별개다. R2 정리가 Mac의 이미지를 지우지 않는다.
- 고아 이미지 정리는 경로 단위다: 관리자가 `ImportedImages`·`YebaeOn`에서 어느 문서도 쓰지 않는 경로를 휴지통에 넣으면 교회 Mac이 다음 [적용] 때 그 파일을 macOS 휴지통으로 옮긴다. R2 바이트는 그대로 둔다(sync.md 13.2).

## MOV 참조 제거

- 가사찬양 문서의 MOV 참조는 정리본에서 제거한다(115개 문서·887개 참조). 가사·슬라이드 구성·MP4·이미지·다른 카테고리의 배경은 유지한다.
- MOV 파일 자체는 삭제하지 않는다.
- 문서·영상 원본과 변경 전 복구본은 공개 Git에 넣지 않는다.

## 오프라인 업데이트 ZIP

서버와 별개인 오프라인 전달 경로로, 다음 구조를 쓴다.

```text
PP6-Update/
├─ documents/   문서(.pro6). 상대경로는 ~/Documents/ProPresenter6 상대경로와 대응한다
├─ assets/      선택. 이 업데이트에 필요한 새 미디어만 담는다
└─ playlists/   재생목록(.pro6pl)
```

- 비교 키는 NFC로 정규화한 상대경로이며, 실제 파일명은 NFC로 바꾸거나 이름을 바꾸지 않는다.
- 대상 Mac에 이미 같은 미디어가 있으면 `assets/`에 다시 넣지 않아도 된다.
- 문서 삭제는 자동 반영하지 않는다.
- ZIP으로 전달한 이미지도 Mac 설치와 이름 충돌 처리는 [sync.md](sync.md) 5.4를 따른다.

## Studio 미디어 창

- 그림 바이트(`GET /api/media/<sha256>/content`)는 sha 주소라 내용이 바뀌지 않으므로 `private, max-age=31536000, immutable`로 보낸다. 공용 캐시(CDN)에는 남지 않고 입장한 브라우저에만 남는다.
- 서랍은 ★ 공용 즐겨찾기(`/api/favorites`, sha 기준), 열린 재생목록 문서가 슬라이드 배경(`backgroundMediaCue`)으로 쓰는 그림, 나머지 서버 그림 순으로 보인다. 배경 칸은 ImportedImages를 빼고, 접힌 `사용된 전체 이미지 보기`는 얹은 그림·가져온 이미지까지 모두 보인다.
- 나머지 그림은 `GET /api/media/paths?folder=Images|YebaeOn`으로 그 폴더의 경로 범위만 쪽 단위(60)로 읽는다. ImportedImages(PPT 슬라이드 그림)는 목록으로 내주지 않는다. 이름 검색은 `instr`로 한다(D1 LIKE 패턴 길이 한도 때문에 경로 앞부분에 LIKE를 쓰지 않는다).
- `그림 추가`는 내 컴퓨터·드롭박스 그림(PNG·JPG·WebP·GIF·BMP, 20MB 이하)을 원본 그대로 올리고 `YebaeOn/<이름>-<n>.<원본 확장자>` 경로를 서버에서 받는다. 단색은 슬라이드 크기 PNG로 만든다. 문서에 넣는 주소는 PP6가 다시 저장할 때 쓰는 `file:///Users/Shared/Renewed%20Vision%20Media/…` 형식이다(Sync 2는 평문 경로와 같은 내용으로 본다, 83a16a7).
- 배경 자르기는 원본을 바꾸지 않는다. 고른 영역을 새 그림(원본이 JPEG면 JPEG)으로 올려 그 장의 배경 주소만 바꾼다. 채우기·맞추기·늘이기는 그림 요소의 `scaleBehavior`를 1·0·3으로 바꾼다(10-05 교회 PP6에서 확인. 2는 뜻을 모르며 Studio는 채우기로 그린다). 새 배경 요소는 PP6가 저장하는 모양 그대로 쓴다: 큐 `behavior="2" enabled="false" displayName=<파일 이름>`, 그림 요소에 위치 `{0 0 0 0 0}`(화면 전체)·그림자·테두리 사전, `format="PNG 이미지"`/`"JPEG 이미지"`.
- 미리보기 그림은 R2 `media/thumb/<앞 2자>/<sha256>`에 가로·세로 320px 이하 WebP로 둔다. D1 행은 없고 있는지는 R2 head로 안다. 원본이 서버에 있는 sha만 받는다. 한 번 만들면 모두가 쓴다.
- 교회 자료 목록(`church-resources/catalog.json`)에는 그림을 두지 않는다(10-05 20개 제거). 렌더는 서버 경로표만 쓴다.
