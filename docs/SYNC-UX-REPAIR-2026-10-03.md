# Sync 0.6.6: 업로드 차단과 비교 화면 수정

## 확인한 원인

- 21:20 사용자 캡처는 2,884개 모두 보내기, 충돌 0개인데 전체 탭이 선택되어 있었다. `selectedDirection`이 전체 탭에서 nil을 반환했고 체크박스·전체 선택·전송 버튼을 함께 비활성화했다. 사용자가 보내기 탭을 알아서 눌러야 하는 숨은 조건이었다.
- 문서 행의 글자가 selectable이어서 행 선택보다 텍스트 선택이 우선할 수 있었다. 충돌 탭에는 전송 방향이 없어 하단 해결 버튼도 없었다. 기존 더블클릭·우클릭 비교만으로 해결 가능하다고 판단한 검증이 부족했다.
- 서버 문서가 없을 때 과거 기준이 남으면 `YBDisposition`은 충돌로 판정했다. 명시적인 새 업로드로 처리할 수 있는 상태를 막았다.
- 재생목록 계획의 실제 서버 문서 목록만 문서 탭에 넘겼다. 서버 파일이 없는 참조는 계획의 items에는 있지만 documents에는 없어 연결 문서 화면에서 사라졌다. 기존 검색·방향 필터도 그대로였다.
- Mac 기준 서버 맞추기는 참조 파일 하나가 없어도 준비 전체를 실패시켰다.
- 이전 0.6.5는 문서 내용 비교 화면만 개선했고 재생목록의 줄글 비교는 그대로였다. 사용자 요구 충족을 잘못 보고했다.

## 변경

| 화면/상태 | 새 동작 |
|---|---|
| 전체 탭, 보낼 문서만 있음 | 체크·전체 선택 후 바로 보내기 |
| 전체 탭, 받기와 보내기 혼재 | 한 방향 선택 후 해당 문서만 전체 선택. 반대 방향을 임의 적용하지 않음 |
| 문서 충돌 | 각 행의 비교·해결 버튼 또는 충돌 탭에서 행 선택 후 하단 비교·해결 |
| 서버에 없고 Mac에 있음 | 과거 기준 유무와 무관하게 보내기. 서버 신규 생성 조건 검사는 유지 |
| 재생목록 문서별 확인 | 남은 검색·방향 필터를 해제하고 서버 미등록 문서도 표시 |
| 재생목록 비교 | 순번 / Mac 순서 / 서버 순서 / 순서 비교 / 연결 문서 표 |
| 누락된 Mac 참조 | 준비 화면에 누락 경로를 알리고 나머지 문서를 전송. 참조와 서버 기존 문서는 보존 |

비교표는 현재 순번을 나란히 보여준다. 삽입으로 이후 순번이 달라진 경우 각각의 현재 위치를 그대로 표시하며, 의미 기반 자동 재배열/병합은 하지 않는다. 누락 파일 자체를 복구하거나 없는 문서를 만들어 주는 기능은 아니다.

## 확인 범위와 운영 영향

사용자 Mac과 운영 서버는 이 작업에서 수정하지 않았다. 최신 Studio 병합 fbcab5b를 기반으로 앱 파일만 변경했다. 원본 파일명·경로를 바꾸지 않는다. 동기화 기준 초기화를 다시 강요하지 않는다.

버튼 활성 상태와 실제 전체 선택 클릭, 충돌 행 선택, 문서별 확인의 필터 해제, 병렬 표 렌더링을 합성 AppKit 자료로 확인한다. Worker 통합에서 서버 미등록 문서의 보내기 판정, 누락 참조를 보존하면서 나머지 문서를 서버에 적용하는 경로를 확인한다. 기존 CAS·파일 변경 보호 검사를 유지한다. Mac CI와 패키징 결과는 아래에 기록한다. High Sierra 실기 검증과 사용자 2,884개 실제 업로드 완료는 별도다.

D1 영향: 새 폴링/타이머/API/SQL 없음. 화면 선택·검색·비교표·문서별 확인은 이미 받은 비교 자료를 사용한다. 기존 재생목록 plan에서 missing으로 확인한 경로만 Mac에서 추가 확인하며 서버 문서 전체 조회를 추가하지 않는다. 문서 열기/저장과 재생목록 저장, 전체 Sync 비교/받기의 기존 호출 계약은 유지한다. 이전에는 중단되던 명시적 업로드가 진행되므로 실제 선택한 신규/변경 문서 수만큼 기존 업로드 API 쓰기가 발생한다. 운영 D1 rows_read/rows_written은 실측하지 않았다.

## 검증 및 배포
