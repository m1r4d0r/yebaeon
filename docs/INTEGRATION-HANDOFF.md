# 예배온 통합 개발 인수인계 · 2026-10-01

## 패키지를 구분하는 기준

- `PP6-Playlist-Sync-Native-v0.2.zip`: 사용자가 교회에서 빌드한 네이티브 앱 원형. main.m, Info.plist, 빌드 스크립트와 더미 재생목록이 포함된다.
- `PP6-Local-Sync-Core-v0.2.zip`: 문서 인덱서·슬라이드 비교·썸네일 실험을 분리한 개발 패키지. 기존 앱 화면은 이 패키지에 없었다.
- `PP6-Original-Source-Assets.zip`: 사용자가 제공한 PP6/재생목록/미디어 원본과 진단 자료. 프로그램 소스 묶음이 아니다.
- `PP6-Playlist-Sync-Full-Dev-Bundle`: 위 원형들과 현재 예배온 소스·통합 앱·이 문서를 함께 전달하는 로컬 개발 묶음. 실제 원본 자료를 포함하므로 GitHub 소스에는 넣지 않는다.

## 지금 지원하는 흐름

공용 비밀번호와 이름으로 입장 → Mac의 `.pro6` 최초 업로드 → 웹에서 서버 문서 편집/저장 → 앱에서 비교·선택 수신·백업 후 적용 → PP6로 확인/저장 → 앱에서 다시 보내기.

재생목록 탭은 기존 로컬 파일 비교/선택 적용을 유지한다. 미디어 탭은 문서에 사용된 파일의 연결 상태를 점검한다. 재생목록 서버 저장, 미디어 파일 송수신·설치, 성경 자료 처리와 전체 자료의 일괄 적용은 후속 작업이다.

기본 문서 대상은 별도 시험 폴더이며 실제 라이브러리는 사용자가 선택한다. 기존 앱은 삭제할 필요가 없다. 새 앱은 첫 실행에 이전 운영 파일 경로를 읽을 수 있지만 기존 설정·백업을 삭제하거나 옮기지 않는다.

## 검증과 실제 환경의 경계

집은 Windows, 교회는 macOS High Sierra 10.13.6 + PP6다. Intel Mac CI에서 10.13 대상으로 빌드하고 합성 자료로 비교·백업·송수신·화면 생성을 검사한다. 운영 서버 웹 문서 왕복은 2026-09-30 실제 문서 복사본으로 별도 검증했다. 새 통합 앱의 High Sierra·키체인·운영 서버 연결·PP6 열기/저장은 교회 검증이 남는다.

통합 앱 0.3.0의 빌드 커밋은 `1408bdb`다. [최종 Mac 검사](https://github.com/m1r4d0r/yebaeon/actions/runs/36791133977)는 199개 검사 모두 통과했고 세 탭의 화면을 확인했다. 개발 묶음은 이 검사에서 생성한 앱 ZIP을 그대로 포함한다.

처음에는 서버 시험 문서 하나로 확인하고, 정상 동작하면 실제 `.pro6` 폴더를 연결해 라이브러리 최초 업로드를 진행한다. 기존 Core 숫자 검사·폰트 수집 등을 매번 다시 시키지 않는다. 폰트는 이미 사용자가 복사해 두었다.

## 개발과 자료 보관

소스 수정·커밋·푸시는 로컬 GitHub 예배온 저장소에서 한다. 다운로드의 Core 폴더는 이전 소스/원본 자료로 보관한다. GitHub 웹 로그인은 필요 없다. 비밀번호·브라우저 쿠키·Mac 키체인 세션은 개발 묶음이나 저장소에 넣지 않는다.

`mac-app/build-dev-bundle.py`가 Git에 커밋된 현재 소스와 명시한 원본 ZIP·검증 앱 ZIP을 모은다. 파일별 SHA-256과 소스/앱 빌드 커밋을 MANIFEST.json에 기록한다. 각 원본 ZIP은 변경하지 않고 그대로 포함한다.
