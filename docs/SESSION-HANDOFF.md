## 이후 기능과 한계

1. **미디어 전송:** 현재는 경로/누락 점검과 웹의 로컬 연결까지다. 사용된 미디어 R2 업로드, 내려받기, 설치, 문서 경로 변환은 미구현이다. 새 미디어로 교체한 ZIP용 문서는 서버 문서 저장에서 차단한다.
2. **성경 자료:** 원본 전체 업로드·목록·해석·검색·슬라이드 생성은 후속 범위다. 파일 형식/번역본을 확인해야 한다.
3. **렌더 정밀도:** Windows 웹과 Mac PP6의 줄바꿈·폰트 크기·효과·이전 배경 유지 차이가 남는다. PP6 정상 화면과 대조할 자료가 필요하다.
4. **확장 편집:** 새 플레이리스트 생성/이름 변경/전체 삭제, 예배별 공유 문서 복사, 배열/전환/자동 실행 단서의 전문 편집은 후속이다. 현재는 기존 플레이리스트의 문서와 순서를 편집한다.
5. **충돌:** 양쪽 수정은 차단한다. 자동 병합/강제 덮어쓰기는 제공하지 않는다. 서버 등록은 같은 파일 이름·다른 내용이면 충돌로 표시한다. 공유 영향 표시는 같은 `.pro6pl` 파일 범위다.

사용자는 목록 최초 표시는 빨라졌고 문서를 오갈 때 미리보기 지연이 남는다고 구분했다. 매번 메타데이터→원본 다운로드와 렌더 재생성, 문서 전환 시 미디어 캐시 제거가 반복되는 코드를 확인했다. PR #12는 인증된 최신 메타데이터의 버전·해시가 같을 때만 검증된 원본을 재사용한다. 원본 캐시는 24개/24MiB UTF-16 문자열 예산이며 메타데이터 조회는 계속한다. 미저장 초안과 서버 충돌 보호는 유지한다.

## 2026-10-02 예배별 순서 이력과 Sync 상태등

웹 PATCH는 선택한 예배 노드의 SHA-256을 기준으로 충돌을 검사한다. 다른 예배가 먼저 저장되면 최신 전체 파일에 해당 노드만 다시 적용하며 D1 전체 파일 CAS로 최대 5회 재시도한다. 같은 예배의 동시 변경과 개별 문서 충돌은 차단한다. Mac 전체 파일 PUT의 기존 CAS는 유지한다.

`yebaeon_playlist_node_versions`는 예배별 순서 번호·XML·작업자·시각을 보관한다. 최초 기준과 이후 바뀐 노드만 기록한다. 웹 이력/복원은 해당 예배에 한정하고 문서 가사를 복원하지 않는다. 이전 전체 파일 버전은 삭제하지 않는다. 기능 도입 전 이력은 전체 파일 기록으로 보존하며 새 예배 이력은 도입 시점의 현재 순서부터 시작한다. PP6로 내려받는 파일은 해당 과거 순서와 다른 예배의 현재 순서를 합친다.

Sync 0.5.3 build 11은 ‘변경 예배 모두 받기’를 제공한다. 받을 수 있는 예배의 문서를 경로별로 합쳐 공유 문서는 한 번 받고 모든 선택 노드를 한 `.pro6pl` 교체로 적용한다. 충돌/누락 예배는 제외 개수를 확인한다. 준비·문서·순서·완료 검증과 백업/중단 복구를 유지하며 묶음의 모든 노드 기준도 함께 복구한다.

웹 목록에는 8px 상태등과 툴팁을 둔다. 초록=마지막 Mac 확인에서 같음, 노랑=서버 변경/받기 필요, 빨강=양쪽 변경, 파랑=Mac 변경/보내기 필요, 회색=확인 전/미업로드. ## 2026-10-02 인덱스 자동 갱신과 전송 완료 후 종료

Sync 0.5.4/build 12는 시작 및 수동 문서 비교에서 원본을 읽지 않는 안전한 전체 경로·크기 스캔을 먼저 `/api/inventory`로 전송한다. 서버는 한 D1 batch 트랜잭션으로 장치별 구성원과 공유 catalog를 갱신한다. 새 경로는 원본 미업로드/읽기 전용으로 나타나고 기존 catalog ID·NFD 원래 경로를 유지한다. 실패/잘못된 스캔은 기존 장치 목록을 바꾸지 않는다. 없어진 항목의 서버 원본·버전·참조는 지우지 않으며 웹 툴팁의 마지막 Mac 목록 여부로 표시한다. 여러 장치는 각자 구성원을 보관하고 하나라도 가진 경로는 존재로 표시한다. 마지막 완료 스캔이며 실시간 감시가 아니다.
