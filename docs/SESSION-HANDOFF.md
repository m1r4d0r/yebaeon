재생목록 파일 자체가 같아도 연결 문서의 버전/해시가 바뀌면 받기 대상으로 잡는다. 선택하지 않은 플레이리스트의 XML은 그대로 보존하며 순서에서 뺀 문서를 자동 삭제하지 않는다. 받는 문서의 경로는 선택한 Mac 문서 폴더에 맞춰 연결한다.

중간 실패는 전체 완료로 표시하지 않는다. **중단 복구로 적용 전으로 되돌린 다음 다시 비교·받기**한다. 모든 파일이 한 번에 교체되는 운영체제 수준의 원자적 작업이나 무조건 이어받기를 의미하지 않는다. 이후 수정한 파일은 복구 중에도 자동 덮어쓰지 않는다.

## 검사 증거

- 전체 Node 검사: **20개 통과**. 실제 Worker/D1/R2 모사 환경에서 인증, 원본/이력, 동시 저장, 문서 연결, 가사만 변경, 추가/제거/정렬, 특수문자 경로를 검사했다.
- [Intel Mac 검사 36847704652](https://github.com/m1r4d0r/yebaeon/actions/runs/36847704652): 앱 빌드 커밋 **`8faa176`**, **256개 검사 통과**(문서 안전성 100, 문서 엔진/Worker 18, 앱·Core·화면 70, 기존 앱/Worker 15, 플레이리스트/Worker 53).
- Mac 검사는 원본 등록→웹 가사 수정→같은 플레이리스트 받기, 순서 이동, 공유 곡, 한글 분해형 경로, 누락/충돌, 다른 플레이리스트 보존, 준비/문서/순서 단계 중단, 재실행·복구·재시도, 새 시험 폴더 수신을 포함한다.
- 웹 로컬 화면: 합성 예배 2개로 입장→플레이리스트→가사 수정→문서 v2 저장→복귀, 순서 이동·추가·교체·제거를 v5까지 확인했다. 공유 문서 안내와 좁은 화면도 확인했다.
- 제공 원본 `.pro6pl`은 로컬에서 19개 플레이리스트/179개 항목(문서 178, 구분 1)으로 읽혔다. 실제 자료는 자동 검사나 공개 웹 파일에 넣지 않았다.
- 운영 서버의 개별 문서는 이전에 37장 시험 복사본 v1→2→3 저장·재열기·다운로드를 확인했다. 이 기록과 위 합성 플레이리스트 검사를 교회 PP6 실기 성공으로 혼동하지 않는다.

## 교회에서만 남은 확인

[교회 실행 순서](CHURCH-TEST.md)를 따른다. 새 앱 실행, High Sierra의 HTTPS·키체인 입장, 실제 라이브러리 최초 등록, 시험 폴더에 플레이리스트 수신, PP6에서 같은 순서/가사/배경·폰트 확인이 남았다. 자동 Mac 검사는 최신 Intel Mac에서 10.13 대상으로 빌드한 결과이며 High Sierra 실기 검증을 대신하지 않는다.

기존 앱을 삭제하거나 폰트를 다시 수집할 필요는 없다. 사용자는 이미 폰트 폴더를 복사해 두었다. 예전 Core 수치 비교·썸네일 검사를 반복 과제로 요구하지 않는다.

## 이후 기능과 한계

1. **미디어 전송:** 현재는 경로/누락 점검과 웹의 로컬 연결까지다. 사용된 미디어 R2 업로드, 내려받기, 설치, 문서 경로 변환은 미구현이다. 새 미디어로 교체한 ZIP용 문서는 서버 문서 저장에서 차단한다.
2. **성경 자료:** 원본 전체 업로드·목록·해석·검색·슬라이드 생성은 후속 범위다. 파일 형식/번역본을 확인해야 한다.
3. **렌더 정밀도:** Windows 웹과 Mac PP6의 줄바꿈·폰트 크기·효과·이전 배경 유지 차이가 남는다. PP6 정상 화면과 대조할 자료가 필요하다.
4. **확장 편집:** 새 플레이리스트 생성/이름 변경/전체 삭제, 예배별 공유 문서 복사, 배열/전환/자동 실행 단서의 전문 편집은 후속이다. 현재는 기존 플레이리스트의 문서와 순서를 편집한다.
5. **충돌:** 양쪽 수정은 차단한다. 자동 병합/강제 덮어쓰기는 제공하지 않는다. 서버 등록은 같은 파일 이름·다른 내용이면 충돌로 표시한다. 공유 영향 표시는 같은 `.pro6pl` 파일 범위다.
