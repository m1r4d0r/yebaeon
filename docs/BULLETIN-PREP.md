# 주보로 준비 · Dropbox 자료

## 사용

1. 스튜디오 상단 `주보·자료` → HWP 선택. 브라우저에서 HWP 5의 압축 본문과 표 셀을 읽는다. AI/OCR/외부 변환 서비스는 사용하지 않으며 주보 원본은 서버에 저장하지 않는다.
2. 1·2·3부 선택 → 적용할 재생목록 선택 → `찬양 후보 찾기`.
3. 정확히 같은 제목의 단일 후보 또는 이 브라우저에서 기억한 연결만 자동 선택한다. 찬송가 번호 검색을 지원하며 여러 후보는 사람이 선택한다. 고정 순서도 연결하거나 체크 해제한다. `부름의 찬양`처럼 제목이 없는 항목은 임의로 추정하지 않는다.
4. 기도·설교는 기본 글상자로 생성하거나 `서식 찾기`로 기존 문서를 선택하고 교체할 글상자를 지정한다. 문서 전체를 복제하고 고른 글상자만 변경한다. 이름/설교가 여러 글상자로 나뉘는 복잡한 서식은 적용 후 편집한다. 설교자는 별도 항목이며 기본 제외다. 필요하면 포함하거나 설교 제목에 함께 입력한다.
5. 말씀은 교회 개역개정 자료와 기본 말씀 템플릿으로 생성한다. `생성 미리보기`로 분할·줄바꿈을 확인한다. 본문의 범위는 기존 장절 파서 지원 범위(단일 절/연속 범위)다. 비연속 절은 사람이 나누어 추가한다.
6. `검수 완료 · 순서 초안에 적용`: 선택한 예배의 기존 순서 전체를 검수한 목록으로 교체한다. 주보에 없는 특순은 나중에 추가해야 한다. 기도·설교·말씀은 새 문서로 등록하여 원본 및 다른 예배를 변경하지 않는다. 원본 서식의 나머지 슬라이드는 복제본에 유지되므로 검수 시 확인한다.
7. 스튜디오에서 최종 검수 후 `변경사항 저장`으로 순서를 확정한다. CAS 충돌은 기존 방식으로 보호한다. 다른 부는 다시 주보 창에서 선택하고 진행한다.

준비 도중 실패하면 같은 화면에서 재시도한다. 생성 경로와 XML은 탭의 sessionStorage에 보존하여 새로고침 후 복구할 수 있다. 이미 성공한 문서는 재사용한다. 적용 전 새 문서는 서버에 생성되지만 순서는 저장 전까지 바뀌지 않는다. 중단 후 사용하지 않은 새 문서가 남을 수 있다. 이것을 전체 트랜잭션으로 표현하지 않는다. 순서 적용 뒤에는 기존 IndexedDB 초안 복구를 사용한다.

## Dropbox 최초 연결 (관리자 한 번)

이 기능은 ChatGPT Dropbox 플러그인과 별개다. 각 이용자는 예배온에 입장하며 개인 Dropbox 인증을 요청하지 않는다. 소유자의 열람 권한으로 서버가 읽는다. 앱 연결이 취소되거나 폴더 권한을 잃으면 다시 설정해야 한다.

1. https://www.dropbox.com/developers/apps 에서 Scoped access → Full Dropbox 앱을 만든다. 기존 공유폴더 접근을 위해 사용하며 전용 App Folder 접근은 해당 기존 폴더에 적용되지 않는다.
2. Permissions는 `files.metadata.read`, `files.content.read`만 활성화한다. 쓰기·삭제·공유 변경 권한은 사용하지 않는다.
3. 공유폴더가 소유자 계정에 추가되어 API 경로로 보이는지 확인한다. 링크만 받은 경우에는 이 버전의 경로 방식으로 읽을 수 없다. 경로는 예 `/교회/주보`이며 계정 전체 `/`는 금지한다.
4. 저장소를 받은 본인 컴퓨터에서 Node 22 이상으로 `npm ci`, `npx wrangler login` 후 `node scripts/connect-dropbox.mjs`를 실행한다.
5. App key / 폴더 경로 / App secret 입력 → 표시된 Dropbox 승인 주소를 열어 한 번 승인 → 승인 코드 입력. App secret과 코드는 화면에 표시하지 않는다. 스크립트는 폴더 읽기를 확인하고 네 값을 Worker secrets로 직접 전달한다. 채팅이나 GitHub에 토큰을 올리지 않는다.
6. Studio의 `교회 자료` 탭에서 폴더 탐색·다운로드·HWP 주보 선택을 확인한다.

자동화된 설정 대신 Cloudflare 대시보드에서 Worker 비밀값 `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_REFRESH_TOKEN`, `DROPBOX_ROOT`를 등록해도 된다. access token만 등록하면 만료되므로 offline 승인으로 받은 refresh token이 필요하다.

보안: 서버 세션 확인 후 지정 루트 내부 상대 경로만 허용, 메타데이터의 실제 경로 재검증, 서명한 페이지 커서, 응답 비캐시, 첨부파일 다운로드. 브라우저로 API 토큰을 전달하지 않는다. 목록 새로고침은 사용자 클릭 때만 수행한다. 공유폴더 원본 쓰기 API는 없다.

## 비용 영향

- 대기/초기 화면: 새 API 호출 0, 폴링/예약 작업 0. HWP 파서와 UI는 정적 자산이다.
- 주보 해석/수정/검수: 브라우저 처리. 말씀·서식은 기존 인증된 리소스 요청을 재사용한다.
- 후보 검색: 예배별 고유 검색어당 기존 문서 검색 최대 100건. 이 화면 내 같은 검색은 캐시한다. 응답 100건이 실제 rows_read 100을 뜻하지 않으며 기존 부분문자 검색은 문서 규모에 따라 스캔이 발생한다. 운영 실측은 미수행.
- 기억한 문서: 문서 ID별 조회. 전체 문서 내용 다운로드/본문 스캔을 추가하지 않는다.
- 적용: 선택한 동적 항목마다 문서 신규 등록. 이후 순서 저장은 기존 CAS 및 관련 선택 범위 조회를 사용한다. 찬양 원본은 복제하지 않는다.
- Dropbox: 요청별 세션 조회 + Dropbox 호출. 목록 100개씩, 파일은 스트리밍. D1에 목록/파일 사본을 저장하지 않는다. 토큰은 만료 전 메모리 캐시. Worker 재시작 시 갱신 요청이 늘 수 있다.
- 기존 문서 열기/저장, 재생목록 저장, Sync 비교/다운로드의 호출 주기와 기본 조회 범위는 변경하지 않는다.

## 구현·검증 범위

실제 제공된 세 HWP는 로컬에서만 검증한다. 공개 저장소에는 주보 원문/기도자 이름/드롭박스 비밀정보를 추가하지 않는다. 합성 HWP 검사로 병합 셀, 예배 구분, 모호한 표 거부를 확인한다. 서버 검사로 경로 탈출·서명 커서·읽기 전용·토큰 비노출을 확인한다. 브라우저 검사로 주보 업로드, 정확 제목 연결, 말씀 생성, 실패/새로고침/재시도, 초안 적용 후 순서 저장, PC/태블릿/모바일을 확인한다.

Dropbox 실제 계정 연결과 교회 PP6 실기는 관리자 설정 후 확인해야 한다. 파일 구성/예배 양식이 달라지면 자동 추정 대신 오류 또는 검수 항목으로 남긴다.

HWP 바이너리 라이브러리는 `scripts/hwp-vendor.mjs`를 esbuild로 bundle하여 `web-editor/hwp-binary.js`로 배포한다. 라이선스는 web-editor/vendor에 보관한다. 재생성 명령:

```
npx esbuild scripts/hwp-vendor.mjs --bundle --minify --format=iife --global-name=YebaeonHWPBinary --target=chrome80 --outfile=web-editor/hwp-binary.js
```
