# Mac ↔ Windows 개발 시행착오와 재발 방지

최종 확인: 2026-10-01 (한국 시간). 집 Windows PC, 교회 macOS High Sierra 10.13.6, ProPresenter 6을 기준으로 한다. 사용자 보고·당시 인수인계 기록·현재 코드·GitHub 검사 로그를 구분하며, 확인되지 않은 세부 원인을 확정하지 않는다.

## 앞으로 작업을 마칠 때 보고할 것

오류가 있었다면 최종 답변에 **증상/실패 단계 → 원인 → 해결 → 재검증 결과 → 현재 중단 여부와 남은 일**을 짧게 보고한다. GitHub 실패 알림이 있는 경우 실행 링크와 수정 후 성공 실행을 연결한다. 해결하지 못했으면 미해결이라고 명시한다. 아직 실행 중인 검사나 배포를 완료로 표현하지 않는다. 오류가 없으면 관련 검사·배포 상태를 간단히 표시한다.

GitHub Actions의 특정 커밋 검사 실패, 사이트 배포 실패, 사용자의 Mac 업로드 중단은 서로 다른 상태다. 검사 메일 하나만으로 현재 앱의 업로드나 최신 사이트가 중단됐다고 판단하지 않는다. 실패한 과거 실행은 후속 수정이 성공해도 실패 이력으로 남는다.

## High Sierra와 초기 앱 UI

- 당시 인수인계 기록에는 Script Editor에서 복잡한 NSView를 구성하다 AppKit 크래시가 발생했고, 복잡한 커스텀 창 대신 macOS 기본 대화상자·기본 목록창을 사용하는 구조로 전환했다고 남아 있다. 해당 크래시의 정확한 스택/API 원인은 현재 자료로 확정하지 않는다.
- 이후 Native Cocoa 앱은 High Sierra에서 컴파일·실행·비교·적용 사이클을 통과한 기록이 있다. 현재는 기존 Native v0.2 화면을 기반으로 통합한 Sync 0.4.1이다. 초기 실패한 UI 구조를 검증 없이 다시 도입하지 않는다.
- 적용 버튼의 한글 잘림과 변경 0 상태를 오류로 오인할 수 있는 표시도 기록됐다. 긴 한글 버튼, 작은 창, 스크롤, 비활성/작업 중/변경 없음/실패 상태를 각각 점검한다.
- 최신 macOS에서 10.13 대상으로 컴파일하는 CI는 실제 High Sierra의 AppKit·HTTPS·키체인·PP6 확인을 대신하지 않는다. 새 API는 availability 검사를 하고 지원 버전 밖 API를 무조건 호출하지 않는다.
- “승인되지 않은 개발자”로 앱이 열리지 않은 사용자 보고도 별도로 기록한다. CI 빌드 성공이나 ad-hoc 서명은 Apple 공증 완료를 뜻하지 않는다. 실행 차단과 앱 실행 후 크래시를 같은 문제로 묶지 않는다. 보안 설정 전체 해제를 일반 실행 절차로 만들지 않는다.
- 3천여 문서를 하나씩 체크해야 했던 UX는 실사용을 막았다. 보내기/받기 전체 선택을 추가했다. 검색된 항목 선택과 전체 방향 선택의 범위를 명시하고 충돌·제외 항목을 자동 선택하지 않는다.
- 대량 작업은 진행 수, 실패/제외 수, 취소·재시도 가능 여부와 마지막 성공 시각을 보여야 한다. 지원하지 않는 취소나 이어받기를 제공한다고 표시하지 않는다. 중단된 적용은 백업·복구 후 비교하는 절차를 따른다.
- 웹 미리보기는 PP6 화면과 다를 수 있다. 동명 미디어 자동 대체를 피하고 정확한 경로 연결, 유일한 이동 후보, 다중 후보, 누락을 구별한다. 성경 최종 서식은 추후 실기 캡처와 대조한다.

## UX/UI 변경 전후에 읽고 확인할 것

1. 이 문서와 SESSION-HANDOFF를 먼저 읽고 지원 OS·실기 확인 범위·미해결 항목을 유지한다.
2. 실제 경로를 수집하고 한글 정규화, 공백, 콜론, 따옴표, 퍼센트, 대소문자 충돌을 구분한다. 원본 이름을 보존한다.
3. 소수 파일 성공만으로 대량 작업 UX를 완료 처리하지 않는다. 전체 선택·진행/실패 표시·중단 복구 범위를 확인한다.
4. 최신 Mac 자동 검사와 교회 High Sierra 실기 검증을 나눠 보고한다. 긴 한글 문구와 변경 없음 상태를 점검한다.
5. 실패 실행은 원인·수정·성공 재검증을 연결한다. 임시 우회와 프로그램의 근본 수정, 확인된 원인과 추정을 구분한다.

## 최근 사용일과 서버 저장일 구분 (2026-10-01)

대량 최초 업로드에서 `updatedAt`은 모두 업로드 당일이 되므로 PP6 사용 시점을 나타내지 않는다. 웹 목록과 현황판에 원본 루트의 `lastDateUsed`를 별도로 표시하고 한국시간임을 안내한다. 조회 실패를 기록 없음으로 숨기지 않는다. 날짜 조회 때문에 Mac의 전체 비교 API를 느리게 만들지 않도록 별도 인증 조회와 웹의 최대 4개 병렬 읽기·버전별 캐시를 사용한다. 기존 원본과 저장 시각 불변 및 과거 버전 조회를 검사했다. 로컬 대용량 거부 시험에서 ECONNRESET 재발 1회 후 전체 23개 재실행 통과. 로컬 배포 dry-run은 npm 레지스트리 네트워크 정책에 막혀 GitHub 배포 결과로 확인한다.

- 라이브러리 정렬은 화면에 받은 첫 100개만 정렬하지 않는다. 전체 검색 결과에 서버 정렬과 안정적인 커서를 적용한다. 최근 사용일을 원본에서 매번 다시 읽지 않고 ID·버전별 색인으로 재사용한다. 최초 수집에는 진행 수를 표시하고 닫기/정렬 변경으로 후속 요청을 멈춘다. 모달이 상단 내비게이션을 가리므로 현황판처럼 필요한 이동 링크는 모달 안에도 제공한다.

## 초안·보관 정리 안전성

- 저장 버튼을 누른 순간의 수정 번호를 붙인다. 응답이 왔다는 이유로 현재 초안을 무조건 삭제하면 요청 중 추가한 편집이 사라진다. 문서를 전환한 경우에도 같은 검사를 한다. 기준 버전 번호만 아니라 기준 원문도 보존한다.
- 브라우저 저장 용량 실패를 ‘자동 저장됨’으로 표시하지 않는다. 탭별 저장 ID를 따로 만들고, 공유 브라우저의 다른 작업자 초안을 자동으로 덮어쓰지 않는다.
- Mac 백업 유지 수는 파일 수가 아닌 완료된 작업 수다. 새 작업의 문서 ID 소유권을 준비 기록부터 붙이고 완료 기록 이후에만 정리한다. 출처 불명/기존 백업과 중단 기록은 일반 완료 기록으로 세지 않는다. 경로 삭제는 descriptor 기반으로 수행하고 링크를 따라가지 않는다.
- 로컬 Miniflare의 큰 고정 길이 업로드 거부 시험은 서버가 Content-Length를 보고 먼저 응답하는 동안 클라이언트 송신이 남아 ECONNRESET가 재현됐다. 같은 25MiB+1 요청을 스트리밍 전송으로 검사하여 실제 바이트 제한과 HTTP 413을 확인한다. Node의 스트림 Request에는 duplex:'half'가 필요하다. 운영 업로드 중단 원인을 이 테스트 증상으로 단정하지 않는다.
