# 예배온 · 다음 단계 — 2026-10-01

현재 구현·검사·다운로드의 기준은 [SESSION-HANDOFF.md](SESSION-HANDOFF.md)다. 집은 Windows, 교회는 High Sierra 10.13.6 + PP6이며 소스는 로컬 GitHub 클론에서 관리한다.

## 집에서 준비한 범위

서버의 기존 플레이리스트 → 찬양/말씀 편집·저장 → Mac에서 같은 플레이리스트 동기화 흐름을 구현했다. 서버는 원본과 버전/저장자를 보관하고, 웹은 곡 추가·교체·순서 변경을 지원한다. Mac 0.4.0은 최초 등록, 연결 문서 수집, 백업·적용, 중단 후 복구를 지원한다. 문서만 바뀌어도 해당 플레이리스트의 변경으로 감지한다.

전체 서버 검사 20개와 Intel Mac 검사 256개가 통과했다. [플레이리스트 기준과 범위](PLAYLIST-WORKFLOW.md), [Mac 사용법](../mac-app/README.md).

## 다음 교회 방문

[CHURCH-TEST.md](CHURCH-TEST.md)의 실행 순서대로 새 앱 실행·입장, 실제 원본 등록, 시험 폴더에서 플레이리스트 수신, 웹 수정 후 재동기화, PP6 열기·화면 확인을 한다. 기존 앱 삭제, 폰트 재수집, 과거 Core 숫자 검사는 반복 과제가 아니다.

High Sierra의 HTTPS/키체인 연결과 실제 PP6의 파일 수용·화면은 집의 자동 검사로 확정할 수 없다. 시험 파일의 새 노드/문서 경로/순서가 PP6에서 어떻게 열리는지 확인해야 한다.

## 이후 개발 우선순위

1. 교회 실기에서 확인한 파일 형식·경로·앱 실행 문제를 먼저 수정한다.
2. **사용 미디어 업로드와 동기화:** 현재 Core로 참조·누락·위치 후보를 점검한다. 다음은 R2 원본 업로드, 필요한 파일만 수신, 중복 제거, 백업, Mac 설치와 경로 변환이다. 모호한 파일명만으로 자동 연결하지 않는다.
3. **성경 자료 서버 보관:** 원본 형식·번역본을 확인한 뒤 원본 업로드와 목록을 먼저 제공하고, 파싱·검색·슬라이드 생성은 별도로 검증한다.
4. **썸네일 정밀도:** PP6 정상 화면 자료와 웹의 글꼴·크기·줄바꿈·효과·이전 배경 유지 차이를 비교한다. 웹 근사 렌더를 PP6의 실제 렌더로 안내하지 않는다.
5. **예배별 복사와 확장 편집:** 공유 곡을 별도 버전으로 복사/연결하는 흐름, 새 플레이리스트 생성/이름 변경, 전문 Arrangement·전환·자동 실행 편집은 이후 범위다.

전체 서버 목표는 모든 `.pro6`, 성경 원본, 사용된 미디어의 보관과 편집/동기화다. 지금 구현한 것은 `.pro6`와 기존 플레이리스트이며 성경·미디어까지 완료한 것은 아니다. [서버 기획](SERVER-PLAN.md).
