# Studio 렌더링 결정과 분석 · 2026-10-02

## 사용자가 확정한 사항

- 폰트는 사용자가 교회 Mac에서 제공한 실제 폰트 파일을 서버에 탑재하여 사용한다. 외부 CDN의 동명 폰트로 대체하지 않는다. family/face/PostScript 이름과 굵기 메타데이터를 원본에서 확인한다. 브라우저에서 FontFace/@font-face로 서버 파일을 읽는 것은 이 결정과 일치한다.
- 일반 빠른 편집은 실제 서식을 반영하는 미리보기와 별도의 텍스트 입력창을 나란히 제공한다. 성경 빠른 편집과 방식을 통일한다.
- 슬라이드 목록의 빈 공간에 크기 조절 슬라이더를 배치한다. 넓은 화면에서 한 줄 4~8장, 정수 단계로 조절한다. 좁은 화면 대응은 별도 설계한다.
- 이번 요청은 결정 기록과 원인 분석/보고이다. 위 기능의 구현과 배포를 진행한 것으로 표시하지 않는다.

## 파일에 저장된 정보와 현재 지원

RVRect3D position에 글상자 위치/크기, verticalAlignment에 세로 정렬, RTF에 문단 정렬과 줄 간격이 저장될 수 있다. 현재 파서는 slleading을 20으로 나누어 추가 줄 간격으로 읽고 다시 기록한다. sl/slmult 등 다른 줄 높이 규칙은 처리하지 않는다. 현재 렌더는 기본 줄 높이를 max(size*1.2, 폰트 ascent+descent)로 근사한다. 데이터가 없다고 단정해서는 안 된다. 캡처 곡의 원본 RTF와 PP6 표시값 대조는 아직 미완료이다.

## 미리보기 현 구조

서버에서 PNG 썸네일을 생성/다운로드하는 방식이 아니다. 브라우저가 문서 XML/RTF를 해석하여 화면 근처 canvas에 직접 그린다. 목록의 내부 버퍼가 가로 400px로 고정되어 CSS로 확대/축소된다. 렌더러는 임시 canvas에 그리고 표시 canvas에 복사하며 결과 canvas를 메모리에 캐시한다. DOM 목록은 render/cards 실행 때 재생성된다. 폰트 상태 변경 이벤트도 전체 목록 갱신을 요청한다. 기존 IntersectionObserver와 결과 캐시는 이미 구현돼 있다.

병목 후보는 글자별 반복 measureText/조판, 화면 갱신 때 DOM 재생성/렌더 작업 재등록, 폰트 완료 이벤트에 따른 전체 갱신, 미디어 최초 로딩이다. 실제 기여도와 지연 시간은 성능 측정 전에는 확정할 수 없다.

## 검토할 근본 대안

공통 슬라이드 장면 모델과 조판 결과를 캐시하고, 변경된 슬라이드만 갱신하며, 화면에 보이는 목록만 유지하는 구조를 먼저 검토한다. SVG viewBox 기반으로 텍스트/도형을 벡터로 표시하는 방식은 확대 시 글자를 저해상도 비트맵으로 늘리는 문제를 피할 수 있다. 공통 조판 결과를 사용해야 하며 SVG만으로 PP6 줄바꿈/폰트/효과 차이가 해결되지는 않는다. 이미지/영상은 원본 래스터이다. Canvas와 SVG의 실제 비용은 같은 곡/4~8열 조건에서 계측 비교 후 결정한다. 무조건 해상도만 늘리거나 모든 슬라이드를 풀 해상도로 그리지 않는다.

## 원인 확정 범위

아웃라인 그리기 누락, 일반 빠른 편집 textarea 경로의 서식/세로 정렬 누락, 고정 400px 버퍼는 코드로 확인했다. 현재 캡처 곡에서 실제 선택된 폰트 face/최종 로드 파일과 줄 간격 변환은 추가 확인이 필요하다. 기능 테스트 성공은 PP6 시각적 일치 검증을 대체하지 않는다.

이번 기록은 문서 변경만이며 앱 기능 수정/배포/새 성능 계측을 수행하지 않았다.
