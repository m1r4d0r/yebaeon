# 디자인 핸드오프 적용과 정책 보정

2026-10-02. 사용자가 제공한 Claude Design 핸드오프와 Sync 0.4.2 build 7의 백업 정책을 함께 검토했다. Studio 변경은 웹 전용 브랜치에서 검증하며, 이 문서의 Sync 개선안은 새 Mac UI가 구현되었다는 뜻이 아니다.

## Studio 구현 범위

문서 목록 → 재생목록/순서, 오른쪽 슬라이드 격자, 상단 보기 전환, 하단 저장이라는 시안을 유지한다. 빠른 편집, 리플로우, 말씀 패널, 서버 미디어 서랍을 분리한다. 서버 자료만 여는 흐름으로 바꾸며 로컬 파일/폴더 업로드, 샘플 열기, ZIP/PNG 내보내기는 운영 화면에서 제거한다.

문서별 실행취소 50단계, 전체 실행취소 자료 200MiB 제한을 적용한다. 이는 서버 버전 보관 기간이나 브라우저 초안 용량을 뜻하지 않는다. IndexedDB 초안과 서버 이력은 기존 정책을 유지한다. 순서 자동 저장도 If-Match 충돌 검사를 거치며 실패 시 내 순서를 초안에 남긴다. 저장 직후 다른 작업자의 버전이 관찰되면 최신 순서를 다시 읽도록 한다.

문서의 쓰는 예배 수는 현재 서버 재생목록을 기준으로 계산한다. 같은 예배 안에 중복 참조된 문서는 한 곳으로 센다. 이름이 아닌 정규화된 전체 상대경로로 연결한다. 작업 이력의 ‘내 것’은 현재 세션의 작업자 이름 기준이며 독립된 개인 계정 인증이 아니다.

## 백업 정책 때문에 바꿔야 하는 Sync 시안

| 시안 | 적용할 수정 |
|---|---|
| Mac도 바뀜 → 확인 한 번 후 덮어쓰기 | 동시 변경 충돌은 계속 차단한다. 백업이 있다는 이유만으로 강제 덮어쓰기를 허용하지 않는다. 서버만 변경, Mac만 변경, 양쪽 변경, 판단 불가를 구분한다. |
| 작업 기록과 문서 트랜잭션을 모두 한 목록에 나열 | 작업 묶음을 한 행으로 표시하고 문서 상세를 펼친다. 재생목록 작업에 속한 문서 기록을 별도 완료 작업처럼 중복 계산하지 않는다. |
| 최근 백업 10개 | ‘완료된 받기 작업 10회’라고 표시한다. 한 작업의 파일이 많아도 1회다. 중단 기록·출처 불명 구버전 기록은 별도로 보존하고 자동 정리 대상에서 제외한다. |
| 완료 / 중단됨 두 상태 | 완료, 복구 필요, 복구 완료, 정리 실패를 구분한다. 동기화 성공과 백업 정리 실패를 한 실패 상태로 합치지 않는다. |
| 재생목록 순서 v8 | 현재 서버 버전은 선택한 예배만의 버전이 아니라 .pro6pl 파일 전체의 버전이다. ‘파일 v8’로 표시하고 어떤 예배의 변경인지 따로 설명한다. |
| 전체 필터에서 전체 선택 | 보내기/받기 방향을 먼저 선택한다. 필터·검색에 보이는 해당 방향만 선택하며 충돌·제외·일치 항목은 제외한다. 전체/충돌 보기에서는 적용 버튼을 끈다. |
| 기본 최근 변경순 | 사용자가 요청한 최근 사용일 우선 업로드를 기본으로 유지한다. Mac 수정일·서버 저장일·PP6 최근 사용일을 혼합하지 않는다. |

### 추가 개선 권고

1. **공통 연결 상태:** 마지막 비교 시각과 마지막 성공 전송 시각을 분리한다. 전송이 멈춘 것처럼 보여도 비교 중/대기/실패/완료를 판별할 수 있어야 한다.
2. **느린 첫 비교:** 한 번 만든 로컬 색인을 19개 재생목록 비교에 재사용한다. 예배마다 3천 파일 전체를 재탐색하지 않는다. 디스크 검사 → 서버 목록 → 비교 단계와 처리 개수를 표시한다.
3. **복구 범위 미리보기:** 선택한 작업의 수정 문서, 새 문서, 재생목록 노드를 보여 준다. 이후 편집된 파일은 복구가 차단된다는 현재 보호를 유지한다. 서버 복원과 Mac 작업 복구는 다른 동작으로 명명한다.
4. **진행 상태 유지:** 최대 4개 업로드 중 완료·진행·실패 수와 마지막 성공 경로를 표시한다. 재실행 시 실패 파일부터 무조건 재전송하지 않고 재비교 결과로 이미 성공한 문서를 제외한다.
5. **잠자기 방지 표시:** 전송 중에만 잠자기를 방지한다는 상태를 표시한다. 컴퓨터 종료나 네트워크 단절까지 막는다는 인상을 주지 않는다.
6. **쓰는 예배 필터:** 전체 자료는 보관하면서 이번 예배/모든 재생목록 참조 문서만 골라 먼저 업로드할 수 있게 한다. ‘순서에서 제거’와 ‘문서 삭제’를 혼동하지 않게 한다.
7. **High Sierra:** 기존 AppKit 컨트롤과 프레임 배치를 재사용한다. 880×620 최소 창, 긴 분해형 한글 이름, 작업 중 비활성 상태를 별도로 확인한다. 최신 Mac CI는 10.13 실기 결과가 아니다.

## 기본 조작 검토

- 마지막으로 선택한 문서/순서/슬라이드 영역에 Ctrl+A, 범위 선택, 방향키, Home/End/PageUp/PageDown을 적용한다.
- 글을 입력하는 동안 선택·복사·잘라내기·붙여넣기·실행취소는 브라우저의 텍스트 편집에 맡긴다. Ctrl+S는 서버 저장, Ctrl+F는 문서 검색이다.
- 한글 조합 중 키와 오른쪽 Alt/AltGraph를 전용 단축키로 처리하지 않는다. 왼쪽 Alt+R/E/B/V, Alt+Enter를 사용한다.
- 슬라이드 Enter 빠른 편집, 더블클릭 편집기, F2 이름, Delete 삭제. 순서 Delete는 참조만 제거한다.
- 우클릭 메뉴의 방향키는 뒤쪽 격자를 움직이지 않는다. Shift+F10/메뉴 키로도 연다.
- Alt+E의 Windows 브라우저 메뉴 충돌은 실제 Edge 확인이 남는다. Alt+Shift+E와 더블클릭도 제공한다.

## 아이콘 제안

해 자체를 예배의 상징으로 설명할 필요는 없다. 사용자가 좋아한 남색과 호박색 대비를 계열의 공통 요소로 남기고, 각 도구의 실제 역할을 중심에 둔다.

- 공통: 남색 #1F2B63 바탕, 호박색 #F3B640 한 부분, 부드러운 사각형, 동일한 흰 선 두께와 모서리 곡률.
- **Sync:** 서로 이어지는 두 화살표를 원형으로 배치한다. 하나는 흰색, 하나는 호박색. 작은 해·구름·기기를 추가하지 않아 16px에서도 동기화가 읽히게 한다.
- **Studio:** 살짝 겹친 두 슬라이드 사각형. 앞 슬라이드 상단 또는 옆면 한 줄만 호박색으로 강조하고 안쪽은 흰색 가사 두 줄로 표현한다. 재생 삼각형은 실시간 송출 앱으로 오해할 수 있어 제외한다.
- 공통 브랜드 인상은 바탕색·강조색·선의 형태로 연결한다. 두 아이콘을 똑같이 만들거나 십자가를 억지로 끼워 넣지 않는다.

아이콘은 이번 운영 화면에서 교체하지 않는다. 먼저 이 역할 구분 방향으로 비교 시안을 확정한 뒤 웹 favicon과 Mac .icns를 각각 제작한다.
