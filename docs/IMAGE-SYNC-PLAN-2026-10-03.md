# 이미지 동기화와 현장 전환 준비

2026-10-03 사용자 최신 결정. [이전 생명주기 인계](SYNC-LIFECYCLE-CONTRACT-HANDOFF-2026-10-03.md)의 미디어 범위보다 이 문서를 우선한다.

## 확정 범위

- **전체 문서 라이브러리가 참조하는 이미지**를 서버에 올린다. 현재 재생목록의 문서로 한정하지 않는다. 악보 PPT에서 가져온 슬라이드 이미지와 배경을 포함한다.
- 동영상은 서버에 올리지 않는다. 최신 승인에 따라 **가사찬양 문서의 MOV 참조만 제거**했다(115개 문서·887개 참조, 가사/슬라이드/기타 미디어 보존). 다른 카테고리와 MP4는 유지한다. 영상 바이트 부재는 이미지 전송 실패가 아니며, 영상이 있는 예배에는 로컬 확인이 필요하다고 표시한다. MOV 파일 자체는 삭제하지 않았다.
- 파일 내용 SHA-256으로 중복 저장을 막는다. 다른 이름의 같은 바이트는 하나, 같은 이름의 다른 바이트는 별개다. 시각적 유사도·재압축으로 합치지 않는다.
- 미디어 버전 이력은 만들지 않는다. 이미지 교체는 다른 내용 식별자를 참조하며, 다른 문서·보관본에서 쓰는 기존 바이트는 유지한다.
- 재사용할 이미지는 **서버 보호 표시**를 기본으로 한다. Mac 폴더 이동을 요구하지 않는다. 보호는 동일 내용 식별자에 한 번 적용한다.
- 전체 문서를 웹에서 열 수 있어야 하므로 **재생목록 미사용만으로 이미지를 정리하지 않는다.** 현재 문서, 보존 중인 문서 버전·보관본·복구본, 진행 중 전송·복원의 참조가 모두 없고 보호도 없는 것만 후보가 된다. 참조가 불완전하면 정리를 보류한다.
- 실제 교회 문서 교체·보관 7/삭제 5 실행은 교회에서 이어간다. 이 PC에서는 운영 자료를 바꾸지 않는다.

## 지금 구현하는 준비 패치와 미구현 범위

Sync 0.6.4/build17 후보는 **전환 사전 확인과 이미지 전송 대상 조사**다. 자동 송수신 완성판으로 안내하지 않는다.

1. 미디어 탭의 ‘이미지 전송 대상 확인’: 전체 문서를 읽고 실제 참조 이미지의 고유 수·중복 용량·누락 문서/슬라이드·제외 영상을 표시한다. 파일 전체를 메모리에 올리지 않고 작은 묶음으로 해시한다. 명시적 실행 때만 조사하며 시작·대기 폴링을 추가하지 않는다.
2. 원래 경로가 없는 이미지는 같은 이름 하나가 발견돼도 자동 확정하지 않는다. 기존 ‘이동한 파일 찾기’에서 후보를 검토한다. 원본 이름과 리터럴 `%3A`, file URL의 디코딩 경계를 구분한다.
3. 읽기 중 변경·문서 목록 변경·지원 범위 밖 참조가 있으면 전체 준비 완료로 표시하지 않는다. PP6의 RVVideoElement라도 이미지 확장자라면 이미지 대상으로 조사하고 알 수 없는 형식은 확인 필요로 남긴다. 보고서의 `serverVerified:false`는 서버 존재 확인/업로드를 하지 않았다는 뜻이다.
4. 일반 전체 재생목록 PUT이 기존 노드를 빠뜨리면 HTTP409로 거부한다. 웹에서 만든 관리 노드뿐 아니라 과거 등록 노드도 포함한다. **명시적 보관·삭제 API는 그대로 허용**한다.
5. ‘Mac 기준 서버 맞추기’는 서버의 보관/삭제 노드가 로컬 전송본에 남아 있는지 문서 업로드 전에 확인한다. 준비 후 서버 상태가 바뀌면 다시 준비한다. 충돌 응답은 서버의 구체적인 해결 안내를 표시한다.

아직 구현하지 않은 것: 이미지 R2 업로드·서버 존재 일괄 조회·Mac 다운로드/설치·문서 경로 연결·서버 보호 표시 UI·미참조 후보/삭제·제외 문서 205개의 서버 은퇴 기능. 준비 보고서를 이 기능들의 완료로 해석하지 않는다.

## 실제 이미지 송수신 구현 순서

### 1. 서버의 이미지 원본과 참조

- 원본 테이블: 내용 hash, 크기, 검증된 종류, 저장키, 보호 여부/revision. 파일명은 별도 표시 메타다. 동일 hash 존재 조회는 대상 hash만 묶어서 수행한다.
- 참조 테이블: documentId/version/hash, 이미지 요소 위치/원래 source, imageHash. 문서 CAS에 연결하여 늦은 저장이 새 문서의 참조를 덮지 못하게 한다. 문서 복제는 바이트를 복제하지 않고 참조를 재사용한다.
- 업로드는 임시 전송 → 전체 크기·SHA 검증 → 사용할 수 있는 원본으로 게시 → 문서 참조 연결 순서다. 중단 파일을 완성 원본으로 공개하지 않는다. 응답 유실 후 같은 작업을 다시 해도 같은 결과를 찾는다.
- 영상용 대용량 큐는 이번 범위에서 제외한다. 이미지 최대 크기는 실제 이미지 조사 결과로 정한다. 큰 이미지 지원에 분할 전송이 필요하면 [R2 multipart](https://developers.cloudflare.com/r2/api/workers/workers-multipart-usage/)와 [stream digest](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/)를 사용하고, 원본 전체를 Worker 메모리에 모으지 않는다.
- 오래된 문서 원본을 서버가 열어서 참조를 보충하는 작업은 checkpoint가 있는 일회성 이관이다. 검색/목록마다 전체 원본을 읽지 않는다.

### 2. Mac 전송과 Studio 이미지 추가

- 최초 이미지 업로드: 전체 문서의 고유 이미지 조사 → 없는 hash만 업로드 → 참조 검증. 이후에는 변경 문서와 해당 참조를 갱신한다. 전체 이미지 폴더를 무조건 전송하지 않는다.
- Studio: 새 이미지를 먼저 검증·저장하고 문서에 연결한다. 이미지 업로드 성공/문서 저장 실패를 분리하며, 재시도는 기존 이미지를 재사용한다. 미저장 이미지 원본이 초안에 보존되는지도 별도로 검증한다.
- 예배 받기: 선택 예배의 필요한 이미지 목록 → 설정한 Mac 수신 폴더의 검증된 원본 재사용/누락 다운로드 → 임시 파일의 SHA 검증 → 이름 충돌 없는 배치 → 문서의 참조 경로 연결 → 문서·순서 적용.
- 이미지 경로를 바꾸면 문서 원본 SHA가 달라진다. **서버 원본 hash와 설치한 Mac 문서 hash를 별도 기준**으로 기록한다. 전송 검증 SHA를 버리거나 본문만 비교해서 해결하지 않는다. 원본/로컬 hash와 이미지 매핑을 같은 복구 기록에 포함한다.
- 이미지 실패 시 해당 예배를 준비 완료로 표시하지 않는다. 이미 받은 이미지와 나중 수정한 파일은 자동 삭제하지 않는다. 영상은 ‘업로드 제외·Mac 원본 필요’로 별도 안내한다.

### 3. 보호 표시와 정리

- 이미지 행에서 보호 표시를 켜거나 끈다. 이름이 다른 동일 바이트에도 적용한다. 보호 수정은 revision 검사로 다른 작업의 결정을 덮지 않는다.
- 처음에는 후보와 이유를 보여주는 수동 정리로 시작한다. 유예기간·복구 방식이 정해지기 전에는 자동 예약 삭제를 만들지 않는다.
- 단순 참조 개수 감소 직후 삭제하지 않는다. 현재·보관·이력·진행 중 작업을 다시 확인하고, 후보 선정 뒤 재참조/보호가 생기면 제거하지 않는다.
- 서버 정리는 Mac 원본 삭제와 별개다. 문서 이관 중에는 정리 후보를 만들지 않는다. 전체 참조 이관 완료가 정리 기능의 선행 조건이다.

## 비용과 검증 범위

이번 준비 패치의 이미지 조사는 로컬 파일 읽기만 한다. 대기·최초 진입·검색·문서 열기/저장·일반 비교/받기의 새 D1 호출은 없다. 일반 전체 PUT은 이미 읽은 파일 catalog를 확인하며 쿼리를 추가하지 않는다. 누락 요청은 기존 관리행 조회 전에 중단해 그 조회와 저장을 생략한다.

명시적 서버 맞추기 준비는 해당 재생목록의 structure 조회 1회를 추가한다. 적용 전에는 기존 단일 파일 GET을 structure GET으로 바꾸므로 HTTP 요청 횟수는 같고 해당 library의 보관/삭제행 조회가 추가된다. 현재 기준으로 관리행은 해당 파일의 수에 비례한다. 전체 라이브러리나 미디어의 집계 쿼리는 없다. 실제 운영 rows_read/rows_written은 미측정이다.

송수신 단계에서는 원본 이미지 I개, 고유 hash U개, 서버에 없는 이미지 M개라면 존재 확인은 U개 대상, 업로드 바이트는 M개 합계다. 이는 요청/자료 범위 추산이며 D1 행 읽기 실측이 아니다. 이후에도 대기 폴링 0, 저장 시 해당 참조만 갱신한다.

자동 검사는 기존 묶음에서 다음 위험을 검증한다: 관리 전 노드 누락 거절과 명시적 삭제 허용, 보관 노드가 있는 서버 맞추기의 사전 중단, 같은 내용/다른 이름과 같은 이름/다른 내용, URL/원래 경로 구별, 읽는 중 변경, 영상 제외, 지원하지 않는 참조의 미완료 표시. 검사 개수를 목표로 삼지 않는다. 교회 High Sierra/PP6 및 실제 이미지 조사·송수신은 별도다.

현장 전환 순서는 [교회 마이그레이션 안내](CHURCH-MIGRATION-2026-10-03.md)를 따른다.
