# 크로스 플랫폼 규칙

집 Windows PC, 교회 macOS High Sierra 10.13.6, ProPresenter 6(PP6) 사이에서 경로·앱 UI·서버·검사를 다룰 때 지키는 원칙. 경로·동기화·High Sierra 호환성·UX/UI를 바꾸기 전에 읽는다. D1 비용은 [d1-cost.md](d1-cost.md)를 따른다.

## 1. 경로와 한글 파일명

### 이름 보존

- 사용자 원본 파일명과 경로는 바꾸지 않는다. NFC/NFD 정규화는 검색·비교 키에만 쓰고 디스크 경로와 표시 이름은 그대로 둔다.
- 처음 경로는 실제 파일 선택이나 디렉터리 열거로 확보하고 이름을 다시 조립하지 않는다.
- 끝 공백은 이름의 일부다. `기본 .pro6pl`의 확장자 앞 공백, `__Documents/기본 /`의 폴더 끝 공백이 실제로 있으므로 원본 경로에 `trim()`을 적용하지 않는다.
- Mac에서 유효해도 Windows에서 적용하기 어려운 이름(콜론 등)은 수신 때 명시적으로 판정한다. 조용히 덮어쓰거나 이름을 바꾸지 않고, 제외 목록·원인·수신 가능 여부를 표시한 채 나머지 점검을 계속한다.
- 서버 저장 키는 문서 ID이고 원본 경로는 메타데이터로 분리한다.

### 경로와 URL

- Mac의 사용자 지정 절대경로와 서버 sourceRoot(`~/Documents/ProPresenter6` 기준)는 같은 문자열이라고 가정하지 않는다. 업로드 참조를 변환하고 로컬 원본은 보존하며, 변환 뒤 서버 plan이 ready인지 확인한다.
- 경로 문자열과 URL 문자열을 섞지 않는다. file URL은 `NSURL fileURLWithPath:`로 만들고 직접 조립하지 않으며, 인코딩·디코딩은 경계에서 한 번만 한다. 이중 디코딩하면 공백·콜론·리터럴 `%3A`의 의미가 달라진다. raw 경로는 URL이 아니므로 `file:` URL만 한 번 디코딩하고 raw 경로의 `%`는 그대로 둔다.
- 셸 인자 분리, 앱의 경로 검증, URL 인코딩, Windows 파일명 제한은 별개 문제다. 문자열을 감싸는 것으로 특수 파일명이 해결된다고 보지 않으며, 셸 인자는 올바르게 인용하고 문자열 명령 조합을 피한다. 리터럴 `%3A`, 콜론, 공백, 따옴표, NFC/NFD는 실제 HTTP·플레이리스트 XML 왕복으로 확인한다.
- 배포 스크립트의 Python 버전을 명시한다. 구형 Mac에 Python 3가 있다고 가정하지 않고, Python 2 지원 시 입력 경계에서 bytes/Unicode 변환을 통일한다.
- ZIP 안의 UTF-8 이름을 CP437로 읽으면 한글이 깨진다. 엄격한 UTF-8 해석으로 복구되는 경우만 교정해 NFC로 표시하고, 이미 올바른 이름·원본 XML·UUID는 바꾸지 않는다. ZIP 항목은 열거해 확인하고(`metadata_encoding='utf-8'`) 배포 ZIP 바이트를 다시 쓰지 않는다.

### 대소문자와 링크

- 로컬과 서버 경로가 대소문자만 달라 충돌하는 경우(case alias)를 검사한다. 열거가 로컬 파일을 빠뜨리면 검사가 거짓 통과하므로 NFC/NFD 파일과 미등록 로컬 파일 검색을 함께 검사한다.
- 파일 열거와 삭제는 디렉터리 descriptor 기반(`openat`/`readdir`/`fstatat`)으로 하고 심볼릭 링크를 따라가지 않는다.
- 경로 검증은 절대 경로·빈 요소·`.`/`..` 요소를 어휘적으로 검사하고 모든 조상의 `lstat` 링크 거부를 유지한다. `stringByStandardizingPath`는 `/private/var`를 `/var`로 줄여 오탐하므로 쓰지 않는다. 테스트 임시 루트만 POSIX realpath로 정한다.

(근거: 파일명·검색·전송, Sync 0.6.2 · 실제 경로와 서버 기준/명시적 해결)

## 2. High Sierra 10.13 제약

기준은 macOS 10.13.6과 Apple LLVM 10(Command Line Tools)이다.

### 환경

- OS·Xcode 업그레이드를 먼저 요구하지 않고 명령과 터미널 출력으로 오류를 확인한다.
- 최신 macOS 러너의 10.13 대상 컴파일은 실제 High Sierra의 AppKit·HTTPS·키체인·PP6 동작을 대신하지 않는다. 실기 전에는 Apple LLVM 10 컴파일과 GUI 성공을 미확인으로 둔다.
- 새 API는 availability 검사를 거쳐 호출한다. 지원 버전 밖 API를 무조건 호출하지 않는다.
- 시스템 SQLite는 3.19다. `INSERT … ON CONFLICT`(UPSERT)가 없으므로 `INSERT OR REPLACE`를 쓴다.
- CI 빌드 성공이나 ad-hoc 서명은 Apple 공증이 아니다. "승인되지 않은 개발자" 실행 차단과 실행 후 크래시는 별개 문제다. 보안 설정 전체 해제를 일반 실행 절차로 만들지 않는다.

### UI 구조

- UI는 기본 AppKit 컨트롤과 macOS 기본 대화상자·목록창을 기반으로 한다. 복잡한 커스텀 NSView 구성은 AppKit 크래시를 낸 적이 있다(스택·API 원인은 미확정). 실기 검증 없이 그 구조를 다시 들이지 않는다.
- 표는 표 객체를 컨트롤러에 연결한 뒤 `reload`하고 실제 셀 문자열을 검사한다. 자동 열 너비에 맡기지 않고 실제 scroll content 폭과 열 간격으로 계산한다. 셀 안의 selectable 텍스트는 행 선택을 가로채므로 선택 불가로 둔다.
- 서버 값이 없는 행의 `remote`는 `NSNull`이다. 정렬에 `remote.updatedAt` KVC를 직접 쓰지 않고 값의 종류와 누락을 먼저 판정한다.
- Enter를 받는 기본 버튼은 한 곳이다. 숨겨진 탭에 기본 버튼을 남기지 않는다.
- 긴 한글 버튼은 높이를 늘리지 않고 충분한 고정 폭과 굵기로 표시한다. 패널 전체를 비례 축소해 글씨를 자르지 않는다. 필터가 최소 창에 안 들어가면 두 줄로 배치한다.

### Objective-C 구현

- 갱신 메서드 끝에서 자기 자신을 무조건 호출하지 않는다(무한 재귀 segfault). 재진입 가드로 덮지 않고 상태 갱신을 이벤트 지점에서 호출한다.
- 삼항식에 `NSDictionary` 값이 섞이면 `id`로 추론되어 `.pathExtension` 같은 속성을 컴파일할 수 없다. `NSString` 지역변수로 자료형을 명시한다.
- 폴더 잠금은 명시적 `close`로 해제한 뒤 다시 열고 종료한 엔진 재사용을 막는다. 잠금 자체는 제거하지 않는다.
- 대량 비교는 문서마다 임시 메모리를 정리한다. 바깥 autoreleasepool 하나로는 작업 종료까지 남는다.

(근거: High Sierra와 초기 앱 UI, Sync 상단 비교·하단 결정 배치와 일시중단)

## 3. PP6 동작과 문서 형식

### 재생목록과 사용일

- `.pro6pl` 전체 파일 버전은 전송·백업용이며 웹의 예배별 편집 기준과 구분한다. 새 재생목록은 실제 원본의 `type=3` 노드 구조를 쓴다.
- 최근 사용일은 원본 루트의 `lastDateUsed`(한국시간)다. 서버의 `updatedAt`은 업로드·저장 시각이라 PP6 사용 시점이 아니다. 조회 실패를 "기록 없음"으로 숨기지 않는다.

### XML과 서식

- 지원하지 않는 요소는 바이트를 보존한다. 원본 XML에 임의 속성을 넣지 않는다.
- 요소의 XML 위치만으로 용도를 판단하지 않는다. 배경 cue에도 특송·엔딩 영상이 있고 `RVVideoElement`에 정지 이미지가 있을 수 있다. 알려진 확장자를 먼저 분류하고 불명확한 것은 미완료로 남긴다.
- 배경 없음은 배경 cue뿐 아니라 `drawingBackgroundColor`도 `false`로 저장한다. 아니면 투명 PNG 뒤에 흰 바탕이 남는다.
- `drawingStroke=false`만으로 글자 아웃라인 없음이라 판단하지 않는다. Cocoa RTF의 `strokewidth`/`strokec`와 XML 도형 stroke는 별개다. 지원하는 효과는 RTF 작성기에도 넣어 편집 후 유실을 막는다.
- 원본 PostScript 이름이 Medium이어도 b trait가 있으면 실제 Bold face를 먼저 찾고, 가짜 Bold나 중복 강조를 피한다. 원본 폰트 내부의 weight를 존중하며(아리따부리 HairLine300/Light400처럼 이름별 예상과 다른 원본이 있다) 동명 CDN 글꼴로 바꾸지 않는다.
- `lineSpacing` 음수를 CSS `line-height`처럼 빼면 PP6 출력과 달라진다. 원본 값은 보존하되 PP6 기본 line-fragment 하한을 유지하고, 원본 글꼴의 `hhea` 메트릭으로 OS별 Canvas 차이를 줄인다. 마지막 줄 뒤의 leading도 높이에 포함한다.

### 미리보기와 미디어

- 웹 미리보기는 PP6 화면과 다를 수 있다. PP6 native 렌더 완료로 표현하지 않고 성경 최종 서식은 실기 캡처와 대조한다.
- 미디어는 정확한 경로 연결, 유일한 이동 후보, 다중 후보, 누락을 구별하고 동명 미디어를 자동 대체하지 않는다. 원래 경로의 `%`를 무조건 디코딩하지 않는다.

(근거: 최근 사용일과 서버 저장일 구분, PP6 글자 조판과 브라우저 초안, 2026-10-03 악보 배경 없음)

## 4. 서버·Worker

### 쓰기 보호

- 전체 파일 쓰기에는 파일 CAS를 둔다. 노드 해시 검사 뒤에도 CAS가 필요하며, 다른 예배의 선행 저장일 때만 재시도한다. 같은 예배의 충돌은 자동으로 덮어쓰지 않는다.
- 생성·보관·복원과 파일 CAS는 같은 DB batch에 기록한다. 구버전 전체 PUT이 관리 노드를 잃거나 되살리지 못하게 막는다.
- 후속 색인 쓰기는 revision 숫자만으로 보호하지 않고, 같은 트랜잭션에서 만든 고유 `write_id`로 실제 승자의 쓰기만 잇는다. 늦게 끝난 색인이 꺼졌거나 버전이 바뀐 문서에 본문을 다시 넣지 않게 한다.
- 이미지 참조 등록은 문서 저장과 같은 D1 batch 및 `write_id`/CAS 조건에 넣는다. 별도 요청이면 실패 때 동기화가 끊긴다.
- 백업 보관 여부와 CAS 버전 번호는 분리한다. 이력 보관을 꺼도 CAS는 유지한다.

### 오류와 재시도

- 트랜잭션 실패는 503 계약을 따른다. 비동기 라우트는 `await`해서 HTTP 오류가 JSON으로 반환되게 한다.
- 일반 폼의 non-CORS POST는 `Referrer-Policy: no-referrer` 아래에서 `Origin: null`이 될 수 있어 same-origin 검사와 충돌한다. 폼을 내는 초기 HTML 응답에만 `same-origin`을 두고 세션·교차 출처 검사는 유지한다.
- 큰 고정 길이 업로드는 서버가 `Content-Length`를 보고 먼저 거부하는 동안 클라이언트 송신이 남아 연결이 끊길 수 있다. 크기 한도는 스트리밍 전송으로 검사해 실제 바이트 제한과 413을 확인한다(Node 스트림 `Request`에는 `duplex: 'half'` 필요).
- 신규 문서 POST와 순서 저장은 하나의 원자적 트랜잭션이 아니다. 준비 XML과 경로를 먼저 브라우저 IndexedDB에 보존하고 같은 이름·내용으로 재시도하며 이미 생성된 문서는 재사용한다. 같은 경로에 다른 내용이 있으면(`path_exists` 409) 덮어쓰지 않고 새 이름을 정해 저장하게 한다.

### 상태와 인덱스

- 상태 보고 실패는 파일 송수신 실패로 처리하지 않고 기존 확인 시각을 최신으로 바꾸지 않는다. 브라우저 저장 성공을 Mac 적용 성공으로 표현하지 않는다.
- 순서가 일치해도 연결 문서의 원본·관측이 없거나 unknown이면 정상(초록)으로 올리지 않고, 조회 실패는 회색으로 둔다.
- 전체 파일 인덱스는 완전한 메타데이터 스캔을 한 트랜잭션으로 커밋한다. 중간 오류를 파일 삭제로 해석하지 않고 서버 원본·참조·버전은 지우지 않으며, 미업로드 항목을 가짜 v1 문서로 만들지 않는다.
- 전송 완료 뒤에는 전체 원본을 다시 읽지 않고 저장 기준을 반영한 뒤 busy를 해제한다. 일시중단은 송신 HTTP를 끊지 않고 진행 중 묶음의 완료 기록까지 마친 뒤 멈추며, 재개 뒤에도 해시·서버 버전 검사를 생략하지 않는다.
- 브라우저 초안은 저장 버튼을 누른 순간의 수정 번호를 붙이고, 응답이 왔다는 이유만으로 현재 초안을 지우지 않는다. 저장소 용량 실패를 "자동 저장됨"으로 표시하지 않는다.

(근거: 예배별 충돌 및 상태 보고, 초안·보관 정리 안전성, 전송 완료와 후처리·전체 파일 인덱스)

## 5. 검사와 CI

### Mac 검사

- Mac CI는 최신 Intel macOS 러너에서 10.13을 대상으로 빌드한다. 통과해도 High Sierra 실기 검증이 아니므로 보고에서 둘을 나눈다.
- 로컬 JS/Worker·정적 검사를 먼저 마치고, Mac 네이티브 검사는 변경을 묶은 출시 후보에서만 돌린다. 같은 소스의 반복 실행, 문서 전용 변경, 캡처만을 위한 재실행은 하지 않고 성공 실행의 산출물을 재사용한다.
- 실패는 제품 오류, 시험 구성 오류, 환경 제한으로 구분한다. 시험 기대를 고칠 때는 제품 계약을 확인하고 검증기를 완화하지 않는다.
- 상태 분류와 화면 표시만 검사하지 않고 실제 사용자 동작(전체 선택 클릭, 행 선택 후 충돌 해결 버튼)까지 확인하며, 캡처는 실제 창을 직접 찍는다.

### 합성 자료와 교회 원본

- 검사는 합성 자료와 로컬 Worker만 쓰고 교회 PP6를 종료시키지 않는다. 교회 원본 문서, 진단 결과, 인증 정보를 공개 저장소에 커밋하지 않는다. 운영 서버·운영 D1에 시험이나 부하 검사를 하지 않는다.
- 격리 GUI 검사(`YB_TESTING`)는 임시 경로를 쓰고 전송과 키체인 접근을 호출 지점에서 거절하며, 이 차단 자체도 회귀 검사에 넣는다. 운영 빌드에는 이 차단이 없다.
- 읽기 전용 진단은 PP6와 Sync를 종료한 뒤 예배 외 시간에 실행한다. 원본·기준 쓰기, 서버 요청, 키체인 조회를 하지 않고 심볼릭 링크와 수집 중 변경은 거절하며, 자체 검사는 임시 합성 원본에만 쓰고 실제 자료 수집보다 먼저 실행한다.
- 진단은 적용용 백업이나 원자적 스냅샷이 아니다. 덮어쓰기 직전에는 별도 백업과 해시·CAS 재검증이 필요하다. 보관·삭제 대상은 사용자가 고르며 이름·사용일로 자동 선정하지 않는다.

### 브라우저 검사와 상태 구분

- 로컬에서 브라우저를 받지 못하면(0바이트, 손상 ZIP) CI의 브라우저로 검증한다. 이 검사는 교회 High Sierra, PP6 실기, Windows의 OS 예약 단축키, 실제 휴대폰 키보드·safe-area 확인을 대신하지 않는다. 합성 모사 검사와 실제 브라우저 검증을 구분한다.
- 검사 실패, 배포 실패, 교회 Mac의 실제 업로드 중단은 서로 다른 상태다. 검사 통과는 운영 배포가 아니고, 배포 확인 요청이 막힌 것(403 등)과 배포 실패도 다르다.
- 확인된 원인과 추정을 구분하고, 원인 미확정인 연결 오류(`ECONNRESET` 등)를 다른 실패와 묶지 않는다. 실행 중인 검사를 완료로 표현하지 않고 미해결은 미해결로 명시한다.
