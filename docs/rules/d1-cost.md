# D1 조회량과 운영 비용

D1 읽기·쓰기량과 검색·색인 설계의 원칙. 기능을 추가하거나 고칠 때마다 적용한다.

## 목표

- 소수 사용자의 예배 준비 작업을 무료 한도 안에서 지속 운영한다.
- 한시적 개발용 결제를 상시 유료 운영 승인으로 해석하지 않는다.
- 비용을 크게 늘리는 폴링, 예약 작업, 전체 스캔, 일괄 쓰기, 새 유료 의존성은 구현 전에 영향과 대안을 사용자에게 설명한다.

## 변경 검토

- 모든 기능 추가·수정에서 D1 읽기·쓰기 행 수와 반복 호출에 미치는 영향을 검토한다. 화면 변경도 연결된 API 호출까지 확인한다.
- 요청 횟수·반환 건수와 실제 rows_read·rows_written을 구별한다.
- 대기 상태, 최초 진입, 검색 1회, 문서 열기·저장, 재생목록 저장, Sync 비교·다운로드에 대해 변경 전후의 조회 범위, 호출 빈도, 예상 비용을 설명한다.
- 추산에는 데이터 규모, 작업 횟수, 전제를 밝히고 실측과 구별한다.
- 쿼리는 필요에 따라 EXPLAIN QUERY PLAN과 D1 meta.rows_read·rows_written으로 확인한다. 운영 DB에 불필요한 부하 테스트를 하지 않는다.
- 코드 변경 보고에는 DB 비용 영향(증가·감소·변화 없음과 근거), 확인한 범위, 남은 실측을 넣는다.

## 검색

- 최근 사용일은 원본 파일의 lastDateUsed이며 검색 결과 정렬에 쓴다.
- 본문 글자 포함 검색과 최근 사용일 정렬을 유지한다. 비용 절감을 이유로 본문 검색을 제목·접두어·단어 검색으로 줄이거나 짧은 한글 검색어를 누락시키지 않는다.
- Studio 최초 문서 영역은 "검색어를 입력해주세요"로 두고, 빈 검색어로 전체 문서를 조회하지 않는다. 검색 결과만 최근 사용일순으로 표시한다.
- 입력 중 불필요한 요청, 저장 후 전체 재조회, 전체 동기화 상태 조회를 줄이고 화면의 대상만 조회한다. 필요한 재생목록은 별도로 불러올 수 있다.

## 색인과 캐시

- 사용일과 검색용 본문은 업로드·변경 시 해당 파일만 갱신하는 것을 우선한다.
- 과거 누락분 보충은 유한한 작업으로 실행하고 완료하면 멈춘다.
- 일반 목록·검색 요청에 전체 색인 진행률 집계나 누락 색인 작업을 붙이지 않는다.
- 색인·캐시·검색 파일의 전면 재생성을 요청마다 실행하지 않는다. 버전·변경분을 기준으로 갱신하고 실패 재시도에는 상한을 둔다.

## 최적화 기준

- 주 작업인 "Studio 문서 검색·편집 → 재생목록 저장 → Sync에서 해당 재생목록과 필요한 문서 받기"를 기준으로 최적화한다.
- 변경되지 않은 파일과 이미 받은 검색 결과를 재사용하되 버전 확인과 충돌 보호는 유지한다.
- 전체 비교와 선택 예배 다운로드의 비용을 구분한다.

## 검색 구조 대안

- 정렬용 DB 인덱스, 부분 문자열 검색용 인덱스, R2 검색용 파일·브라우저 검색을 비교한다.
- 읽기 절감뿐 아니라 최초 다운로드 용량, 브라우저 메모리, 갱신 지연, 쓰기량, 저장량, 인증을 함께 평가한다.
- 검색 파일을 도입하면 본문 자료의 접근 보호를 유지한다.
