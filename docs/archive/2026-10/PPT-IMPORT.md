# PPT 추가

상단 **PPT 추가**에서 PPT/PPTX 한 파일을 드롭하거나 선택한다. 브라우저에서 변환하며 PowerPoint 원본은 서버/외부 변환 서비스로 보내지 않는다. 파일당 40MB·120장, 압축 해제 총량 160MB, 변환 이미지 총량 180MB 제한이다. 변환기 약 1.9MB는 파일을 선택할 때만 불러온다.

## 사용자 흐름

1. 설교·행사는 **슬라이드 전체 이미지**, 악보는 **배경 분리**를 선택한다.
2. 가져올 장을 체크하고, 악보는 각 장에서 사용할 그림을 선택한다. 기본값은 큰 투명 이미지 우선이다. 현재는 장당 악보 그림 하나이며 여러 조각/그룹의 악보는 PowerPoint에서 하나의 그림으로 준비한다.
3. 악보의 첫 번째 선택 장은 제목을 유지한다. 이후 장은 그림 상단 16.7%를 제외한다. 숫자로 조절할 수 있다. 원본 좌표와 음표 크기를 유지하며 잘린 부분은 투명하다. 하단 이동용 도형과 다른 텍스트 도형을 가져오지 않는다. 실제 슬라이드 1·5·9·11을 삭제하는 기능이 아니다.
4. 원본 배경/배경 없음(투명)/단색/새 사진 중 선택 후 **변환 미리보기**. 썸네일을 누르면 확대된다. 변환 설정을 바꾸면 검수 체크가 해제되므로 다시 미리보기한다.
5. 검수 확인 후 **문서 추가**. 일반은 특별순서, 악보는 악보찬양 카테고리다. 같은 이름의 기존 문서는 덮어쓰지 않는다. 이름 충돌(409)이면 복구 영역의 **새 문서 이름 → 이 이름으로 저장**을 사용한다. 기본 제안은 기존 이름 뒤 `(PPT)`이며 원하는 이름으로 수정할 수 있다. 재변환 없이 준비한 이미지·검수 결과를 유지한다. 선택한 재생목록 하단 추가는 초안이며 기존 **변경사항 저장**으로 확정한다. 원래 순서를 교체하지 않는다.
6. 가져온 악보를 열고 PPT 추가 창의 **현재 열려 있는 악보 문서의 배경 바꾸기**에서 전체 배경을 교체한다. 악보 PNG는 그대로 유지한다. 이후 변경사항 저장이 필요하다.

## 지원 경계

- PPTX는 브라우저 OOXML 렌더러로 정지 화면을 생성한다. PPT는 바이너리 구조/그림/텍스트/좌표를 읽어 정지 화면을 생성한다. PowerPoint와 동일한 렌더링 엔진이 아니다.
- 원본 폰트가 변환 컴퓨터에 없으면 **이미지로 만들기 전에** 대체 폰트가 쓰일 수 있다. 이미지화가 원래 렌더링 문제까지 해결하지는 않는다. 저장된 PNG 이후에는 보는 기기의 폰트에 영향받지 않는다.
- PPT 마스터 장식·특수 도형·표, PPTX 일부 벡터/SmartArt/효과, 애니메이션·영상은 완전 재현을 보장하지 않는다. 미리보기와 원본을 대조한다. 일반 설교/행사 실제 파일은 아직 사용자 피드백이 필요하다.
- 악보와 사진이 이미 한 그림으로 합쳐져 있으면 사진을 복원해서 분리하지 않는다. 선택 이미지가 불투명하면 경고한다. AI 배경 제거/OCR을 사용하지 않는다.
- 사용자 제공 PPT 12장과 LibreOffice로 변환한 동일 자료 PPTX 12장 모두 투명 그림·원본 배경 분리 및 제목 크롭을 로컬 검증했다. 원본·추출물·실제 교회 캡처는 Git에 커밋하지 않는다. 교회 High Sierra/PP6 실기 재생은 별도다.

## 저장·복구·동기화

PNG의 SHA-256을 기준으로 기존 이미지 API에 등록한다. 저장 전 hash를 80개씩 조회하여 이미 전송한 이미지는 재전송하지 않는다. 경로는 `file:///YebaeOn-Media/<sha256>.png`다. 악보 PNG는 displayElements, 배경 PNG는 backgroundMediaCue에 넣어 분리한다.

문서와 미디어 참조는 같은 D1 batch/CAS 조건으로 커밋한다. 이미지 업로드를 먼저 확인하며 없는 이미지의 문서는 저장하지 않는다. 복제/배경 변경/장 재배열 때도 저장할 XML에서 현재 참조를 생성한다. Sync의 슬라이드 번호는 **1부터** 시작한다. 기존 Mac 문서의 수동 참조 등록 방식은 유지한다.

서버 이미지 내용 조회는 기존 Studio 세션을 요구한다. 브라우저 이미지 로딩은 hash별로 재사용한다. 가져온 문서의 준비 XML·PNG를 IndexedDB에 작업자 이름별로 보존하고 실패/새로고침 뒤 같은 경로·같은 내용으로 재시도한다. 저장된 이미지와 문서는 자동 롤백되지 않으며 준비본 버리기는 브라우저 준비본만 지운다. 브라우저 저장소가 지워지면 이 복구본도 사라진다.

## 비용

- 대기/최초 진입/모달 열기/변환/크롭: 새 D1 요청 0, 폴링/예약 작업 없음. 변환은 로컬 CPU·메모리를 사용한다.
- 가져오기 한 번: 고유 이미지 N개를 80개 단위로 존재 조회, 없는 이미지만 N 이하 PUT, 문서 POST 한 번. 슬라이드 S개이면 일반 최대 S개, 분리 악보 최대 2S개이며 같은 배경/같은 악보는 hash로 재사용한다. R2에 PNG 용량이 추가된다.
- 문서 저장: 가져온 경로가 있을 때만 해당 hash의 PK 조회와 해당 문서 버전의 참조 R행 INSERT가 추가된다. 반복 배경 교체/문서 저장도 현재 참조를 버전별로 기록하므로 쓰기가 추가된다. 기존 Mac 경로만 있는 문서에는 추가 DB 쿼리 없음.
- 문서 열기: 화면에서 요구한 이미지 content 조회가 추가되고 같은 hash는 브라우저에서 재사용한다. 검색/순서 저장/Sync 비교의 기존 요청 빈도와 범위는 바꾸지 않는다. Sync 다운로드는 새 문서의 연결된 이미지 수·용량만큼 기존 이미지 API를 이용한다.
- SQL PK/문서별 범위로 제한하며 전체 문서 스캔이나 자동 색인을 추가하지 않는다. 요청 수와 rows_read/rows_written은 다르다. 합성 Worker 검사 성공, 운영 DB 행 수 부하 실측은 미수행이다. 새 유료 서비스 없음.

## 빌드·검증

`scripts/build-ppt.mjs`가 pinned npm 의존성을 번들하고 라이선스 공지를 생성한다. `ppt-codec@2.2.23`의 OfficeArtFOPTEOPID fBid/fComplex 역전과 미지원 BLIP 슬롯 누락은 버전 검증된 esbuild 패치로 보정한다. node_modules나 원본 파일을 수정하지 않는다. 독립 바이트 fixture는 MS-ODRAW 비트14/15 규칙을 확인한다. 패치 대상 문자열이 바뀌면 빌드를 중단해 업그레이드를 재검토한다.

`npm test`, `npm run deploy:check`, `node tests/browser/ppt-import.cjs`로 검사한다. 브라우저 검사는 합성 PPTX 일반/악보 변환, 투명도·첫 장 제목 유지, 강제503 후 새로고침/재시도, 중복 방지, 배경만 변경, 재생목록 초안, 1440/820/390px를 확인한다. 실제 자료는 `PPT_FIXTURE_DIR`로 로컬에서만 추가 검증한다.

최종 저장 공간 부족 검사: IndexedDB의 QuotaExceededError를 강제로 재현하여 준비본 보존 실패 시 이미지/문서 업로드 0건과 ‘업로드를 시작하지 않음’ 안내를 확인했다. 복구본 보존이 성공한 다음에만 업로드 상태로 넘어간다. PR #30 Studio 검사 37114585361 및 첫 운영 배포 37114695652는 성공했다. 이 저장 공간 안내 보정은 후속 운영 커밋으로 반영한다.

배경 없음(투명)은 악보 PNG의 기존 알파를 유지하고 배경 PNG와 backgroundMediaCue를 생성하지 않으며 슬라이드 바탕색도 끈다. 미리보기의 체크무늬는 투명 영역 안내다. Studio 편집 화면의 어두운 바탕은 표시용일 수 있으며 저장한 악보에 합성되지 않는다. 불투명 그림에 합쳐진 배경을 자동으로 지우는 기능은 아니다. 배경 없이 가져온 문서에도 나중에 전체 배경 적용으로 배경 cue를 추가할 수 있다.
