# 문서 정리 이후 작업과 적용 순서 · 2026-10-03

## 현재 상태

[PR #23](https://github.com/m1r4d0r/yebaeon/pull/23)은 구현·검증 완료, 미병합이다. 자동 승인 검토가 main 병합의 운영 배포 부작용에 대한 명시적 승인 부족을 이유로 병합을 거절했다. 사용자에게 병합·사이트 배포 승인을 요청했으며 답변 전에는 다른 경로로 배포하지 않는다. 실제 교회 문서/템플릿 교체와 운영 자료 정리도 미실행이다.

사용자가 Sync 변경 시 공개 저장소 Actions 사용을 재허용했다. 과거 Actions 중단 규칙, 보관 대상 미선정 기록은 현재 결정을 대체하지 않는다. PR #22의 최신 소스 5caab8c를 이번 후보에 병합했다. 그 안의 비교 양보·자동 재개와 Mac 기준 서버 맞추기는 이미 구현/검증된 기능이다.

유지 7·보관 7·삭제 5 재생목록은 이미 승인됐다. 결혼예배는 보관, 중보기도자 컨퍼런스는 삭제다. 정리본의 기본.pro6pl은 유지 7개, 보관목록.pro6pl은 보관 7개다. 새 템플릿 6종도 로컬에 준비됐다. 실제 자료/식별자가 담긴 적용 계획은 공개 Git에 추가하지 않는다.

## 검증과 오류 수정

- 후보 소스: 00f90df29999fa6e95825ca0cc586577369e120f. 이후 인계 문서 변경은 앱 코드와 구분한다.
- 로컬 Node 59개 및 기존 Studio Chrome 흐름 통과. 새 문서/목록 관리도 실제 Worker 모사 서버를 연결한 브라우저에서 이름 충돌, 미저장 복제, UUID 참조/미디어 보존, 생성·보관·복원을 확인했다.
- [Studio CI 37069912945](https://github.com/m1r4d0r/yebaeon/actions/runs/37069912945) 성공.
- [Mac CI 37069897194](https://github.com/m1r4d0r/yebaeon/actions/runs/37069897194) 한 번의 후보 실행으로 빌드·진단·안전성·Worker·GUI·패키징 성공. 기존 비교 양보/재개를 재사용하고 신규 보관 연결의 중단·복구를 검증했다. 검사 수를 버전 목표로 삼지 않는다.
- 설치 ZIP: 760111 bytes, SHA256 af5ed0316acb3a454c2c46243078051c489b695bd3329ca7fe4f7c377ec1d162. 최소 OS 10.13. 최신 Intel macOS에서 만든 10.13 대상 빌드이며 교회 High Sierra/PP6 실기 확인은 남았다.
- 초기 브라우저 검사의 넓은 검색 선택/잘못된 텍스트 함수, 기존 font-preview.html 누락은 검사 코드를 고쳐 재검증했다. artifact 연결 도구의 임시 URL이 HTTP403으로 거부되어 같은 성공 artifact를 GitHub 직접 다운로드로 확보/ZIP CRC·버전·SHA 검증했다. 앱 재빌드로 우회하지 않았다. 현재 검사 실패는 없고 운영 배포만 승인 대기다.

## 비용

대기·최초 문서 영역·입력 중 새 문서 조회/폴링은 없다. 카테고리 필터는 기존 검색 SQL에 포함되고 bare Sync 문서 목록 계약은 유지한다. 기존 3,107개 합성 조건의 warm search 12,449 rows_read, 상태 대상 20개 80행은 이전 측정과 같다. 본문 부분 문자열 검색 의미를 축소하지 않았다.

목록 일반 PUT은 해당 파일의 관리 노드 조회 한 번을 추가한다. 목록 추가는 파일 CAS와 관리 행을 한 batch로 기록한다. 보관/복원은 선택 목록의 참조 문서를 80개씩 조회하고 확보된 파일만 읽는다. 보관함은 명시적으로 열 때 100개씩 조회하며 시작 비교에 추가하지 않는다. Mac 구조 정리는 명시 실행 때 해당 파일의 목록 상태를 조회한다. 새 서버 전용 노드가 있는 자동 업로드만 그 파일 원본을 한 번 더 읽는다. 실제 운영 D1 측정은 미실행이며 모사 측정과 구분한다.

## 이어서 할 순서

1. 병합·운영 사이트 배포 승인 후 PR #23 병합, 자동 배포 결과와 실제 사이트 자산/인증 경계 확인. 지금 승인 검토 거절을 우회하지 않는다.
2. 교회 Mac의 현재 원본·동기화 기준·서버 버전을 읽기 전용으로 대조하고 양쪽 백업. 이 Windows 세션에는 실제 Mac 기준이 없다.
3. 승인된 7개를 서버에서 보관하고 5개를 제외. 보관 당시 문서 누락(성탄절의 알려진 누락 포함)을 기록한다. 미디어 전체가 확보됐다고 표시하지 않는다.
4. 교회 문서/템플릿/활성 목록을 준비된 정리본으로 교체하고 PP6 대표 화면을 확인. Sync의 Mac 기준 서버 맞추기로 버전 CAS/해시 검증 뒤 공통 기준 연결.
5. 제외한 205개 서버 문서와 과거 정적 catalog, 템플릿 6종 반영을 별도 마무리. 현재 reset은 서버 전용 문서를 보존하므로 4번만으로 정리 완료라고 보고하지 않는다. DB 초기화·버전 전체 삭제 금지. 운영 인증과 최신 양쪽 자료를 확보한 뒤 경로/참조를 대조해 처리한다.
6. 미결 25개 현장 이미지 확인. 그 뒤 미디어 실제 송수신·중복/실패 재시도·보관 참조 보호, 의미상 동일 변경 판정 및 운영 비용 관측을 순차 진행. 원본 이미지/영상 전체가 아직 없으므로 제목으로 확정하지 않는다.

가사/악보 두 버전, 사용자 확정 카테고리 및 기존 배경 유지 결정은 다시 물을 필요가 없다. 남은 것은 기준 선정이 아니라 배포 승인과 현장 적용/누락 원본 확인이다.
