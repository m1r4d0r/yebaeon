### 남은 실제 적용

1. 교회 Mac의 현재 원본·선택 경로·문서/재생목록 기준·중단 작업을 읽기 전용으로 확보한다. 이 PC 복사본에는 Mac의 Sync 기준 기록이 없다. 비밀번호/키체인은 수집하지 않는다.
2. 서버의 현재 ID·버전·해시와 정리본을 대조해 변경 계획을 저장한다. 정리 중 서버에 새 작업이 있었으면 해당 차이를 확인한다.
3. 변경 전 서버 원본과 로컬 기준을 백업하고 CAS로 반영한다. 실제 저장 해시를 확인한 항목만 Mac 기준에 연결한다. 응답이 모호하면 재조회하며 기준 파일만 일치로 바꾸지 않는다.
4. 정리본에서 제외한 205개의 서버 문서/정적 catalog 처리를 결정 기록과 대조한다. 정적 manifest 교체만으로 업로드된 옛 문서가 없어지지는 않는다. DB 초기화나 과거 버전 일괄 삭제로 해결하지 않는다.
5. 템플릿 6종과 재생목록의 서버 정리는 아래 보관 보호와 함께 반영한다. 실제 배포·PP6 재열기를 검증한 뒤 완료 처리한다.

## 2. 재생목록 보관·복원

- 19개 중 사용 중 7 / 보관 7 / 삭제 5로 확정했다. `기본.pro6pl`과 `보관목록.pro6pl`로 나눴다. 결혼예배는 보관, 중보기도자 컨퍼런스는 삭제다. 다시 선정받지 않는다.
- 서버 보관 항목을 활성 목록 전체 PUT과 분리한다. 구버전 Sync가 활성 7개만 올려도 보관 7개가 소실되거나 자동 복원되지 않아야 한다.
- 기본 목록/시작 비교에서 보관 항목을 제외하고 명시적으로 열고 복원한다. 당시 문서까지 고정할지, 최신 공유 문서를 참조할지는 미결이다. 찬양 이력 끔 정책과 충돌하므로 복원 동작을 구체적으로 제안한다.
- 서버 보존·원본 백업·필요 문서/미디어 검증 뒤 교회 Mac의 선택 노드를 제거한다. 공유 문서를 함께 지우지 않으며 보관 참조 미디어를 정리에서 보호한다.

## 3. 전체 비교에 막히지 않는 선택 작업

- 전체 비교를 안전한 경계에서 취소/양보하고 선택 문서·예배의 최신 상태만 확인해 받기/등록한다. 일시중단은 작업 소유권을 보유하므로 취소와 구분한다.
- 파일 적용은 직렬로 유지한다. 부분 결과를 전체 비교 완료로 표시하거나 기준 없는 항목을 강제로 일치 처리하지 않는다.
- SHA는 전송 무결성 확인에 유지한다. 사용일·경로만 다른 경우의 의미 비교는 실제 자료와 필드 규칙이 먼저다. 가사만 같다고 배경·배치·arrangement·재생 신호를 무시하지 않는다.
- PR #22는 2026-10-03 확인 시 open, head `5caab8cdb67cf450181c760e0ba1a22e99819021`. 병합 전 최신 UI/일시중단 변경을 확인한다. 이번에는 Mac 소스를 바꾸지 않았다.

- 기존 dist의 오래된 파일 때문에 첫 정적 빌드가 보호 규칙으로 중단되어, 별도 빈 출력 폴더에서 288개 공개 자산 빌드에 성공했다. 기존 dist는 그대로 두었다.
- 대기/첫 진입: 새 폴링·cron·전체 보충 0회. 문서 열기/Sync 비교·다운로드/재생목록 저장: 추가 조회 없음. 검색은 기존 SQL 안에서 필터링하고 원본을 읽지 않는다. 본문 부분 문자열 검색은 여전히 라이브러리 크기에 비례한다.

- 운영 서버 변경·배포·PR 생성·push·Actions 실행은 하지 않았다. Studio PR 생성과 main push에는 자동 Actions 트리거가 있으므로 그대로 진행하지 않는다. High Sierra 빌드와 PP6 재열기는 미검증이다.
