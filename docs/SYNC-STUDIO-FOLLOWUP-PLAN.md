## 작업 묶음 0 · 서버 현황 페이지와 DB 조회 절감

### 코드 확인 결과와 비용 해석

- D1의 500만 행 읽기는 Workers Free **하루 한도**다. 한국 시간 오전 9시(00:00 UTC)에 재설정된다. 화면에 반환한 행 수가 아니라 SQL 실행 시 스캔한 행(인덱스 포함)이 기준이다. 색인/테이블 변경이나 저장도 SQL에 따라 읽기가 함께 발생할 수 있다.
- GitHub 문서 읽기·소스 수정·푸시 자체는 운영 D1 조회가 아니다. 로컬/CI 모사 검사는 운영 DB와 분리된다. 배포 후 접속·실제 저장/업로드·목록/검색·스케줄 작업은 운영 DB를 사용한다.
- web-editor/status.js: 보이는 탭에서 10초마다 /api/status. 숨긴 탭은 refresh에서 건너뛰지만 다시 보이면 즉시 조회한다.
- cloudflare/status.mjs: 문서 COUNT/SUM/MAX, 이전 버전 JOIN 집계, 최근 12개 정렬, 작업자별 GROUP BY 등 7개 쿼리를 반복한다. 화면에서 사용하지 않는 workers 집계도 계산한다. 예시로 문서 3천 행 집계 하나만 10초마다 반복해도 1시간 약 108만 행 스캔 규모이며 여러 집계/JOIN이 더해진다. 실제 요청별 rows_read는 아직 측정하지 않았다.
- wrangler.jsonc의 매분 cron → worker.mjs scheduled → indexUsage(32)·indexSearch(16). 색인 미완료 대상 찾기와 전체 진행 집계가 완료 이후에도 실행된다. 브라우저를 닫아도 발생한다.
- web-editor/cloud.js의 상태등 30초 갱신 → sync-observations.mjs GET에서 전체 문서 해시·전체 상태 보고를 읽고 서버 재생목록도 R2에서 파싱한다. 문서 검색 시에도 상태등 refresh가 호출된다.
- library-catalog.mjs의 이름/본문 검색은 instr를 이용한 부분 문자열 비교이며 일반 SQL 인덱스로 검색어를 바로 찾는 구조가 아니다. 목록 요청마다 searchProgress 전체 집계도 있다. ‘본문 색인을 만들었다’는 것은 원본 XML을 검색마다 다운로드하지 않는다는 뜻이며 D1 스캔 비용이 없어졌다는 뜻은 아니다.
- 알림의 94% 약 470만 행 중 각 경로의 실제 비중은 미확정이다. 현황판만 원인이라고 단정하지 않는다. 운영 쿼리별 메타/Cloudflare Metrics 확인 전 합계 추정을 실제 측정으로 기록하지 않는다.

공식 근거: https://developers.cloudflare.com/d1/platform/pricing/ 및 https://developers.cloudflare.com/d1/observability/metrics-analytics/ (2026-10-02 확인). 무료 한도 소진 시 D1 쿼리가 실패할 수 있으므로 반복 조회부터 줄인다.

### 승인한 조회 순서

사용자 19:04~19:05 결정으로 이전 P4의 ‘인덱스 → 전체 문서 → 예배’ 순서를 대체한다. 로그인 확인 → 전체 재생목록과 연결 문서 우선 비교 → 나머지 문서 백그라운드 점검이다. 선택 예배만 우선하는 방식은 채택하지 않는다. 실제 Mac 파일 적용은 받기 버튼에서 수행한다. 기존 Mac 원본 재생목록의 서버 등록/단방향 CAS 갱신은 유지한다.

- 우선 묶음이 끝나면 받기 사용 가능. 공유 문서는 비교 회차의 해시와 장치/파일번호/크기/mtime/ctime(나노초 포함)으로 확인한 로컬 요약을 재사용한다. 나머지 점검에서도 변경이 없으면 원본을 다시 읽거나 XML을 분석하지 않는다.
- 백그라운드는 앱 실행의 해당 폴더에서 한 번만 예약한다. 받기·등록·수동 비교·폴더 변경 등 명시적 작업이 오면 취소를 요청하고, 같은 직렬 큐의 다음 점검 경계에서 중단한 뒤 사용자 작업을 실행한다. 파일 적용과 비교는 병렬 실행하지 않는다. 중단된 전체 점검은 문서 탭의 ‘서버와 비교’로 명시적으로 재시도한다.
- 진행 중 HTTP 요청은 즉시 취소하지 않으며 제한 시간 내 완료/실패 후 양보한다. 메타데이터 페이지·inventory·선택적 관측 보고는 각각 10초 요청 제한을 사용한다(기존 전송기의 절대 대기 여유 별도). 로컬 스캔/원본 읽기는 파일 경계에서 중단한다.
- 전체 inventory는 완성된 목록을 한 번에 커밋한다. 취소된 일부 목록을 전송해서 나머지 파일을 사라진 것으로 표시하지 않는다. 본문 색인은 시작 점검에 넣지 않는다.
- 비교 요약은 현재 앱 프로세스에서만 보관한다. 재실행 후 첫 점검은 실제 원본을 읽는다. 원본 전체를 지속 캐시하지 않으며 송수신 직전·직후 실제 해시 확인은 유지한다.

### 화면·비교·복구

- 최상위 창의 경로를 두 줄로 분리하고 고정 1060×720 스크롤 캔버스를 제거한다. 탭의 실제 영역에 맞춰 표 높이를 줄이고 상하 컨트롤을 유지한다. 긴 예배 이름은 받기 버튼 제목 대신 툴팁으로 제공한다. 서버 시간은 서울 기준으로 표시하고 선택 행 대비를 보완한다.
- 자동 원본 등록/파일 전체 갱신도 예배별 공통 기준을 저장한다. 구버전 기준 누락은 ‘현재 전체 로컬 해시 = 저장된 로컬 해시 = 과거 서버 원본 해시’ 증명이 있는 경우에만 보완한다. 증명이 없는 서로 다른 파일은 계속 충돌/기준 없음으로 차단한다.
- 순서 추가·제거·이동과 문서 변경을 별도 표시한다. 삽입/삭제 때문에 번호만 밀린 기존 항목을 이동으로 오인하지 않는다. 제거한 참조의 원본 파일은 유지한다.
- 문서 SHA 차이는 본문만 바뀌었다는 증명이 아니므로 ‘문서 변경’으로 표시한다. PP6의 사용일·경로 차이를 의미 비교에서 제외할 후보로 검토했으나 자동 수신 안전성에는 원본 SHA를 유지한다. 선택 arrangement·미디어/전환 등 중요한 속성을 일괄 무시하지 않는다. 의미상 동일한 원본의 자동 병합/강제 덮어쓰기는 이번 범위가 아니다.
- 묶음 복구 전에 모든 대상의 현재 파일·기준·원본 백업을 검사한다. 같아서 다운로드하지 않고 기준만 갱신한 문서도 이전 기준으로 복구한다. 작업별 batchID로 중단 저널 소유권을 확인한다. 문서 적용/순서 적용/예배 기준 저장 후 중단을 재시작 복구 검사한다.
- 예배별 서버 이력과 로컬 받기 작업 백업은 기존처럼 구분한다. 완료한 받기 10회 보관 및 중단 기록 보호를 유지한다. 기존 백업을 일괄 삭제하지 않는다.

### DB 비용 영향과 산정 범위

서버 스키마·SQL·Studio 검색/저장 경로는 변경하지 않는다. 운영 DB에 부하 시험을 하지 않으며 다음은 호출 구조의 계산이다.

| 작업 | 조회/쓰기 영향 |
|---|---|
| 앱 대기 | 추가 요청 0회. 폴링·cron 없음 |
| 우선 묶음 비교 | 재생목록 페이지 + 예배별 plan. plan은 해당 예배 문서 경로 IN 조회, 파일 버전/예배 최신 이력/인증 확인. 전체 문서 목록·inventory 완료를 기다리지 않음 |
| 전체 백그라운드 점검 완주 | 기존과 같은 전체 문서 메타데이터 페이지와 완전한 inventory 1회. 연결 문서 메타데이터는 이 목록에 포함되지만 원본 내용은 로컬 캐시 재사용. 뒤로 미룬 것을 전체 DB 조회량 절감으로 표현하지 않음 |
| 상태 보고 | reconcile의 중복 예배 보고를 제거. 우선 묶음의 연결 문서는 ID별 1개 보고. 60초 안의 동일 해시·상태는 앱 메모리에서 중복 쓰기를 생략. 시간이 지났다고 자동 요청하지 않으며 실패 보고는 캐시하지 않음 |
| 선택 예배 받기 | 기존 다단계 plan 재확인, 변경된 원본 다운로드, 백업/적용, 상태 보고 유지. 이후 전체 문서 재비교를 자동 반복하지 않음. 공유 문서 다운로드는 묶음당 한 번 |
| Studio 검색·문서/순서 저장 | PR #20 계약 유지, 이 PR로 추가 DB 요청 없음 |

예시 가정: 서버 원본 3,107개, 예배 19개, 연결 문서 고유 150개, 문서 페이지 100개. 우선 화면은 약 32회의 전체 문서 목록 요청과 3,107개 inventory 처리를 먼저 기다리지 않는다. 예배 plan 19회에서 같은 문서가 여러 예배에 쓰이면 서버 메타데이터는 반복 조회될 수 있다. 로컬 원본 비교는 고유 문서 최대 150개부터 시작하고, 전체 점검에서 나머지 약 2,957개를 읽는다(파일 미변경 가정). 기존 전체 비교의 원본 해시+사용일 추출 약 6,214회 읽기와 이후 연결 문서 읽기를 줄인다. 이는 호출/파일 읽기 계산이며 D1 rows_read 실측이 아니다. SQL 인덱스 접근·인증·버전 검사의 행 비용은 기존 d1-request-cost로 관측한다. inventory의 전체 쓰기 비용은 남아 있으며 증분 서버 API/영속 캐시는 별도 검토 사항이다.
