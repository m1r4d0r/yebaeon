# Sync 점검 목록 처리

Sync 정리 창의 '확인 필요' 목록을 글로 뽑아 Claude에게 보내고, 항목마다 처리 방안을 제안받는 방법이다. 받은 Claude는 이 문서를 기준으로 답한다.

## 글 뽑기

- **Studio**: 작업자 메뉴 › 교회 Mac › 창 위 [점검 목록 복사]. Mac이 마지막으로 보고한 정리 창 목록(최대 100개)에 서버 상태를 붙인다. 집에서도 된다.
- **Sync 2**: 정리 창 아래 [목록 복사]. 지금 목록 전체에 Mac 쪽 사실(파일 있음·크기·수정 시각·sha·영수증 기준 버전)까지 붙인다. 서버에 닿지 않으면 Mac 쪽 내용만 복사한다.
- 둘 다 서버 `POST /api/sync/devices/<장치>/review`가 글을 만든다(`cloudflare/sync-review.mjs`). 누를 때만 부른다. 운영 데이터는 바꾸지 않는다.

글의 모양: 머리(만든 때·장치·빌드·Mac 상태·일지 번호), `### <목록> (n)` 아래 항목마다 `Sync 설명`, `Mac:`(Sync에서 뽑았을 때만), `서버:`(문서 버전·상태·마지막 저장자·크기·sha·카테고리·이력·열린 보관본), `서버 예배:`(그 문서가 든 사용 중 예배), `최근 일지:`(최근 3줄, 쓴 쪽이 Mac인지 Studio인지), `그림:`(경로표 상태), `정리 창 버튼:`. 끝에 예배 비교에서 같지 않은 줄과 적용 보고의 기다림.

## 답하는 방법

- 항목마다 한 줄 결론(누를 버튼), 까닭(글의 어떤 사실 때문인지), 누르기 전에 확인할 것을 적는다. 같은 판단이 되는 항목은 묶는다.
- 글에 없는 것은 짐작하지 않는다. 판단이 갈리면 [차이 보기]로 볼 곳을 짚고 사람이 고르게 한다.
- 버튼은 사람이 Sync 정리 창(또는 원격 지원 창)에서 누른다. Claude는 운영 서버를 직접 고치지 않는다. 서버 쪽 고칠 일(코드 버그로 보이는 것)은 따로 적는다.
- 위험 순서: Mac 파일을 덮는 것(서버 것 받기), 서버 현재본을 바꾸는 것(Mac 것 올리기), 휴지통으로 보내는 것. 덮이는 쪽은 각각 Mac 백업 폴더·서버 보관본·서버 이력·휴지통에 남지만, 이력 끔 문서는 서버 이전 버전이 남지 않는다.

## 목록별 판단

| 목록 | 뜻 | 먼저 볼 사실 | 대개 |
|---|---|---|---|
| 같은 이름, 다른 내용 | 같은 경로에 Mac과 서버 내용이 다르고 영수증에 공통 이력이 없음. [적용]이 건너뛴다 | 서버 마지막 저장자·시각과 Mac 수정 시각, 최근 일지(Studio 저장인지), 서버 예배에 드는지 | 서버가 나중이고 Studio에서 고쳤으면 **서버 것 받기**. Mac이 나중이고 PP6에서 고친 흔적이면 **Mac 것 올리기**. 둘 다 살려야 하거나 다른 곡이면 **둘 다 두기**. 글자만 다르고 같은 곡으로 보이면 [차이 보기] 먼저 |
| 서버에만 있는 문서 | 서버 사용 중 문서인데 Mac에 파일도 받은 기록도 없음 | 서버 예배에 드는지, 카테고리, 최근 일지 | 예배에 들거나 곧 쓸 것이면 **서버 것 받기**. 안 쓰는 옛 문서면 그대로 두거나 Studio에서 보관함으로 |
| Mac에서 지움 | Mac에서 지운 문서·예배. 다시 받지 않음 | 서버 예배에 드는지, 서버 상태 | 예배에 쓰이면 **다시 받기**. 정말 안 쓰면 **서버 휴지통으로**. 예배 줄은 데일리 창에서 체크하면 다시 받음 |
| 확인 필요 | 보류: 받을 자리에 같은 이름 Mac 파일, 이력 없는 다른 내용, 내용이 다른 이미지 등 | Sync 설명의 이유 | 이유대로: 이름 겹침이면 같은 이름, 다른 내용과 같게. 문서 줄이면 [차이 보기] |
| 외부 참조 | 문서가 허용 폴더 밖 그림을 가리킴 | `그림:` 줄(서버 경로표에 있는지) | 교회 Mac에서 계속 쓸 그림이면 **그림 가져오기**(YebaeOn/으로 복사·경로 바꿈·서버에도 올림) |
| 이미지 보충 | 서버 경로표에 있고 이 Mac에 없는 그림 | `그림:` 줄의 서버 상태, '원본 그림 없음' | **이미지 받기**. 서버에 원본 그림이 없으면 받을 수 없으니 서버 쪽 일로 적음 |
| 번호 붙임 | 둘 다 두기로 만든 `이름 2` 사본 기록 | 원래 문서와 사본 중 예배가 쓰는 쪽 | 사본이 필요 없으면 **번호 사본 지우기** |

- 예배 비교의 `보류`·`Mac 수정 올리기 대기`·`받을 것` 줄은 데일리 창 [적용]으로 푼다. 보류 이유가 이력 없는 문서뿐이면 정리 창에서 정한다.
- `이 장치가 적용한 번호`가 일지 마지막 번호보다 많이 뒤면 Mac이 오래 비교·적용하지 않은 것이다. 먼저 [다시 비교]를 권한다.
- 같은 항목이 여러 번 다시 생기면(받았는데 또 다름) 비교 규칙 문제일 수 있다. 버튼 대신 [차이 보기]의 '비교용으로 맞춘 뒤 첫 차이'를 받아 코드 문제로 넘긴다.
