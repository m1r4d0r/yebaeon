# PPT 가져오기

Studio 상단 `PPT 추가`로 PPT·PPTX를 슬라이드 이미지 문서로 바꾸어 등록하는 방법과 지원 범위를 정리한다.

한 번에 파일 하나를 드롭하거나 선택한다. 변환은 브라우저에서 하며 PowerPoint 원본은 서버나 외부 변환 서비스로 보내지 않는다. 제한은 파일당 40MB·120장, 압축 해제 총량 160MB, 변환 이미지 총량 180MB다. 변환기(약 1.9MB)는 파일을 선택할 때만 불러온다.

## 사용 순서

1. 설교·행사는 `슬라이드 전체 이미지`, 악보는 `배경 분리`를 선택한다.
2. 가져올 장을 체크한다. 악보는 각 장에서 사용할 그림을 고른다. 기본값은 큰 투명 이미지다. 장당 악보 그림은 하나이므로 여러 조각이나 그룹으로 된 악보는 PowerPoint에서 하나의 그림으로 만들어 둔다.
3. 악보의 첫 번째 선택 장은 제목을 유지하고, 이후 장은 그림 상단 16.7%를 제외한다. 숫자로 조절할 수 있다. 원본 좌표와 음표 크기는 유지하고 잘린 부분은 투명하다. 하단 이동용 도형과 다른 텍스트 도형은 가져오지 않는다. 특정 슬라이드를 삭제하는 기능은 아니다.
4. 원본 배경, 배경 없음(투명), 단색, 새 사진 중에서 고르고 `변환 미리보기`를 누른다. 썸네일을 누르면 확대된다. 변환 설정을 바꾸면 검수 체크가 풀리므로 다시 미리보기한다.
5. 검수를 확인하고 `문서 추가`를 누른다. 일반 자료는 특별순서, 악보는 악보찬양 카테고리에 들어간다.
   - 같은 이름의 기존 문서는 덮어쓰지 않는다. 이름이 겹쳐 409가 나면 복구 영역의 `새 문서 이름 → 이 이름으로 저장`을 쓴다. 기본 제안은 기존 이름 뒤 `(PPT)`이며 수정할 수 있다. 준비한 이미지와 검수 결과는 다시 변환하지 않고 유지한다.
   - 선택한 재생목록 하단에 추가되는 것은 초안이다. 기존 `변경사항 저장`으로 확정하며 원래 순서를 교체하지 않는다.
6. 가져온 악보를 연 상태에서 PPT 추가 창의 `현재 열려 있는 악보 문서의 배경 바꾸기`로 전체 배경을 교체한다. 악보 PNG는 그대로 유지된다. 이후 `변경사항 저장`이 필요하다.

배경 없음(투명)은 악보 PNG의 기존 알파를 유지하고 배경 PNG와 배경 cue를 만들지 않으며 슬라이드 바탕색도 끈다. 미리보기의 체크무늬는 투명 영역 표시다. Studio 편집 화면의 어두운 바탕은 표시용이라 악보에 합성되지 않는다. 배경 없이 가져온 문서에도 나중에 전체 배경을 적용할 수 있다.

## 지원 범위와 제약

- PPTX는 브라우저 OOXML 렌더러로, PPT는 바이너리의 구조·그림·텍스트·좌표를 읽어 정지 화면을 만든다. PowerPoint와 같은 렌더링 엔진이 아니다.
- 원본 폰트가 변환 컴퓨터에 없으면 이미지로 만들기 전에 대체 폰트가 쓰일 수 있다. 이미지화가 원래 렌더링 문제를 해결하지는 않는다. 저장된 PNG는 보는 기기의 폰트에 영향받지 않는다.
- PPT 마스터 장식, 특수 도형, 표, PPTX의 일부 벡터·SmartArt·효과, 애니메이션, 영상은 완전한 재현을 보장하지 않는다. 미리보기를 원본과 대조한다.
- 악보와 사진이 이미 한 그림으로 합쳐져 있으면 사진을 복원해 분리하지 않는다. 선택한 이미지가 불투명하면 경고한다. AI 배경 제거와 OCR은 쓰지 않는다. 불투명 그림에 합쳐진 배경을 자동으로 지우지 않는다.

## 저장과 복구

- PNG의 SHA-256을 기준으로 이미지를 등록한다. 저장 전에 hash를 80개씩 조회해 이미 올라간 이미지는 다시 보내지 않는다. 악보 PNG는 displayElements에, 배경 PNG는 backgroundMediaCue에 넣어 분리한다.
- 이미지 업로드를 먼저 확인하며, 없는 이미지를 가리키는 문서는 저장하지 않는다. 문서와 미디어 참조는 같은 D1 batch와 CAS 조건으로 커밋한다.
- 이미지를 올린 뒤 서버가 교회 Mac 경로 `/Users/Shared/Renewed Vision Media/YebaeOn/<문서이름>-<n>.png`를 정해 이미지 경로표에 넣고, 문서에는 그 file URL을 적는다. 이미 같은 그림이 `YebaeOn/`에 있으면 그 경로를 다시 쓰고, 새 그림은 같은 이름의 다음 번호를 받는다. 배경 바꾸기는 `<문서이름> 배경-<n>.png`이다. Sync 2는 그 문서를 쓰는 예배를 [적용]할 때 Mac에 없는 이미지를 받아 둔다.
- 이 방식 전에 가져온 문서는 `file:///YebaeOn-Media/<sha256>.png`로 남아 있다. Studio에서는 보이지만 교회 Mac에서는 이미지가 없다(경로 변환은 BACKLOG).
- 가져온 문서의 준비 XML과 PNG는 작업자 이름별로 브라우저 IndexedDB에 보존되어, 실패하거나 새로고침한 뒤 같은 경로와 같은 내용으로 재시도한다. 보존에 실패하면(저장 공간 부족 등) 업로드를 시작하지 않고 그렇게 안내한다. 브라우저 저장소를 지우면 복구본도 사라진다.
- 저장된 이미지와 문서는 자동으로 롤백되지 않는다. `준비본 버리기`는 브라우저 준비본만 지운다.
- Sync의 슬라이드 번호는 1부터 시작한다. 기존 Mac 문서의 수동 참조 등록 방식은 그대로다.

## 비용

- 대기, 최초 진입, 모달 열기, 변환, 크롭: 새 D1 요청과 폴링이 없다. 변환은 로컬 CPU와 메모리를 쓴다.
- 가져오기 한 번: 고유 이미지 N개를 80개 단위로 존재 조회하고, 없는 것만 N개 이하로 PUT하며, 경로 정하기를 200개 단위로 한 번(조회 3·쓰기 2문장, 새 경로마다 경로표·일지 1행), 문서는 한 번 POST한다. 슬라이드 S개이면 일반은 최대 S개, 분리 악보는 최대 2S개다. 같은 배경과 같은 악보는 hash로 재사용한다. R2에 PNG 용량이 추가된다.
- 문서 저장: 가져온 이미지(`YebaeOn/` 경로나 옛 `YebaeOn-Media`)가 있을 때만 경로표 조회 1문장, hash의 PK 조회, 문서 버전별 참조 행 INSERT가 추가된다. 다른 Mac 경로만 있는 문서에는 추가 쿼리가 없다.
- 문서 열기: 화면에서 요구한 이미지 content 조회가 추가되고 같은 hash는 브라우저에서 재사용한다. 검색, 순서 저장, Sync 비교의 요청 빈도와 범위는 그대로다.
- 조회는 PK와 문서별 범위로 제한되며 전체 스캔이나 자동 색인은 없다.
