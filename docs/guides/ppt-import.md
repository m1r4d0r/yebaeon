# PPT·PDF 가져오기

Studio 상단 `PPT·PDF 가져오기` 창으로 PPT·PPTX·PDF를 슬라이드 그림 문서로 바꾸는 방법과 지원 범위를 정리한다.

## 흐름

1. 최상단 **악보 / 설교·광고 / 기타**에서 사용자가 용도를 고른다. 파일 내용이나 확장자로 용도를 자동 판단하지 않는다. 처음에는 기타가 선택된다.
   - 악보: 새 문서 추가, 악보찬양 카테고리, 악보와 배경 분리.
   - 설교·광고: 기존 문서 교체, 전체 슬라이드 이미지. 교체할 문서는 사용자가 직접 고른다.
   - 기타: 새 문서 추가, 예배순서 카테고리, 전체 슬라이드 이미지.
2. 최상단 왼쪽에는 파일 이름, 오른쪽에는 `내 컴퓨터에서 불러오기` → `드롭박스에서 가져오기` 버튼이 있다. 여기에서 파일을 고른다. 용도 선택은 유지되며 파일을 읽은 뒤 미리보기가 자동으로 생성된다.
3. 넣을 곳·카테고리·가져오기 방식을 필요에 맞게 조절한다. **분리 방식은 카테고리에 종속되지 않는다.** 용도를 다시 누르면 해당 기본 설정으로 돌아간다.
4. 옵션이나 포함할 장을 바꾸면 자동으로 다시 변환하고 검수 체크를 해제한다. 변환 버튼은 없다. 입력 중에는 짧게 기다렸다 최신 설정으로 변환하며 이전 결과는 저장할 수 없다.
5. 썸네일을 눌러 확대하고 모든 장 검수에 체크한 뒤 저장한다.

## 악보와 배경

- **악보와 배경 분리**: 투명 악보 그림은 분리하고, 불투명 그림은 전체 이미지로 유지한다. 장마다 그림을 직접 지정하거나 통 이미지로 바꿀 수 있다.
- **흰 바탕을 투명하게 · 악보 분리**: 슬라이드 배경에 PNG로 들어간 악보도 선택 가능하다. 흰색과 가장자리를 투명하게 처리한다. 흰 글자·테두리도 영향을 받으므로 미리보기로 확인한다.
- **전체 슬라이드 이미지**: 배경·그림·글자를 한 장으로 합치며 제목 자르기와 흰 바탕 제거를 적용하지 않는다.
- **하단 번호·문구 자르기**: 켜면 모든 장의 아래쪽을 지정한 비율(기본 8%)만큼 투명하게 지운다. 악보 위치와 크기는 유지한다. 악보가 아래까지 있는 파일은 미리보기를 보며 비율을 낮춘다. 전체 이미지 모드에는 적용하지 않는다.
- 투명한 부분은 진한 격자로 표시한다. 일부 투명 픽셀이 이미 있는 PNG도 흰 바탕 투명화를 선택하면 흰색을 제거한다.
- 분리 모드의 제목 자르기는 첫 번째 포함 장을 유지하고 나머지 장의 위쪽 비율(기본 16.7%)을 자른다.
- 분리한 배경 그림은 문서에 넣지 않고 미디어에 따로 등록한다. 단색 배경과 배경 자체를 악보로 사용한 원본은 중복 등록하지 않는다.
- 기존 문서 교체도 분리 모드를 직접 선택할 수 있다. 대상 크기에 비율을 유지해 맞춘다.

## 크기와 비율

- PPT 제한은 파일당 40MB·120장, 압축 해제 총량 160MB, PDF는 60MB·120쪽, 변환 이미지 총량 180MB다. 암호 걸린 PDF는 열지 않는다. 변환기(PPT 약 1.9MB, PDF 약 1.7MB)는 그 종류 파일을 고를 때만 불러온다.
- 새 문서는 PPT면 PPT 비율(가로 1920), PDF면 1920×1080이다. 교체는 대상 문서 크기로 만든다. 장이나 쪽의 비율이 다르면 늘이지 않고 가운데 두며 남는 곳은 검은색이고, 썸네일에 `여백`으로 표시한다.
- 드롭박스에서는 연결 루트 안의 폴더와 PPT·PDF만 보인다. 폴더는 이름순, 파일은 최근 수정한 것이 위이고 수정일을 함께 보인다. 종류별 크기 한도를 넘는 파일은 고를 수 없다(서버도 받기 전에 거절). PPT 창은 늘 `hanwoori/10예배온`에서 열고, 주보 창은 늘 `HANWOORI/06주보/주일주보`에서 연다.
- 교체는 버전 조건(CAS)으로 저장해, 그 사이 다른 곳에서 문서가 바뀌었으면 덮지 않는다. `확인`으로 다시 불러온 뒤 교체한다. 편집기에 그 문서의 저장하지 않은 변경이 있으면 시작하지 않는다. 그 문서를 쓰는 모든 예배에 같이 반영된다.
- 같은 이름의 새 문서가 이미 있으면 덮어쓰지 않는다. 409가 나면 복구 영역의 `새 문서 이름 → 이 이름으로 저장`을 쓴다(기본 제안: 기존 이름 뒤 `(PPT)`). 다시 변환하지 않는다.

## 지원 범위와 제약

- PPTX는 브라우저 OOXML 렌더러로, PPT는 바이너리의 구조·그림·텍스트·좌표를 읽어 정지 화면을 만든다. PowerPoint와 같은 렌더링 엔진이 아니다.
- 원본 폰트가 변환 컴퓨터에 없으면 이미지로 만들기 전에 대체 폰트가 쓰일 수 있다. 이미지화가 원래 렌더링 문제를 해결하지는 않는다. 저장된 PNG는 보는 기기의 폰트에 영향받지 않는다.
- PPT 마스터 장식, 특수 도형, 표, PPTX의 일부 벡터·SmartArt·효과, 애니메이션, 영상은 완전한 재현을 보장하지 않는다. 미리보기를 원본과 대조한다.
- 악보와 사진이 이미 한 그림으로 합쳐져 있으면 사진을 복원해 분리하지 않는다. 선택한 이미지가 불투명하면 경고한다. AI 배경 제거와 OCR은 쓰지 않는다. 흰 바탕만 사용자가 선택한 경우 투명하게 처리한다. 복잡한 사진·무늬 배경 분리는 지원하지 않는다.

## 저장과 복구

- PNG의 SHA-256을 기준으로 이미지를 등록한다. 저장 전에 hash를 80개씩 조회해 이미 올라간 이미지는 다시 보내지 않는다. 악보 PNG는 displayElements에 넣고, 나눈 배경은 문서에 넣지 않고 미디어로만 올린다.
- 이미지 업로드를 먼저 확인하며, 없는 이미지를 가리키는 문서는 저장하지 않는다. 문서와 미디어 참조는 같은 D1 batch와 CAS 조건으로 커밋한다.
- 이미지를 올린 뒤 서버가 교회 Mac 경로 `/Users/Shared/Renewed Vision Media/YebaeOn/<문서이름>-<n>.png`를 정해 이미지 경로표에 넣고, 문서에는 그 file URL을 적는다. 이미 같은 그림이 `YebaeOn/`에 있으면 그 경로를 다시 쓰고, 새 그림은 같은 이름의 다음 번호를 받는다. 배경 바꾸기는 `<문서이름> 배경-<n>.png`이다. Sync 2는 그 문서를 쓰는 예배를 [적용]할 때 Mac에 없는 이미지를 받아 둔다.
- 옛 표기 `file:///YebaeOn-Media/<sha256>.png`는 Studio 표시와 서버 저장에서 계속 읽는다. 이 표기로 저장된 운영 문서는 없다(10-04 확인).
- 가져온 문서의 준비 XML과 PNG는 작업자 이름별로 브라우저 IndexedDB에 보존되어, 실패하거나 새로고침한 뒤 같은 경로와 같은 내용으로 재시도한다. 보존에 실패하면(저장 공간 부족 등) 업로드를 시작하지 않고 그렇게 안내한다. 브라우저 저장소를 지우면 복구본도 사라진다.
- 저장된 이미지와 문서는 자동으로 롤백되지 않는다. `준비본 버리기`는 브라우저 준비본만 지운다.
- Sync의 슬라이드 번호는 1부터 시작한다. 기존 Mac 문서의 수동 참조 등록 방식은 그대로다.

## 비용

- 대기, 최초 진입, 모달 열기, 변환, 크롭: 새 D1 요청과 폴링이 없다. 변환은 로컬 CPU와 메모리를 쓴다. 말씀 PDF 탭을 열면 대상 문서 찾기(검색 1회·문서 조회·내용 1회)가 한 번 돈다.
- 드롭박스: 폴더를 열 때마다 목록 1회(세션 조회 + 드롭박스 호출), 파일을 고를 때 메타데이터·다운로드 1회. D1에 쓰지 않는다.
- 말씀 PDF 교체 한 번: 그림 N장 존재 조회(80개씩)·없는 것만 PUT·경로 정하기 1회·문서 PUT 1회(CAS). 문서 저장 비용은 일반 저장과 같다.
- 가져오기 한 번: 나눈 배경이 있으면 고유 배경 B개를 같은 방식으로 존재 조회·PUT하고 경로 정하기를 한 번 더 한다(새 경로마다 경로표·일지 1행, 미리보기 PUT B개). 재생목록에 넣으면 순서 저장 1회(일반 순서 저장과 같음). 고유 이미지 N개를 80개 단위로 존재 조회하고, 없는 것만 N개 이하로 PUT하며, 경로 정하기를 200개 단위로 한 번(조회 3·쓰기 2문장, 새 경로마다 경로표·일지 1행), 문서는 한 번 POST한다. 슬라이드 S개이면 일반은 최대 S개, 분리 악보는 최대 2S개다. 같은 배경과 같은 악보는 hash로 재사용한다. R2에 PNG 용량이 추가된다.
- 문서 저장: 가져온 이미지(`YebaeOn/` 경로나 옛 `YebaeOn-Media`)가 있을 때만 경로표 조회 1문장, hash의 PK 조회, 문서 버전별 참조 행 INSERT가 추가된다. 다른 Mac 경로만 있는 문서에는 추가 쿼리가 없다.
- 문서 열기: 화면에서 요구한 이미지 content 조회가 추가되고 같은 hash는 브라우저에서 재사용한다. 검색, 순서 저장, Sync 비교의 요청 빈도와 범위는 그대로다.
- 조회는 PK와 문서별 범위로 제한되며 전체 스캔이나 자동 색인은 없다.
