# 주보 준비와 Dropbox 연결

Studio에서 HWP 주보를 읽어 예배 순서 초안을 만드는 방법과, 교회 Dropbox 폴더를 Studio에 연결하는 관리자 설정을 정리한다.

## 주보로 준비

1. 상단 `주보·자료`에서 HWP 파일을 선택한다. 브라우저가 HWP 5의 압축 본문과 표 셀을 읽는다. AI·OCR·외부 변환 서비스는 쓰지 않고 주보 원본은 서버에 저장하지 않는다.
2. 1·2·3부 중 하나와 적용할 재생목록을 고른 뒤 `찬양 후보 찾기`를 누른다.
3. 정확히 같은 제목의 후보가 하나뿐이거나 이 브라우저에서 기억한 연결이 있으면 자동으로 선택된다. 찬송가 번호로도 검색한다. 후보가 여러 개이면 직접 고른다. 고정 순서도 연결하거나 체크를 해제한다. `부름의 찬양`처럼 제목이 없는 항목은 추정하지 않는다.
4. 기도·설교는 기본 글상자로 만들거나 `서식 찾기`로 기존 문서를 고르고 교체할 글상자를 지정한다. 문서 전체를 복제하고 고른 글상자만 바꾼다. 이름과 설교가 여러 글상자로 나뉜 복잡한 서식은 적용 뒤 편집한다. 설교자는 별도 항목이며 기본으로 제외된다. 필요하면 포함하거나 설교 제목에 함께 입력한다.
5. 말씀은 교회 개역개정 자료와 기본 말씀 템플릿으로 만든다. `생성 미리보기`에서 분할과 줄바꿈을 확인한다. 장절은 단일 절이나 연속 범위만 지원한다. 비연속 절은 나누어 추가한다.
6. `검수 완료 · 순서 초안에 적용`을 누르면 선택한 예배의 기존 순서 전체가 검수한 목록으로 바뀐다. 주보에 없는 특순은 나중에 추가한다. 기도·설교·말씀은 새 문서로 등록되므로 원본과 다른 예배는 바뀌지 않는다. 원본 서식의 나머지 슬라이드는 복제본에 남으므로 검수할 때 확인한다.
7. Studio에서 최종 검수한 뒤 `변경사항 저장`으로 순서를 확정한다. 저장 충돌은 기존 방식으로 보호된다. 다른 부는 주보 창에서 다시 선택해 진행한다.

### 중간에 실패하면

- 같은 화면에서 재시도한다. 생성 경로와 XML은 탭의 sessionStorage에 보존되어 새로고침 뒤에도 복구된다. 이미 성공한 문서는 다시 쓴다.
- 적용 전에 만든 새 문서는 서버에 생성되지만 순서는 저장 전까지 바뀌지 않는다. 중단하면 쓰지 않은 새 문서가 남을 수 있다. 전체를 하나의 트랜잭션으로 취급하지 않는다.
- 순서를 적용한 뒤에는 기존 IndexedDB 초안 복구를 쓴다.
- 파일 구성이나 예배 양식이 다르면 자동으로 추정하지 않고 오류나 검수 항목으로 남긴다.

## Dropbox 최초 연결 (관리자, 한 번)

각 이용자는 예배온에 입장하며 개인 Dropbox 인증을 요청받지 않는다. 소유자의 열람 권한으로 서버가 읽는다. 앱 연결이 취소되거나 폴더 권한을 잃으면 다시 설정한다.

1. https://www.dropbox.com/developers/apps 에서 Scoped access, Full Dropbox 앱을 만든다. 기존 공유폴더에 접근하려면 Full Dropbox가 필요하다.
2. Permissions는 `files.metadata.read`와 `files.content.read`만 켠다. 쓰기·삭제·공유 변경 권한은 쓰지 않는다.
3. 공유폴더가 소유자 계정에 추가되어 API 경로로 보이는지 확인한다. 링크만 받은 경우는 경로 방식으로 읽을 수 없다. 경로는 `/교회/주보`처럼 지정하고 계정 전체 `/`는 쓰지 않는다.
4. 저장소를 받은 본인 컴퓨터에서 Node 22 이상으로 `npm ci`, `npx wrangler login`을 한 뒤 `node scripts/connect-dropbox.mjs`를 실행한다.
5. App key, 폴더 경로, App secret을 입력한다. 표시된 승인 주소를 열어 한 번 승인하고 승인 코드를 입력한다. App secret과 코드는 화면에 표시되지 않는다. 스크립트가 폴더 읽기를 확인하고 네 값을 Worker secrets로 직접 전달한다. 채팅이나 GitHub에 토큰을 올리지 않는다.
6. Studio의 `교회 자료` 탭에서 폴더 탐색, 다운로드, HWP 주보 선택을 확인한다.

스크립트 대신 Cloudflare 대시보드에서 Worker 비밀값 `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_REFRESH_TOKEN`, `DROPBOX_ROOT`를 직접 등록해도 된다. access token만 등록하면 만료되므로 offline 승인으로 받은 refresh token이 필요하다.

### 보안

- 서버 세션을 확인한 뒤 지정한 루트 안의 상대 경로만 허용하고, 메타데이터의 실제 경로를 다시 검증한다.
- 페이지 커서는 서명하고 응답은 캐시하지 않으며 파일은 첨부 다운로드로 준다. API 토큰은 브라우저로 전달하지 않는다.
- 공유폴더 원본을 쓰는 API는 없다.

## 비용 영향

- 대기·초기 화면: 새 API 호출과 폴링·예약 작업이 없다. HWP 파서와 UI는 정적 자산이다.
- 주보 해석·수정·검수는 브라우저에서 처리한다.
- 후보 검색: 예배별 고유 검색어당 기존 문서 검색 최대 100건이며, 같은 검색은 화면 안에서 캐시한다. 부분 문자 검색은 문서 규모에 따라 스캔이 생긴다.
- 기억한 문서는 문서 ID별로 조회한다. 전체 문서 내용을 내려받거나 본문을 스캔하지 않는다.
- 적용: 선택한 동적 항목마다 문서를 새로 등록한다. 찬양 원본은 복제하지 않는다.
- Dropbox: 요청마다 세션 조회와 Dropbox 호출이 있다. 목록은 100개씩, 파일은 스트리밍이다. 목록과 파일 사본은 D1에 저장하지 않는다. 목록 새로고침은 클릭할 때만 수행한다.
