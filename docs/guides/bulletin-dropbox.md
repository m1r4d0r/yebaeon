# 주보 준비와 Dropbox 연결

Studio에서 HWP 주보를 읽어 예배 순서 초안을 만드는 방법과, 교회 Dropbox 폴더를 Studio에 연결하는 관리자 설정을 정리한다.

## 주보로 준비

상단 `주보로 준비` 창 맨 위 `드롭박스에서 가져오기`(늘 `HANWOORI/06주보/주일주보`에서 열고, 폴더는 이름순·파일은 최신순)나 `내 컴퓨터에서 추가`로 HWP 주보를 연다. 브라우저가 HWP 5의 압축 본문과 표 칸을 읽는다. AI·OCR·외부 변환 서비스는 쓰지 않고 주보 원본은 서버에 저장하지 않는다.

주보를 읽으면 단계마다 값을 미리 채운다(노란색). 오른쪽에서 칸을 고르고 왼쪽 주보에서 낱말을 누르면 채워진다. 처음 누르면 바꾸고 이어서 누르면 덧붙인다. `¶`는 줄 전체를 넣는다. 모바일에서는 칸의 `주보` 단추로 아래에서 주보를 올리고, 줄을 눌러 낱말 단추로 고른다. 모든 칸에 `넘어가기`가 있다.

1. **찬양**: 부별로 예배 전 찬양, 설교 후 찬양, 헌금 찬양. 검색어로 서버 문서 후보(분류 포함)를 보여 줄 뿐 자동으로 바꾸지 않는다. 같은 곡이 가사·악보 두 문서이거나 제목에 후렴 첫 줄이 붙어 이름이 다를 수 있으므로 사용자가 고른다. 고른 문서는 이 브라우저가 기억해 다음에 표시한다.
2. **기도**: 1·2·3부 기도자. 기도 문서의 ‘이름 직함’ 줄만 바꾼다.
3. **주일말씀**: 시리즈명·제목·본문, 대지 질문·문장·빈칸·인용구. 빈칸 답은 2쪽 말씀 요약(첫째·둘째·셋째)에서 찾아 제안한다. 요약이 없으면 비워 둔다.
4. **주중말씀**: 예배순서 표 맨 아래 칸의 첫 줄은 수요예배, 둘째 줄은 금요예배. 사역자 이름만 있거나 본문이 없는 행사면 넘어간다. 셋째 줄(새벽기도)은 다루지 않는다.
5. **검토·적용**: 재생목록과 문서별로 바뀌는 것을 본다. 체크를 끄면 뺀다. `적용`은 바뀐 문서(슬라이드 미리보기)와 순서(바뀐 줄 굵게)를 이 창에서만 만들어 보여 주고 서버에는 쓰지 않는다. 확인한 뒤 `서버에 저장`을 누르면 그때 서버의 최신 버전을 다시 읽어 같은 변경을 만들어 저장한다. 실패한 항목만 `다시 적용`으로 다시 한다.

### 양식이 바뀌어 추천이 틀릴 때

- 칸 하나는 언제든 직접 고친다. 칸을 고르고 주보에서 낱말이나 ¶(줄)을 누르면 추천과 상관없이 바뀐다. ‘전체 주보’를 켜면 표 전체에서 고를 수 있다.
- 구역을 잘못 짚었으면 구역을 지정한다. 주보의 칸마다 지금 단계에 맞는 단추가 붙는다. 누르면 그 칸을 기준으로 추천을 다시 뽑는다.
  - 찬양: ‘이 칸을 N부 찬양으로’ — 그 부의 예배 전 찬양 목록
  - 주일말씀: ‘설교 노트로’ — 제목(■ 줄)·대지·인용구. 질문 줄 형식이 달라도 번호 붙은 빈칸 문장 바로 앞줄을 질문으로 본다. ‘말씀 요약으로’ — 빈칸 답
  - 주중말씀: ‘주중예배 칸으로’ — 첫 줄 수요예배, 둘째 줄 금요예배
- 기도는 ‘가 / 나 / 다’처럼 셋으로 나뉜 줄의 ¶를 누르면 1·2·3부를 한 번에 채운다.

### 읽는 규칙

- 예배순서 표: ‘1부예배·2부예배·3부예배’ 머리칸이 있는 표. 부마다 자기 열을 덮는 칸을 읽는다. 표를 찾지 못하면 칸이 비어 있을 뿐 오류로 멈추지 않는다.
- 찬양: 신앙고백 다음부터. 사도신경 위의 부름의 찬양은 지난주 것을 그대로 쓴다. 설교 칸 뒤 첫 곡은 설교 후 찬양, ‘드림의 찬양’ 다음 곡은 헌금 찬양.
- 기도자: ‘/’로 셋으로 나뉘는 줄. 직함은 집사·권사·장로(시무·안수·은퇴·협동·원로·명예 포함)·형제·자매·목사·강도사·전도사·선교사 등.
- 설교: ‘책 장:절’로 시작하는 칸. 칸이 부별로 나뉘면 설교 묶음을 나눈다. 2부가 든 묶음은 `주일예배말씀`, 청년예배만이면 `청년부 말씀`, 1부만이면 `1부 말씀` 문서를 쓴다.
- 시리즈명: 쉼표 앞이 숫자로 끝날 때만 떼어 낸다(`기도 시리즈2, 응답하시는 하나님`). 아니면 쉼표까지 제목이다.
- 1쪽 ‘■’ 줄이 제목과 본문, ‘What?·How?·Why?’ 줄이 대지 질문, ‘1. …___…’ 줄이 대지 문장, 그 아래 ‘책장:절’로 시작하는 줄이 인용구. ‘=>’ 결단 문장은 쓰지 않는다.
- 성경: 한 장 안의 쉼표 절(`요13:36,37`, `막14:31,38-40`)을 받는다. 없는 장절은 어디서 끊겼는지 알린다.

### 무엇을 어디에 쓰나

| 대상 | 작업 |
|---|---|
| 1부 예배(첫 주일은 품성, 아니면 클래식)·2부 예배·청년예배 | 사도신경 다음 ~ N부 기도 앞의 찬양 영역을 고른 문서로 교체(하나 이상 고른 경우만). 말씀(목사님 ppt가 있으면 그 다음) 바로 뒤가 설교 후 찬양, 그다음이 헌금 찬양(청년예배는 고정이라 제외). 엔딩(`엔딩`·`마지막 화면`) 앞까지만 바꾼다. 부름의 찬양·목사님 ppt·헌금 뒤 곡은 건드리지 않는다. 설교 묶음에 따라 말씀 자리 문서를 바꾼다 |

- 순서 이름은 변형을 받는다: 기도는 `1부 기도`·`1부기도`·`2부 기도 v2`, 말씀 문서가 없고 `주일예배말씀 목사님 ppt`만 있으면 그것이 말씀 자리다. 자리를 찾지 못하면 경고 끝에 그 순서의 이름 목록을 보인다.
- 설교 후 찬양·헌금 찬양은 한 예배에서 고르면 아직 고르지 않은 다른 예배의 같은 자리에도 같은 곡이 들어간다(주보 글이 다르면 넣지 않음). 다르면 그 예배에서 바꾼다.
- 찬양 후보 검색은 이름과 본문(가사) 색인을 함께 보고 관련성순이다.
| N부 기도 문서 | ‘이름 직함’ 줄만 바꿔 새 버전으로 저장 |
| 주일예배말씀(·청년부 말씀·1부 말씀) | 제목 → 본문(절마다) → [제목 → 대지 → 인용구]×대지 수 → 제목으로 다시 구성. 문서 안의 기존 제목·말씀·대지 슬라이드를 서식으로 복제하므로 배경·글꼴이 이어진다. 대지는 n번째 대지 슬라이드 서식을 쓰고, 모자라면 마지막 대지 서식을 복제하고 알린다. 빈칸 답은 밑줄 |
| 수요예배·금요예배말씀 | 제목 + 본문으로 다시 구성 |

- 모든 문서 저장은 현재 버전 기준(If-Match)이고, 순서 저장은 예배 노드 기준이다. 다른 사람이 먼저 저장했거나 Studio에 저장하지 않은 변경이 있으면 그 항목만 멈춘다.
- 작업 중인 값은 탭의 sessionStorage에 두어 새로고침해도 이어 할 수 있다.

## Dropbox 최초 연결 (관리자, 한 번)

각 이용자는 예배온에 입장하며 개인 Dropbox 인증을 요청받지 않는다. 소유자의 열람 권한으로 서버가 읽는다. 앱 연결이 취소되거나 폴더 권한을 잃으면 다시 설정한다.

1. https://www.dropbox.com/developers/apps 에서 Scoped access, Full Dropbox 앱을 만든다. 기존 공유폴더에 접근하려면 Full Dropbox가 필요하다.
2. Permissions는 `files.metadata.read`와 `files.content.read`만 켠다. 쓰기·삭제·공유 변경 권한은 쓰지 않는다.
3. 공유폴더가 소유자 계정에 추가되어 API 경로로 보이는지 확인한다. 링크만 받은 경우는 경로 방식으로 읽을 수 없다. 경로는 `/교회/주보`처럼 지정한다. 전체 Dropbox를 탐색하려면 `/`를 입력한다. 전체 모드에서는 예배온 이용자가 연결 계정으로 열람 가능한 전체 폴더를 볼 수 있다. 읽기 전용은 동일하다.
4. 저장소를 받은 본인 컴퓨터에서 Node 22 이상으로 `npm ci`, `npx wrangler login`을 한 뒤 `node scripts/connect-dropbox.mjs`를 실행한다.
5. App key, 폴더 경로, App secret을 입력한다. 표시된 승인 주소를 열어 한 번 승인하고 승인 코드를 입력한다. App secret과 코드는 화면에 표시되지 않는다. 스크립트가 폴더 읽기를 확인하고 네 값을 Worker secrets로 직접 전달한다. 채팅이나 GitHub에 토큰을 올리지 않는다.
6. Studio `주보로 준비` 창 맨 위 `드롭박스에서 가져오기`로 폴더 탐색과 HWP 주보 선택을 확인한다. `PPT 추가` 창도 같은 시작 줄과 같은 루트를 쓴다([PPT·PDF 가져오기](ppt-import.md)). 다운로드 전용 목록(옛 `교회 자료` 탭)은 없앴다.

스크립트 대신 Cloudflare 대시보드에서 Worker 비밀값 `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_REFRESH_TOKEN`, `DROPBOX_ROOT`를 직접 등록해도 된다. access token만 등록하면 만료되므로 offline 승인으로 받은 refresh token이 필요하다.

### 보안

- 파일 받기에 `max`(바이트)를 주면 메타데이터 크기가 넘을 때 받지 않고 413으로 거절한다. 가져오기 창이 쓴다.
- 서버 세션을 확인한 뒤 지정한 루트(전체 모드는 계정 루트) 안의 상대 경로만 허용하고, 메타데이터의 실제 경로를 다시 검증한다.
- 페이지 커서는 서명하고 응답은 캐시하지 않으며 파일은 첨부 다운로드로 준다. API 토큰은 브라우저로 전달하지 않는다.
- 공유폴더 원본을 쓰는 API는 없다.

## 비용 영향

- 대기·초기 화면: 새 API 호출과 폴링·예약 작업이 없다. HWP 파서와 UI는 정적 자산이다.
- 주보 해석·수정·검수는 브라우저에서 처리한다.
- 후보 검색: 찬양 칸을 열 때 그 검색어로 한 번(같은 검색은 화면 안에서 캐시). 대상 재생목록 순서(plan)는 필요할 때 한 번씩 읽는다.
- 적용: 고른 문서 수만큼 문서 읽기·저장, 바뀐 재생목록마다 순서 저장 한 번. 찬양 원본은 복제하지 않는다.
- Dropbox: 요청마다 세션 조회와 Dropbox 호출이 있다. 목록은 100개씩, 파일은 스트리밍이다. 목록과 파일 사본은 D1에 저장하지 않는다. 목록 새로고침은 클릭할 때만 수행한다.

전체 모드는 목록 100개 단위·클릭한 폴더만 조회하며 계정 전체를 재귀 스캔하지 않는다. 같은 클릭 수에서 D1 조회/쓰기 범위와 빈도는 이전과 같다. 실제 계정 연결은 별도 확인한다. 기존 Full Dropbox 승인으로 연결한 경우 Cloudflare의 `DROPBOX_ROOT`만 `/`로 바꾸면 되며 재승인이 필요하지 않다.
