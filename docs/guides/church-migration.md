# 교회 Mac 전환 절차

0.6.6 앱에서 Sync 2로 한 번만 넘어가는 순서다. 서버 편집본을 지키는 것이 최우선이다.

## 현재 상태

- 서버: 문서 장부 2,884개와 원본 2,884개가 모두 있다. 재생목록 `기본 .pro6pl`은 활성 8개, 보관 7개다.
- Mac 문서 폴더는 정리본 그대로다. 0.6.6의 `state.json`은 참고하지 않는다.
- Sync 2 1차(받기 전용)의 받기는 확인되었다. 올리기·이미지·상주 모드는 2차 범위다.
- 0.6.6 앱은 더 쓰지 않는다. 켜기만 해도 재생목록 자동 PUT이 일어날 수 있다. `Mac 내용 사용…`과 `서버 다시 맞추기`는 쓰지 않는다. 서버는 `X-YebaeOn-Sync: 2` 머리글이 없는 재생목록 전체 PUT을 426으로 거절한다.

## 단계

| 단계 | 할 일 | 다음으로 가기 전 확인 |
|---|---|---|
| 1. 복사 | 교회 Mac에서 문서 폴더와 재생목록 파일을 통째로 복사해 운영 폴더 밖에 둔다. | 파일 수와 크기 기록. 일부를 다시 열어 봄 |
| 2. 이미지 (집 PC) | 아래 "이미지 올리기"를 따른다. 문서 작업과 별개로 한 번 한다. | `scan` 보고 숫자 기록. `upload` 완료 |
| 3. Sync 2 2차 설치 | 2차 설치본을 설치한다. 0.6.6 앱과 프로필 폴더는 그대로 둔다. | 앱이 켜지고 서버에 연결됨 |
| 4. 처음 연결 | 문서 2,884개를 한 번 전부 해시하고 50개씩 서버 manifest와 대조한다. 같음은 영수증에 적고, 서버에 원본이 없는 것은 올리기 큐에 넣고, 다름은 서버본을 받고 Mac 바이트는 보관본으로 남긴다. 재생목록 노드는 의미 지문을 비교하며 다르면 서버 노드를 적용하고 Mac 노드는 보관본으로 남긴다. 확인 목록을 보고 `적용`을 누른다. | 같음·없음·다름 수를 기록. 서버에 원본이 모두 있으므로 없음 0이 정상 |
| 5. PP6 실기 | PP6에서 활성 예배를 열어 순서·배경·찬양 연결을 확인하고 닫는다. 아래 "PP6 확인"을 본다. | 문제가 있으면 멈춤 |
| 6. 올리기 | Mac에서 문서 하나를 고쳐 올리고, 올린 직후 다시 실행한다. | 받을 것·올릴 것이 0, 서버 요청 1회 |
| 7. 상주 모드 | 상주를 켠다. 웹에서 수요·금요예배를 저장해 본다. | 15분 안에 준비되고, PP6가 꺼져 있으면 자동 적용됨 |
| 8. 마무리 | 0.6.6 앱과 프로필은 보관한다. 서버의 옛 inventory·관측·참조 표와 API는 사용자 승인 뒤에 지운다. | 승인 전에는 지우지 않음 |

### PP6 확인

- `filePath="~/Documents/ProPresenter6/…"` 형식의 큐를 여는가.
- 송출만 하고 닫을 때 `.pro6`·`.pro6pl`을 다시 저장하는가. 저장하면 RTF·UUID·미디어 경로 중 무엇이 바뀌는가.
- Studio에서 저장한 문서를 열고 저장한 뒤에도 의미 지문이 그대로인가. 노드 지문이 같으면 변경으로 보지 않는다.

## 이미지 올리기 (집 PC)

1. 교회 Mac의 문서 폴더와 `/Users/Shared/Renewed Vision Media/Images`, `…/ImportedImages`를 그대로 복사해 온다. 폴더 구조와 파일명(NFD 포함)은 바꾸지 않는다. `YebaeOn/`(서버가 채움)·`PasteBoardImages`·영상·오디오는 가져오지 않는다.
2. `node bulk-media.mjs scan --docs <문서 폴더> --media <복사한 미디어 폴더>`로 참조를 모은다. 보고 항목은 찾음, PasteBoardImages(제외), 허용 폴더 밖, 원본 없음(268 안팎), 빈 경로(29)다. 마지막 둘은 Mac에서도 깨진 참조이므로 목록만 남긴다.
3. `upload`로 올린다. 같은 바이트는 한 번만 올리고, 다시 실행하면 끝난 것은 건너뛴다.
4. 서버에 경로표 등록 API(`PUT /api/media/paths`)가 배포된 뒤 `--register`로 경로표를 등록한다.

서버와 교신하는 이미지 폴더는 `/Users/Shared/Renewed Vision Media/` 아래 세 개뿐이다.

| 폴더 | 내용 | 방향 |
|---|---|---|
| `Images/` | PP6에서 직접 넣은 이미지 | Mac → 서버, 서버 → Mac(없을 때만) |
| `ImportedImages/<PPT폴더>/` | PP6의 PPT 가져오기 산출물 | 같음 |
| `YebaeOn/` | 웹(Studio)에서 가져온 이미지 전용 | 서버 → Mac. Mac에서 손대지 않음 |

- 경로 키는 NFC로 맞춘 Mac 절대경로다.
- 경로표에 없는 경로는 건드리지 않는다. 경로표에 있고 Mac에 없으면 허용 폴더 안에서만 받고, sha를 확인해 임시 이름으로 쓴 뒤 바꾼다.
- Mac에 있으면 sha256을 비교한다. 다르면 덮지도 사본을 만들지도 않고 "확인 필요 · 내용이 다른 이미지"로 보고한다.
- 이미지가 없어도 문서는 적용하고 그 예배를 "적용됨 · 이미지 n개 없음"으로 표시한다. 완료가 아니다.
- `YebaeOn/` 폴더가 없으면 Sync 2가 첫 적용 때 만든다.

## 중단했을 때

- 처음 연결 중 중단: 다시 실행한다. 영수증에 적힌 파일은 stat이 같으면 다시 해시하지 않는다.
- 적용 도중 꺼짐: 다음 실행에서 회차 기록을 보고 끝까지 마무리한다. 그 사이 사용자가 고친 파일은 건드리지 않고 보류로 남긴다.
- 되돌리기: 마지막 회차의 백업을 제자리로 이름 바꾸고 영수증을 회차 이전으로 돌린다. 적용 뒤 PP6에서 고친 파일은 되돌리지 않고 알린다. 되돌린 항목은 다음 동기화 때 다시 "받을 것"으로 나온다.
- 영수증 소실·손상: 메뉴의 전체 검사로 다시 만든다. 장치 id는 그대로다.
- 이미지 올리기 중단: `upload`를 다시 실행한다. `--register`만 다시 실행해도 된다.
- 설치 후 확인 실패: PP6와 Sync를 종료하고 1단계의 복사본으로 Mac 파일을 복구한다. 0.6.6이나 옛 파일로 전체 업로드하지 않고 서버 상태를 먼저 확인한다.
- 서버 문서 복원: 문서별 보존 버전이나 단계 1의 복사본으로 CAS 복원한다.
