- 10차(10-05): 주중 말씀은 첫 말씀 장 앞의 표지를 맨 앞에 남김, 주보 창 단추를 `미리 보기` → `적용`으로 바꾸고 적용이 모두 성공하면 창을 닫음, 전후 슬라이드 비교를 모바일에서도 가로 스크롤 한 줄로.
- 11차(10-05): 주보 `적용`은 서버에 쓰지 않는다. 바뀐 문서·순서를 Studio 미저장 상태(브라우저 초안)로 넘기고 해당 재생목록에 `· 저장 필요`를 붙인다. 서버 저장은 그 재생목록을 열어 `서버 저장`으로 한다.
- 12차(10-05): `서버 저장` 한 번으로 이 탭의 모든 미저장 문서·순서를 저장(열지 않은 재생목록 초안도 노드 sha 기준으로 올림, 문서 실패 시 순서는 보류). 손으로 고친 재생목록에서 다른 재생목록으로 갈 때 ‘저장하고 넘어갈까요?’를 묻고, 취소하면 `저장 필요`로 남긴다. 주보로 넘긴 것만 있을 때는 묻지 않는다.
- 13차(10-05): 저장 충돌 정책 변경. 문서는 막은 뒤 최신 불러오기(내 편집 버림)·사본으로 저장·나중에를 묻는다. 순서는 막지 않고 내 순서로 덮어쓴 뒤, 직전 서버 순서와 비교해 빠진·다시 들어간·되돌린 항목과 순서 바뀜을 저장 결과 창으로 알린다.
- 14차(10-05): 충돌로 만든 사본을 원래 문서 바로 아래에 넣어 함께 저장. 개발자도구 콘솔에 배포 번호·커밋·빌드 시각과 CHANGELOG 최근 5줄을 표시(`build-info.js`, 빌드가 생성).

## PPT 가져오기 저장 방식 (10-05) — main 1d64fdf, Deploy run 37312404459 성공(사용자 승인)

- `선택한 재생목록 맨 아래에도 추가`를 켜면 문서 추가 직후 그 순서도 서버에 저장한다(전에는 초안으로 남아 서버 저장 필요). 주보 `적용`은 맨눈 검수를 위해 그대로 초안이다.
- 악보찬양 새 문서에서 악보를 나눈 장의 배경(바탕·배경 그림·장을 덮는 불투명 그림)을 같은 그림은 하나로 모아 미디어 `YebaeOn/<문서이름> 배경-<n>.png`로 올리고 미리보기 그림도 만든다. 한 가지 색뿐인 배경은 올리지 않는다. 문서에는 넣지 않는다(악보만 투명). 배경 올리기가 실패해도 문서 추가는 유지하고 상태 줄에 알린다.
- 검사: Node 85개, 브라우저 7종(`ppt-import`에 사진 배경 장·순서 저장·배경 경로·미리보기 확인 추가), `deploy:check` 통과. 실제 교회 악보 PPT로는 아직 확인하지 않음.
