# 예배온 Sync 다음 세션 작업 지시·인계

기준: 2026-10-02 21:08 한국 시간. 이 문서의 최신 사용자 지시가 과거 계획의 자동 검사·서버 정본 복구 절차보다 우선한다.

## 1. 가장 먼저 지킬 지시

1. **GitHub Actions를 실행하지 않는다.** 무료분 소진을 사용자가 보고했다. 수동 실행, 실패 재실행, `verify-mac` 라벨 부착/재부착을 하지 않는다. 푸시·PR·병합의 자동 실행 조건도 먼저 확인한다. 웹 검사도 예외가 아니다.
2. 사용자의 Mac에서 직접 빌드·GUI 확인한다. Mac 검사 재개는 예상 차감량·실행 횟수를 제시하고 별도 명시적 승인을 받은 경우만 가능하다. 유료 결제·예산 증액·저장소 공개 전환은 승인되지 않았다.
3. 시작 전 `AGENTS.md`, `docs/CROSS-PLATFORM-LESSONS.md`, `docs/SESSION-HANDOFF.md`, 이 문서와 `docs/SYNC-STUDIO-FOLLOWUP-PLAN.md`를 읽고 main 및 PR #22의 최신 상태를 확인한다. 다른 세션 변경을 덮어쓰지 않는다.
4. 보고는 한국어. 실패는 증상 → 확인된 원인 → 해결 → 재검증 → 남은 일 순서. 작성 완료·컴파일 성공·자동 검사 성공·교회 실기 성공을 구분한다.
5. 모든 수정에서 D1 읽기/쓰기와 반복 호출 영향을 검토한다. 비용 측정용 운영 부하 시험, 새 폴링·전체 반복 색인을 도입하지 않는다.

### 반드시 먼저 고칠 알려진 오류

Mac CI 37001417118 및 37001879863은 엔진/앱 빌드 후 GUI 검사에서 exit139(segfault)로 실패했다. 두 번째 로그는 APP CHECK75 다음에서 종료된다. **확인된 코드 원인은 `YBServerPlaylistsController.m`의 `updateReceiveAll` 끝에서 자기 자신을 무조건 재호출하는 것**이다. 재귀로 스택이 소진된다. 두 번째 커밋의 presentation 재진입 가드는 이 오류를 해결하지 못했다.

아래 수정은 이전 세션의 로컬 작업본에만 있고 원격 PR에는 아직 없다. 다음 세션에서 먼저 반영한다.

```objc
// updateReceiveAll 끝: 자기 호출을 제거한다.
self.receiveAllButton.enabled=count>0 && !self.work.busy;
// 여기에 [self updateReceiveAll]; 을 넣지 않는다.

// acceptComparison: 끝: 선택한 비교를 반영한 뒤 전체 받기 상태도 갱신한다.
self.receiveButton.enabled=[result[@"ready"] boolValue]
    && (changed+added || [result[@"orderChanged"] boolValue]) && !self.work.busy;
[self updateReceiveAll];
```

수정 후 Mac 재검증은 **아직 하지 않았다**. 같은 실패 실행을 성공으로 표시하거나 현재 브랜치를 그대로 사용자에게 실행시키지 않는다. 기존 운영 앱에는 이번 UI 코드를 반영하지 않았다.

## 3. 교회 Mac 직접 빌드

사용자가 확인한 환경:

```text
macOS High Sierra 10.13.6
Apple LLVM version 10.0.0 (clang-1000.10.44.4)
Target: x86_64-apple-darwin17.7.0
InstalledDir: /Library/Developer/CommandLineTools/usr/bin
```

Command Line Tools가 이미 설치돼 있다. 최신 Xcode나 OS 업그레이드를 먼저 요구하지 않는다. 수정된 소스를 별도 폴더에 준비하고 저장소 루트에서:

```bash
bash mac-app/build.command
```

결과: `mac-app/build/예배온 Sync.app`. 앱 빌드는 clang 및 Mac 기본 도구로 진행되며 Node/Python/Wrangler 설치는 필요 없다. GitHub Actions 사용량은 없다. 구형 컴파일러에서의 실제 성공은 아직 확인하지 않았다. 오류가 나면 터미널 출력을 받아 수정한다. 빌드만으로 운영 문서·서버를 변경하지 않는다. 기존 앱은 새 앱 검증 전 교체하지 않는다.

**앱 실행은 다르다:** 기존 시작 동작에 서버 비교·inventory 보고·조건부 원본 등록/갱신이 있다. 새 앱을 무심코 운영 폴더로 실행해 진단 전 서버를 변경하지 않도록, 격리된 합성 자료의 UI 검사부터 준비한다.

`mac-app/test.command`는 GUI 검사 이후 Node 기반 Worker 통합 검사도 실행한다. High Sierra에서 이 스크립트 전체가 준비돼 있다고 가정하지 않는다. 기존 스크립트의 GUI 컴파일/실행 구간을 분리한 로컬 검증 경로를 만들고, Worker 검사는 적절한 로컬 Linux 환경에서 수행하는 방안을 사용한다. 테스트 환경설정·키체인·원본은 운영과 격리한다.

## 4. 지금 해결할 실제 사용자 문제

금요예배에서 말씀은 ‘문서 변경 · 받기’이고 수정1/새문서0이지만, 재생목록은 ‘확인 필요’로 전체 받기가 막혔다. 화면 문구:

> Mac 재생목록도 수정됐거나 최초 기준이 없습니다. 원본 파일을 등록한 Mac에서 비교해 주세요.

개별 말씀 문서를 받으려 해도 전체 비교에서 멈춰 사용할 수 없었다. 실제 로컬 수정, PP6 내부 정보 변화, 공통 기준 누락 중 무엇이 결정적 원인인지는 **로컬 원본·기준 기록·서버본을 아직 대조하지 않아 미확정**이다. 전체 비교가 멈춘 구체 단계/원인도 미확정이다.

사용자는 시간이 없어 교회 Mac에서 필요한 작업을 전부 다시 했다. **이번 정리는 현재 로컬 Mac의 재생목록·문서를 기준으로 서버를 맞추는 것으로 승인했다.** 오늘 Studio 작업을 서버 이력에서 복원하는 옛 제안은 폐기한다. 평상시 서버 정본 정책은 별개로 유지한다.

실제 경로(이름의 공백·한글을 바꾸지 말 것):

```text
/Users/procg/Documents/ProPresenter6
/Users/procg/Library/Application Support/RenewedVision/ProPresenter6/Playlists/기본 .pro6pl
```

### 진단과 기준 재설정 순서

1. Mac의 현재 목록19개, 선택된 파일/폴더, 문서·재생목록 동기화 기준, 중단 작업 여부를 읽기 전용으로 수집한다. 진단 도구는 아직 작성/전달되지 않았다.
2. 비밀번호·세션·키체인을 수집하지 않는다. 기준 기록은 `~/Library/Application Support/YebaeOn Sync/<프로필 해시>/state.json`, `playlist-state-<경로 해시>.json`, `playlist-active.json` 등의 실제 존재 여부를 확인한다. 프로필 해시를 임의로 추정하거나 전체 설정 폴더를 무차별 업로드하지 않는다.
3. 변경 전 로컬 원본과 기준 기록을 백업한다. PP6/Sync의 진행 작업을 확인하고 원본이 바뀌는 중에는 스냅샷/적용을 진행하지 않는다.
4. 서버의 현재 버전·해시와 대조해 변경 대상 계획을 만든다. 서버 덮어쓰기 승인은 DB 초기화·자료/과거 이력 일괄 삭제·기준 파일 삭제 승인이 아니다.
5. 필요한 범위의 문서/순서를 버전 CAS로 갱신하고 저장된 내용·해시를 확인한 뒤 로컬 기준을 연결한다. 업로드 실패나 모호한 응답 상태에서 기준만 ‘일치’로 바꾸지 않는다. 중간 실패 후 완료분/미완료분을 구별한다.
6. 다시 비교해 실제 불일치와 공통 기준 누락이 해소됐는지 확인한다. 이력 보관이 꺼진 문서는 서버의 기존 정책에 따라 과거본 보존이 제한될 수 있으므로 ‘전부 서버 이력에 남는다’고 보장하지 않는다.

### 의미 없는 변경 판정

- 삽입/삭제 때문에 번호만 밀린 항목을 이동으로 오인하지 않는 수정은 이미 반영됐다.
- 사용일·경로만 바뀐 문서를 실제 송수신에서 동일하게 보는 처리는 아직 없다. 현재 원본 SHA 판정을 사용한다.
- 실제 내용 변화 판정과 전송 무결성 검증을 분리할 필요가 있다. 본문만 비교해 미디어·배치·arrangement·전환 같은 중요한 변경을 무시하지 않는다. 필드별 비교 규칙과 검증 자료가 먼저다.
- 구버전 기준 보완은 현재 전체 원본이 과거 등록 원본과 같다는 증명이 있을 때만 가능하다. 기록을 무작정 지우면 해결되지 않는다.

### 전체 비교 때문에 작업이 막히는 문제

- 기존 0.6.0은 재생목록+연결 문서 우선, 나머지 백그라운드 점검이며 명시적 작업이 백그라운드를 취소하도록 설계돼 있다. 실제로 어느 경로에서 막혔는지 확인한다.
- 이번 PR의 ‘일시중단’은 작업을 보유하므로 중단한 채 다른 작업을 할 수 있다는 뜻이 아니다.
- 전체 비교를 안전하게 취소/양보하고 필요한 문서 또는 예배의 최신 상태만 확인해 작업할 수 있는 경로가 필요하다. 부분 비교 결과를 전체 비교 완료로 표시하지 않는다. 파일 적용을 동시에 실행하지 않는다.

## 5. 새로 승인한 재생목록 보관 요구

재생목록19개 중 거의 쓰지 않거나 연1회 사용하는 목록을 서버에 보관하고 Mac에서 제거해 시작 로딩/비교를 줄이고 싶다. **어떤 목록을 보관할지는 아직 선택받지 않았다.** 이름·사용일로 임의 선정하지 않는다. 19개 전체 목록도 이 세션에서 아직 확보하지 못했다.

구현 방향:

- Studio에 ‘사용 중 / 보관’ 구분과 복원 제공. 보관 목록은 기본 목록 및 Sync 시작 비교에서 제외한다.
- 이번 로컬 기준 재설정과 보관을 연계한다. 최신 로컬 순서와 필요한 자료가 서버에 보존됐는지 확인 → 로컬 백업 → 선택한 예배 노드만 Mac 재생목록에서 제거 → 결과/기준 검증 순서다.
- **현재는 Mac 전체 .pro6pl의 단방향 자동 PUT 갱신 경로가 있다.** 보관 구현 전에 Mac에서 먼저 삭제하면 서버 현재 목록에서도 빠질 수 있다. 단순 화면 숨김만 추가해서 완료하지 않는다.
- 서버 보관 자료를 로컬 활성 목록 전체 PUT과 분리해 보존한다. 예배 ID 기준으로 병합하고, 구버전 Sync가 보관 상태를 이해하지 못하는 경우의 읽기/쓰기 호환성 보호도 설계한다. 제거가 다시 추가로 보이거나 보관 예배가 자동 복원되는 순환을 막는다.
- 공유 문서 파일은 예배 제거와 함께 삭제하지 않는다. 보관한 순서의 당시 문서 내용까지 고정할지, 현재 공유 문서를 참조할지는 미확정이다. 서버 문서 이력 끔 정책과 보존 요구가 충돌하지 않도록 구체화한다.
- 복원 시 필요한 문서·미디어를 검증한 뒤 Mac에 순서를 추가한다. 보관된 자료는 추후 미참조 미디어 정리에서 보호한다.
- 비용: 시작 plan 호출은 19개에서 활성 예배 수 A개로 줄이는 것이 목표. 활성5개라면 예배별 plan은19→5회이나 이는 D1 전체 비용74% 절감 보장이 아니다. 인증·공유 문서·목록·남은 전체 문서 점검 비용은 별도다. 전체 문서 백그라운드 조회가 그대로면 그 비용은 남는다. 필터를 서버 단계에 적용하고 보관 목록을 매번 모두 읽지 않도록 인덱스/페이지 범위를 검토한다.

아직 서버 보관 기능·로컬 제거·기준 재설정은 구현 또는 실행되지 않았다. 사용자의 데이터 삭제는 전혀 수행하지 않았다.

## 6. 미디어 후속 과제 — 이번 긴급 정리 뒤

- 활성 재생목록에 연결된 문서의 참조 미디어 업로드, 내용 해시로 중복 제거.
- Studio에서 사용한 새 미디어도 예배 받기에서 내려받고 로컬 경로 연결. 미디어 검증 후 문서·순서 적용.
- 미디어 자체 버전 이력은 불필요. 완료 파일을 기억하는 전송 재개는 별도 구현 필요.
- 미참조 정리에 유예 기간과 보관 고정 태그/폴더를 두고 재사용 이미지와 보관 예배의 자료를 보호. 구체 기간은 미정.
- 현재 미디어 탭은 로컬 누락/중복 후보 점검뿐이며 자동 송수신은 없다.

## 7. UI 유지 제약·완료 기준

- High Sierra10.13.6, 기존 NSButton/NSTableView/NSSearchField/NSPopUpButton/NSSegmentedControl/NSProgressIndicator/시트만 재배치. 프레임 방식과 최소880×620 유지.
- SF Symbols, NSSwitch, NSControlSizeLarge, 다크/강조색 API, NSTableView style, NSGridView, Auto Layout/NSStackView 전환, 새 NSSplitView, Swift, 커스텀 버튼 금지.
- 주요 둥근 버튼은 폭150이상·굵은 제목. 기본 Return 버튼은 하나, 설정 시트에서는 닫기가 기본. 작은 창의 한글 잘림·겹침·작업 잠금·기본 버튼 이동 검증.
- 재생목록/문서/비교 전/설정 시트 PNG를 실제 Mac에서 만들고 다운로드 가능하게 전달. 합성 목표 그림을 앱 실행 캡처로 대신하지 않는다.
- 새 앱 설치본과 안전한 소스 빌드 절차 제공. 운영 PP6 재열기·순서·본문·배경 확인은 사용자 실기 단계로 명시한다.

## 8. 다음 세션의 실행 순서와 현재 중단점

1. 최신 코드/병렬 세션/Actions 트리거 확인. 위 자기 재귀 오류 수정 반영. Actions0회 유지.
2. 읽기 전용 Mac 진단 자료 수집 절차 준비·전달, 19개 목록과 기준 기록 확보. **사용자에게 보관할 목록을 선택받는다.**
3. 진단 결과로 로컬 기준 서버 갱신 및 보관 상태/전체PUT 호환성 계획을 구체화. 원본 백업과 대상 확인 후 적용 기능 구현.
4. 필요한 작업을 전체 비교와 분리하고 취소/일시중단/재개 의미를 명확히 구현. 의미 비교는 검증 자료와 범위를 먼저 정한다.
5. 로컬 검사 → 사용자 Mac 빌드/격리 GUI 검사 → 실제 선택 대상 검증. 서버 API 변경은 현재 배포 연결과 Actions 자동 조건을 확인한 뒤 비용 없는 적절한 배포 경로를 정한다. Cloudflare Git 연결과 GitHub Wrangler 배포가 중복인지 이 세션에서는 확인하지 않았다.
6. 검증된 결과만 main/설치본에 반영하고 계획서·실패 이력 갱신. 미디어는 후속.

이번 인계 저장은 문서 작업이다. 진단 도구·보관 기능·서버 데이터 정리·Mac 새 빌드는 아직 미완료이며, 사용자의 실제 원본 파일이 없어 다음 진단에는 Mac에서의 자료 수집이 필요하다.
