# 예배온 Sync 0.6.6 · 쓰지 않는 앱

**이 앱은 더 쓰지 않는다.** 재생목록 비교에 쓰면 서버 편집본을 덮을 수 있어 서버가 전체 PUT을 426으로 거절한다. 현행 앱은 [예배온 Sync 2](../mac-sync2/README.md)다. Sync 2가 자리 잡으면 이 폴더를 지운다(단, `YBPlaylistIO.m`·`YBPlaylistFormat.m`·`assets/SyncIcon-1024.png`는 Sync 2 빌드가 쓰므로 먼저 옮긴다). 아래는 0.6.6 당시 안내다.

사용자가 제공한 `PP6-Playlist-Sync-Native-v0.2.zip`의 `main.m`을 기반으로 기존 재생목록 화면에 문서와 미디어 탭을 연결했다. High Sierra 10.13을 대상으로 빌드한다. 기존 앱을 새로 구현한 것이 아니라 재생목록 비교·선택 적용 코드를 옮기고 Core 및 서버 송수신 엔진을 연결한 버전이다. [출처](ORIGIN.md).

## 실행

로컬 개발 묶음의 `app/YebaeOn-Sync-macOS.zip`에는 Mac 자동 검사에서 빌드한 `예배온 Sync.app`이 들어 있다. Mac에서 압축을 풀어 실행한다. **기존 `PP6 Playlist Sync.app`과 백업은 보관**하고 시험 중에는 이전 앱을 종료한다. 새 앱의 이름과 식별자가 달라 기존 앱을 덮어쓰지 않는다. 개발용 서명이므로 다운로드한 앱 실행이 차단되면 Finder에서 앱을 우클릭하고 `열기`를 선택한다.

직접 빌드할 때는 저장소 또는 묶음의 `source/`에서 다음을 실행한다. Finder에서 `mac-app/build.command`를 열어도 된다.

```bash
bash mac-app/build.command
```

결과는 `mac-app/build/예배온 Sync.app`이다. Apple Command Line Tools의 `clang`만 필요하며 교회 실행에 Node.js·Python·Wrangler는 필요 없다. 기존 Core와 개별 송수신 도구는 `mac-sync/`에 유지한다.

## Sync 0.5.2 build 10 · 재생목록 자동 비교

- 실행/서버 비교 때 저장된 Mac 원본 `.pro6pl`과 서버의 같은 이름을 확인한다. 서버가 비어 있으면 원본 파일을 등록하고 문서 참조는 별도로 비교한다.
- 공통 기준이 있고 Mac 파일만 바뀐 경우 서버 버전 조건을 확인해 새 버전으로 보낸다. 서버만 바뀌면 기존 백업을 거치는 받기 화면에서 확인한다. 양쪽 변경, 다른 파일 이름, 공통 기준이 없는 경우 자동 덮어쓰지 않고 상태를 표시한다.
- 이 동작은 **새 앱 설치 후 실행할 때** 적용된다. 기존 0.5.1 앱은 자동 업데이트되지 않는다. 최초 서버 등록 전에는 Mac의 저장된 `.pro6pl` 경로가 실제 운영 파일인지 확인한다.

## Sync 0.5.0 build 8

- 위 연결 막대에서 문서 폴더와 `.pro6pl` 경로를 확인·변경한다. 입장/로그아웃은 앱 메뉴, 최초 원본 등록은 파일 메뉴다.
- 재생목록·문서·미디어 세 탭을 제공한다. 로컬 파일끼리 비교하는 기존 도구는 **도구 → 로컬 재생목록 비교**에 유지했다.
- 실행 시 문서 비교에 이어 서버 재생목록을 자동 비교한다. 예배 목록에서 하나를 고르면 받기 전 문서 변경과 순서를 확인할 수 있다. 공유 문서는 한 비교 안에서 읽은 해시를 재사용하며 적용 직전 다시 검증한다.
- **파일 vN**은 선택한 예배만이 아니라 `.pro6pl` 전체 버전이다. Mac도 바뀌거나 기준을 판단하지 못하면 받기를 차단한다.
- 문서 탭은 받기/보내기 방향을 선택한 다음 검색·참조 필터에 보이는 항목만 전체 선택한다. 기본 순서는 PP6 최근 사용일이며 Mac 수정일·서버 저장일은 별도 열이다. 목록의 ⌘A와 Shift/⌘ 행 선택, 더블클릭 내용 비교를 지원한다.
- 최대 4개 병렬 업로드와 전송 중 잠자기 방지를 유지한다. 완료 개수와 마지막 성공 시각을 표시하며 실패 후에는 다시 비교해 남은 문서를 선택한다. 앱 강제 종료/네트워크 단절까지 막지는 않는다.
- **복구 기록**은 완료된 받기 작업 10회를 보관하고 중단·구버전 기록을 추가 보존한다. 문서 작업은 작업 전체를 먼저 검사하고, 이후 변경 파일이 있으면 시작하지 않는다. 작업 도중 비정상 종료되면 기록에서 복구를 재시도한다. 재생목록 받기는 해당 문서와 선택 순서를 함께 복구한다. 원자적 전체 교체를 의미하지 않는다.
- 순서에서 제거한 문서는 디스크에서 지우지 않는다. 반면 받기 작업을 되돌릴 때 그 작업에서 새로 받은 문서는 제거한다.
- 창 최소 크기 880×620, 작은 화면은 스크롤로 전체 조작에 접근한다. High Sierra 호환 기본 AppKit 컨트롤을 사용한다. 실제 교회 Mac의 표시·HTTPS·키체인·PP6 실행 검증은 별도로 필요하다.

## 로컬 재생목록 비교 도구

기존 프로토타입의 운영 `.pro6pl` 선택, 최신 파일 선택, 재생목록별 체크, 추가·삭제·수정·이동 비교와 선택 적용을 유지했다. `예제로 비교`는 앱에 든 더미를 별도 작업 폴더로 복사하므로 앱 내부 파일이나 운영 파일을 변경하지 않는다.

- 처음 실행할 때 새 설정이 없으면 기존 `~/Library/Application Support/PP6 Playlist Sync/settings.json`의 운영 파일 경로를 읽어 새 앱의 `playlist-settings.json`에 기억한다. 이전 설정은 수정하지 않는다.
- 비교한 뒤 운영 파일이 바뀌었으면 적용을 중단한다. PP6 실행 여부와 현재 파일을 적용 직전 다시 확인한다.
- 선택한 재생목록의 XML만 교체한다. 선택하지 않은 재생목록은 유지한다.
- 적용/복원 전에 `~/Documents/PP6-Playlist-Backups/<고유 번호>/`에 원본을 저장한다. 같은 순간의 여러 백업도 서로 겹치지 않는다.
- 이 로컬 비교 도구는 `.pro6pl` 신규 재생목록 전체 추가/삭제와 서버 업로드를 담당하지 않는다. 서버 등록/수신은 첫 번째 탭을 쓴다. 기존 v0.2처럼 이미 존재하는 재생목록의 선택 적용을 제공한다.

## 문서 탭

새 설정이 없을 때 기본 문서 경로는 `~/Documents/ProPresenter6`이며 기존에 저장한 경로는 유지한다. 폴더를 직접 확인한 뒤 사용한다. 자동 비교는 파일을 송수신하지 않는다. 받기·보내기를 실행하려면 선택과 확인이 필요하다.

입장 정보는 Mac 키체인에 저장하며 웹 브라우저 로그인과 별도 세션이다. **재생목록에서 쓰는 문서만**은 현재 선택한 로컬 `.pro6pl`의 모든 예배 참조를 기준으로 한다. 원본 파일 이름과 경로를 유지한다.

화면 뒤에서 네트워크·파일 작업을 처리하므로 응답을 기다리는 동안 창을 계속 볼 수 있다. 작업 중 다른 변경 작업과 앱의 정상 종료는 막는다. 비정상 종료는 기존 Sync의 기록을 통해 다음 실행에서 복구한다.

동기화 기준·원본 해시·백업 위치·문서별 적용과 충돌 정책은 [송수신 엔진 안내](../mac-sync/README.md)를 따른다. CLI와 통합 앱은 같은 문서 폴더/서버의 상태를 공유하며 동시에 같은 폴더를 변경할 수 없다.

## 미디어 탭

문서 탭에서 선택한 폴더를 Core로 분석한다. 기본 검색 폴더는 `/Users/Shared/Renewed Vision Media`와 `/Users/Shared/ProCG Content`이고, 다른 폴더도 추가할 수 있다.

0.6.4의 `이미지 전송 대상 확인`은 전체 문서에서 참조하는 이미지를 조사한다. 내용이 같은 파일을 한 번 계산하여 고유 이미지 수·중복 절감 용량을 보여주고, 영상은 제외한다. 누락·확인 중 변경·알 수 없는 형식은 확인 필요로 남긴다. 아직 서버에 이미지를 전송하거나 서버 존재 여부를 조회하지 않는다.

`이동한 파일 찾기`는 기존 연결 점검이다. `연결 확인이 필요한 항목만`과 파일명 검색으로 누락 배경을 찾는다. `선택 항목 자세히`에서 원래 경로와 발견한 위치를 보고 Finder에서 열 수 있다. 점검 결과는 로컬 JSON으로 저장할 수 있다.

같은 파일명을 다른 위치에서 발견한 것은 내용까지 같은 파일임을 보장하지 않는다. 현재는 점검 기능을 통합했으며, **미디어 서버 업로드·자동 복사·경로 변경은 다음 단계**다. Playlist·Documents·Media를 한 번에 적용하는 일괄 트랜잭션도 아직 없다.

## 검증 범위

Intel Mac 자동 검사에서 앱 빌드, 기존 더미의 재생목록 비교/선택 적용·원본 백업·후속 수정 보호, Core 문서 비교·미디어 네 가지 판정, 네 화면 생성, 문서 탭이 쓰는 모델의 실제 Worker 왕복을 검사한다. 시험 비밀번호와 합성 파일만 사용한다. PNG 화면과 앱 ZIP은 비공개 저장소의 검사 산출물로 보관한다.

2026-10-01 [기본 브랜치 검사](https://github.com/m1r4d0r/yebaeon/actions/runs/36791133977)에서 빌드 커밋 `1408bdb`의 199개 검사(파일 안전성 100, 엔진/Worker 왕복 18, 앱·Core·화면 66, 앱/Worker 왕복 15)가 통과했다. 이전 0.3.0의 세 탭 화면도 확인했다. 내려받은 0.3.0 앱의 실행 파일은 Intel x86_64, 최소 macOS 10.13이며 외부 실행 도구 없이 시스템 라이브러리만 참조한다.

최신 Mac에서 10.13 대상으로 빌드한 결과는 교회 High Sierra 실기 검증을 대신하지 않는다. 교회에서는 새 앱 실행, 기존 운영 파일 경로 인식, 시험 `.pro6` 한 문서의 운영 서버 송수신과 PP6 열기·저장을 먼저 확인한다. 과거 비교 수치와 썸네일 검사를 반복할 필요는 없다.

## 시작 시 서버 상태 확인

앱을 실행하면 저장된 로그인 상태로 서버에 한 번 연결하고, 설정된 문서 폴더를 읽어 서버 목록과 비교합니다. 입장 정보나 폴더가 없으면 안내만 표시합니다. 비교는 문서를 송수신하지 않으며 중단된 적용은 기존 복구 절차를 따릅니다. 성공한 비교의 시각, 문서 수, 폴더, 자동 실행 여부는 `last-server-comparison.json` 환경설정에 남습니다. 서버는 Sync의 연결과 첫 문서 목록 조회 시각을 기록하며 `/status.html`에서 확인할 수 있습니다. 서버 기록의 비교 시각은 요청 관측 시각이므로 로컬 비교 완료를 보장하지 않습니다.

## 0.4.1 build 6 · 최근 사용순과 병렬 보내기

문서 목록에서 최근 사용순/이름순을 선택합니다. 최근 사용일은 로컬 .pro6의 lastDateUsed를 해석하며, 없거나 잘못된 날짜는 최근 사용순의 마지막에 둡니다. 업로드도 화면의 정렬 순서대로 최대 4개씩 처리합니다. 다운로드와 로컬 기준 기록은 순차 처리합니다. 업로드 중 자동 유휴 잠자기를 방지하며 종료·오류 시 해제합니다. 수동 잠자기와 종료 예약을 무효화하는 기능은 아닙니다.

중단 후 앱에서 서버와 비교 → 보내기 전체 선택 → 선택 문서 보내기를 사용합니다. 성공한 서버 문서는 유지되고 동일 내용은 다시 보내기 대상에서 빠집니다. 4개 묶음에 오류가 생기면 성공한 문서의 기준을 먼저 기록하고 다음 묶음을 시작하지 않습니다. 로컬 기록이 실패해도 서버 저장은 유지되므로 다시 비교해야 합니다. 자동 재시도는 아직 하지 않습니다.
