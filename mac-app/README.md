# 예배온 Sync · 통합 Mac 앱

사용자가 제공한 `PP6-Playlist-Sync-Native-v0.2.zip`의 `main.m`을 기반으로 기존 재생목록 화면에 문서와 미디어 탭을 연결했다. High Sierra 10.13을 대상으로 빌드한다. 기존 앱을 새로 구현한 것이 아니라 재생목록 비교·선택 적용 코드를 옮기고 Core 및 서버 송수신 엔진을 연결한 버전이다. [출처](ORIGIN.md).

## 실행

로컬 개발 묶음의 `app/YebaeOn-Sync-macOS.zip`에는 Mac 자동 검사에서 빌드한 `예배온 Sync.app`이 들어 있다. Mac에서 압축을 풀어 실행한다. **기존 `PP6 Playlist Sync.app`과 백업은 보관**하고 시험 중에는 이전 앱을 종료한다. 새 앱의 이름과 식별자가 달라 기존 앱을 덮어쓰지 않는다. 개발용 서명이므로 다운로드한 앱 실행이 차단되면 Finder에서 앱을 우클릭하고 `열기`를 선택한다.

직접 빌드할 때는 저장소 또는 묶음의 `source/`에서 다음을 실행한다. Finder에서 `mac-app/build.command`를 열어도 된다.

```bash
bash mac-app/build.command
```

결과는 `mac-app/build/예배온 Sync.app`이다. Apple Command Line Tools의 `clang`만 필요하며 교회 실행에 Node.js·Python·Wrangler는 필요 없다. 기존 Core와 개별 송수신 도구는 `mac-sync/`에 유지한다.

## 서버 재생목록 탭 · 0.4.0 기본 흐름

1. **입장 / 이름 변경**으로 로그인하고 문서 폴더와 `.pro6pl` 파일을 고른다. 문서 탭과 같은 세션·문서 폴더·동기화 기준을 사용한다.
2. 처음에는 **원본 · 문서 서버 등록**으로 재생목록 파일 전체와 참조 문서들을 등록한다. 경로가 맞지 않거나 서버와 내용이 다른 문서는 보고하며 자동 덮어쓰지 않는다. 기본 원본 루트는 `~/Documents/ProPresenter6`이다.
3. **서버 목록**에서 플레이리스트 하나를 선택하고 **선택 순서 비교**를 누른다. 가사만 수정됐어도 받기 대상에 표시한다. 공유 문서의 다른 플레이리스트 이름도 표시한다.
4. **이 플레이리스트 받기**는 필요한 문서를 먼저 내려받아 검증하고, 문서별 백업·적용 후 선택한 노드만 반영한다. 다른 플레이리스트와 참조에서 빠진 문서는 유지한다. 선택한 문서 폴더에 맞춰 해당 노드의 `filePath`를 연결한다.
5. **백업 · 중단 복구**는 해당 작업의 문서와 순서를 함께 적용 전으로 되돌린다. 중단 복구 후 다시 비교·받기를 한다. 진행 중인 묶음이 있으면 문서 탭의 독립 송수신도 막는다. 이후 수정한 파일이나 이후 동기화 기준이 있으면 오래된 백업으로 덮어쓰지 않는다.

**시험 폴더 / 시험 파일 만들기**로 운영 파일과 다른 대상에 받을 수 있다. 전체 절차는 [교회 확인 안내](../docs/CHURCH-TEST.md)를 따른다. 새 미디어, 새 플레이리스트 생성/전체 삭제, 이름 변경, 전문 Arrangement 편집은 현재 범위에 없다. 기존 서버 플레이리스트를 빈 시험 파일에 받으면 선택한 노드를 추가한다.

## 로컬 재생목록 비교 탭

기존 프로토타입의 운영 `.pro6pl` 선택, 최신 파일 선택, 재생목록별 체크, 추가·삭제·수정·이동 비교와 선택 적용을 유지했다. `예제로 비교`는 앱에 든 더미를 별도 작업 폴더로 복사하므로 앱 내부 파일이나 운영 파일을 변경하지 않는다.

- 처음 실행할 때 새 설정이 없으면 기존 `~/Library/Application Support/PP6 Playlist Sync/settings.json`의 운영 파일 경로를 읽어 새 앱의 `playlist-settings.json`에 기억한다. 이전 설정은 수정하지 않는다.
- 비교한 뒤 운영 파일이 바뀌었으면 적용을 중단한다. PP6 실행 여부와 현재 파일을 적용 직전 다시 확인한다.
- 선택한 재생목록의 XML만 교체한다. 선택하지 않은 재생목록은 유지한다.
- 적용/복원 전에 `~/Documents/PP6-Playlist-Backups/<고유 번호>/`에 원본을 저장한다. 같은 순간의 여러 백업도 서로 겹치지 않는다.
- 이 로컬 비교 탭은 `.pro6pl` 신규 재생목록 전체 추가/삭제와 서버 업로드를 담당하지 않는다. 서버 등록/수신은 첫 번째 탭을 쓴다. 기존 v0.2처럼 이미 존재하는 재생목록의 선택 적용을 제공한다.

## 문서 탭

`입장 / 이름 변경`에서 이름과 공용 비밀번호를 입력한다. 세션만 Mac 키체인에 저장한다. 기존 브라우저 로그인과 별도 세션이며, 웹과 같은 서버의 문서를 사용한다.

1. 기본은 `~/Documents/YebaeOn-Sync-Test` 시험 폴더다. `문서 폴더 선택`으로 다른 폴더를 명시할 수 있다.
2. `서버와 비교`를 누르면 받기·보내기·일치·충돌로 표시한다. 이름/폴더로 검색할 수 있다.
3. 왼쪽 체크로 문서를 선택하고 `선택 문서 받기` 또는 `선택 문서 보내기`를 누른다. 확인 창에서 경로와 대상 문서를 검토한다. 받기와 보내기는 별도로 선택한다.
4. 문서 행을 클릭하고 `선택 문서 내용 비교`를 누르면 Core의 슬라이드 변화 집계를 확인할 수 있다. 내용 비교는 원본을 변경하지 않는다.
5. `백업 · 중단 복구`에서 적용 전 원본으로 되돌리거나 중단된 작업을 복구한다. 신규로 받은 파일을 되돌릴 때는 제거 대상을 명시한다.

화면 뒤에서 네트워크·파일 작업을 처리하므로 응답을 기다리는 동안 창을 계속 볼 수 있다. 작업 중 다른 변경 작업과 앱의 정상 종료는 막는다. 비정상 종료는 기존 Sync의 기록을 통해 다음 실행에서 복구한다.

동기화 기준·원본 해시·백업 위치·문서별 적용과 충돌 정책은 [송수신 엔진 안내](../mac-sync/README.md)를 따른다. CLI와 통합 앱은 같은 문서 폴더/서버의 상태를 공유하며 동시에 같은 폴더를 변경할 수 없다.

## 미디어 탭

문서 탭에서 선택한 폴더를 Core로 분석한다. 기본 검색 폴더는 `/Users/Shared/Renewed Vision Media`와 `/Users/Shared/ProCG Content`이고, 다른 폴더도 추가할 수 있다.

`미디어 점검 시작`으로 사용된 배경·영상별 문서/슬라이드와 연결 상태를 확인한다. `연결 확인이 필요한 항목만`과 파일명 검색으로 누락 배경을 찾는다. `선택 항목 자세히`에서 문서의 원래 경로와 발견한 위치를 보고, 위치가 하나로 확인되면 Finder에서 열 수 있다. 결과를 로컬 JSON으로 저장할 수 있다.

같은 파일명을 다른 위치에서 발견한 것은 내용까지 같은 파일임을 보장하지 않는다. 현재는 점검 기능을 통합했으며, **미디어 서버 업로드·자동 복사·경로 변경은 다음 단계**다. Playlist·Documents·Media를 한 번에 적용하는 일괄 트랜잭션도 아직 없다.

## 검증 범위

Intel Mac 자동 검사에서 앱 빌드, 기존 더미의 재생목록 비교/선택 적용·원본 백업·후속 수정 보호, Core 문서 비교·미디어 네 가지 판정, 네 화면 생성, 문서 탭이 쓰는 모델의 실제 Worker 왕복을 검사한다. 시험 비밀번호와 합성 파일만 사용한다. PNG 화면과 앱 ZIP은 비공개 저장소의 검사 산출물로 보관한다.

2026-10-01 [기본 브랜치 검사](https://github.com/m1r4d0r/yebaeon/actions/runs/36791133977)에서 빌드 커밋 `1408bdb`의 199개 검사(파일 안전성 100, 엔진/Worker 왕복 18, 앱·Core·화면 66, 앱/Worker 왕복 15)가 통과했다. 이전 0.3.0의 세 탭 화면도 확인했다. 내려받은 0.3.0 앱의 실행 파일은 Intel x86_64, 최소 macOS 10.13이며 외부 실행 도구 없이 시스템 라이브러리만 참조한다.

최신 Mac에서 10.13 대상으로 빌드한 결과는 교회 High Sierra 실기 검증을 대신하지 않는다. 교회에서는 새 앱 실행, 기존 운영 파일 경로 인식, 시험 `.pro6` 한 문서의 운영 서버 송수신과 PP6 열기·저장을 먼저 확인한다. 과거 비교 수치와 썸네일 검사를 반복할 필요는 없다.

## 0.4.0 플레이리스트 검사

빌드 `8faa176`의 [Intel Mac 검사](https://github.com/m1r4d0r/yebaeon/actions/runs/36847704652)에서 256개 검사(100+18+70+15+53)가 통과했다. 새 플레이리스트/Worker 검사는 등록, 가사만 수정, 순서 변경, 공유 문서, NFD 경로, 다른 노드 보존, 강제 중단·재실행 복구, 새 폴더 수신을 포함한다. Windows 웹에서는 같은 플레이리스트의 가사 편집·저장·복귀 및 곡 추가·교체·제거·정렬을 확인했다. 실제 PP6 수용과 화면은 교회에서 검증한다.

## 특수문자 파일명과 전체 선택

콜론(`:`), 따옴표, `&`, `%`가 들어간 문서는 원본 이름과 상대경로를 유지해 송수신한다. 서버 파일은 문서/버전 ID를 사용한 R2 키로 보관하며, 원본 경로는 메타데이터로만 관리한다. URL 전송 시 인코딩하고 재생목록 XML에 넣을 때 이스케이프한다. 운영 파일을 자동으로 이름 변경하지 않는다.

문서 탭의 **보내기 전체 선택** 또는 **받기 전체 선택**은 검색에 가려진 항목까지 해당 방향의 전체 문서를 선택한다. 이전 선택을 교체하며 일치·충돌·업로드 제외 항목은 선택하지 않는다. 선택 후 기존 송수신 버튼으로 개수와 대상 폴더를 확인한다.

경로 길이·구성 제한에 걸린 로컬 문서는 **업로드 제외**로 남기고 나머지 비교를 계속한다. 행을 선택해 **선택 문서 내용 비교**를 누르면 제외 사유를 확인한다. 경로 탈출, 심볼릭 링크, 대소문자/정규화 충돌에 대한 기존 차단은 유지한다. 미디어·성경 파일 전송은 이 변경에 포함되지 않는다.
